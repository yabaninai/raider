# RAI-169 independent acceptance: SDLC-01–04

This acceptance map is for the immutable RAI-169 lane candidate. It exercises the existing stage, approval, launcher, and integration surfaces without changing their expected outcomes. `LocalForgeAcceptanceSpec` supplies a test-only `ForgePort` adapter that translates each integration mutation and read to the real `LocalForgeStand` protocol. It is not the RAI-167 fake port. The testkit protocol suite separately covers actual temporary Git refs through `DisposableGitForgeStand`.

## Explicit boundaries

- ADR-030 D1–D4 are in scope. D5/local release is SDLC-05 and belongs to RAI-170; no release/tag/publish/deploy behavior is verified here.
- The stand is local only. This does not verify a hosted forge or real branch protection.
- The TokenRouter checkout, approved exact command list, source hashes, and target base/head were not supplied. No target-specific commands or source identity are invented; TokenRouter recheck evidence remains pending until that target packet exists.
- The verifier does not alter RAI-167 outcomes or claim that a local stand establishes real-forge behavior.

## Defect found

`IntegrationWorkflow.runMutation` groups `ForgeOutcome.TimedOutUncertain`, `ForgeOutcome.Unknown`, and `ForgeOutcome.ReconcileRequired` into the same `Refusal.UnknownOutcome`. `refused` then serializes all three as `IntegrationOutcome.Unknown`, although the typed evidence taxonomy also defines `IntegrationOutcome.TimedOutUncertain` and ADR-030 §4.2 requires the categories to remain distinguishable. The stand correctly reports `TimedOutUncertain` and the adapter preserves it; integration evidence loses that distinction. SDLC-V-03 retains an assertion for the required distinction and reports the mismatch as a failure. This verifier card does not change the integration implementation.

## Repeat commands

The core, testkit, and runtime acceptance group was run three consecutive times. Because the reproducible SDLC-V-03 assertion fails, sbt stops that invocation before starting the CLI task. The CLI artifact/launcher group was therefore run separately ×3:

```sh
sbt --batch \
  'raiderCore/testOnly raider.core.sdlc.SdlcStagesSpec' \
  'raiderTestkit/testOnly raider.testkit.sdlc.forge.LocalForgeStandSpec' \
  'raiderRuntime/testOnly raider.runtime.sdlc.approval.ApprovalArtifactsSpec raider.runtime.sdlc.integration.IntegrationWorkflowSpec raider.runtime.sdlc.integration.LocalForgeAcceptanceSpec'

sbt --batch \
  'raiderCli/testOnly raider.cli.run.SdlcArtifactSchemaSpec raider.cli.workflow.WorkflowRunSpec'
```

Each command was run ×3. The expected runtime defect exits 1 on each run; all other listed module suites pass on each run. Exact repetition results are reported in the RAI-169 work record and completion message.
