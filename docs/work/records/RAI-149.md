## Resulting behavior

`CodingToolset.toolOf` no longer stamps every tool `RecoveryClass.ReadOnly`. It now takes the recovery class as a parameter (the same per-tool pattern `StateTools.toolOf` already uses) and each of the six coding tools carries its correct frozen `RecoveryClass`, consistent with the canonical `RecoveryTaxonomy` membership (RAI-148, ADR-027 §6.2):

| Tool | Before | After | Canonical membership |
| --- | --- | --- | --- |
| `fs_read` | ReadOnly | ReadOnly (unchanged verdict) | pure read — not in Exec/Write sets |
| `fs_search` | ReadOnly | ReadOnly (unchanged verdict) | pure read |
| `fs_tree` | ReadOnly | ReadOnly (unchanged verdict) | pure read |
| `proc_run` | ReadOnly (**defect**) | **Mutating** | ExecTools (RAI-148 correction) |
| `fs_edit` | ReadOnly (**defect**) | **Mutating** | WriteTools |
| `fs_patch` | ReadOnly (**defect**) | **Mutating** | WriteTools (RAI-148 correction) |

Opt-in state tools (RAI-094, appended when a store is passed) were audited and were ALREADY correct per-tool — untouched: `state_get`/`state_keys` → ReadOnly, `state_put` → Mutating, `state_delete` → Idempotent.

Consequence: the plan-mode read-only enforcement chain — `PlanMode.of` surface narrowing (`PlanMode.scala:212`, filters `recovery == ReadOnly`) and `AgentLoop.enforceReadOnly` (`AgentLoop.scala:576`, denies `recovery != ReadOnly` against the FULL registry lookup) — no longer admits the mislabeled mutating tools into a plan phase. Pre-fix, a plan-phase `fs_patch` REALLY applied a source patch and `proc_run` REALLY executed a command (proven by the pinned reproducer below); post-fix both are refused with the typed policy denial (`RA-TOOLDENY` / `tool_denied`) while the loop stays alive, and genuinely read-only tools still execute. Ordinary (non-plan) runs are unchanged: mutating coding tools still execute (enforcement is plan-phase only).

Consumers verified: NO signature changes needed — `PlanMode.of(full, artifactsDir, maxRepairAttempts)` and `AgentLoop(..., planMode = ...)` are consumed unchanged by the new tests; no runtime source file was touched. No RecoveryClass enum change, no wire change, no config-driven taxonomy, no ADR-028 semantic change (non-goals respected).
