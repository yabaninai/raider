   `WorkflowRun.body` runs the typed output-dir probe

## Limitations / blockers

1. The first red UO-01 attempt found a real fixture pitfall, recorded here for
   the next author: a bare `try/finally` around the constructed test ZIO
   restores the directory permissions BEFORE the effect runs (zio.test
   suspends the assertion body — the Scala try block completes during effect
   CONSTRUCTION). The chmod and the run both live inside the effect now;
   restoration uses `.ensuring`.
2. The UO-01 test relies on POSIX permissions actually applying to the test
   process owner (as any permission-based test must). Under a root-owned test
   runtime it would fail honestly (mkdir succeeds → wrong exit code), never
   falsely pass. No root-skip guard was added — a skip is not a pass.
3. The named test runs in-process (`WorkflowRun.run`), not through the CLI
   subprocess; the subprocess leg (exit 27 + `raider RA-JOURNAL: ...` stderr
   line) follows from the same typed `Outcome` mapping (`command` →
   `HeadlessRunner.exitCodeFor`), which is shared code already covered by the
   launch-matrix subprocess tests on the writable path. The raw-defect
   subprocess crash (exit 1) observed in RAI-155.d is structurally impossible
   now: the only `.orDie` surface (writer open) runs strictly after the typed
   probe succeeded.
4. Lane evidence applies to this branch's snapshot (the manifests' `source`
   fingerprint section); per policy it does not replace checking the
   integrated candidate.
