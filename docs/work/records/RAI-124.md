## Resulting behavior

`:type <expression>` in the product REPL loop (`raider.repl.Main`, no-flag
legacy mode) prints the exact type of an expression through the REAL
interpreter compiler WITHOUT executing it:

- `Commands.handle(":type …")` forwards the string verbatim (trimmed) to
  `engine.eval` — dotty ReplDriver 3.9.0 parses its OWN native `:type` command
  (`ParseResult.TypeOf` → `ReplCompiler.typeOf`): the expression is compiled
  against live session state and is not run. There are no effects, model calls,
  or binding mutations; resN numbering does not advance (pinned by a test).
  The Scala 3 interpreter's existing typeOf mechanism is used; there is no
  custom parser/formatter.
- A type error is an honest compiler diagnostic (E006 `Not found: …`, E007
  `Found:/Required:`); the REPL stays alive and the next request works. Empty
  input gets the driver's own usage text, `:type <expression>`.
- Multiline: `:type` lines use the same pending-buffer path as Scala input; on
  submission, the buffer is flattened to one-line source
  (`Commands.typeQuerySource`: `\n`→space + trim — the driver's
  CommandExtract regex full-matches one line). The known residue is documented:
  block statements require explicit `;` after flattening (otherwise there is an
  honest syntax error).
- Registration: `Commands.helpText` gained the command line `:type <expression>`;
  the stale “Not in this slice” line was updated (`:type` is now included;
  completion/live providers are already in the product); `ReplChatCommands.catalog`
  has a `:type` entry in helpText order. Freshness equality
  (ReplChatPaletteSpec, precedent RAI-111) is green. TAB completion/palette
  mechanics were untouched (they are generated from the registry).
- The chat module (JLine) is untouched; the compiler layer `modules/repl-engine`
  is only consumed (frozen `ReplEngine.eval`).

## Limitations / blockers

- No paid calls: PTY/unit fixtures use scripted/mock backend, no network;
  provider keys were not read.
- Single-line grammar residue: a multiline block without `;` after flattening
  results in an honest compiler syntax error (native dotty `:type` does not
  accept a multiline argument at all; this path supports strictly more).
- `:TYPE`/` :typ` honestly fail (driver is case-sensitive; our dispatch uses
  exact name; driver prefix matching remains for forwarded requests).
- `:type f` for an unapplied def is an honest compiler E178 (dotty semantics,
  not wrapped).
- TYPE-03 timing window: the job oracle is the echoed `JobHandle` binding +
  `j.await()` result; streaming in mock mode completes quickly, so the request
  is sent immediately after start (content-based oracles, not timing-based).
- Lane evidence applies to snapshot `42d4086`; the integrated candidate needs
  its own checks after merge (board/records do not rebind the manifest).
