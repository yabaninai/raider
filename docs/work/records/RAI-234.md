### Analysis deliverable: the arming gap is source-plausible; the window is pinned

Analysis of ZIO 2.1.26 (build.sbt:10) run-loop sources (snapshots with sha256 in `evidence/rai-234/zio-src/`, fetched from `raw.githubusercontent.com/zio/zio` tag `v2.1.26`):

- `AgentLoop.scala:259-265` emits `phaseStarted` via `ev(...)` (line 107; synchronous UIO: `ConcurrentLinkedDeque.addLast`), then evaluates `planAttempt(...).onExit(_ => ev(_.phaseFinished(...)))`.
- ZIO `FiberRuntime.runLoop` polls the fiber inbox **before every effect step** (`FiberRuntime.scala:1105-1110`, `drainQueueWhileRunning`). An `InterruptSignal` found at a poll replaces the pending effect with `Exit.Failure(cause)` (`FiberRuntime.scala:327-334`).
- `onExit` compiles to `ZIO.uninterruptibleMask { restore => restore(self).foldCauseZIO(...cleanup...) }` (`ZIO.scala:1125-1137`). The cleanup "arming" = evaluation of that mask/fold frame, which happens **after** the emission step has completed and the continuation AST has been constructed.
- The vulnerable window is therefore the stretch between the emission effect's completion (`tags` becomes observable) and the evaluation of `onExit`'s first node: an interrupt signal enqueued in that stretch is processed at the next poll and kills the fiber with the fold frame not yet pushed — cleanup never runs, `phase_finished` is never recorded. Signature: `tags = Vector("phase_started:plan:ReadOnly")` — exactly the RAI-225 one-off red (RAI-225 record, loaded gate run at commit `69a9a4b`; both files verified byte-identical `69a9a4b..HEAD` via `git diff`).
- Once the fold frame is pushed, the region is genuinely safe: the failure unwind hits the `FoldZIO` frame while flags are uninterruptible (restore wrapped only the inner effect), so `shouldInterrupt()` (FiberRuntime.scala:1459: `isInterruptible() && isInterrupted()`) is false and the cleanup runs; the interrupt-strips-through path (`FiberRuntime.scala:1319-1323`) does not fire. This is why the test passes in the overwhelmingly common case and why an interrupt landing inside `planAttempt` (e.g. at the `gate.await` async boundary) cannot wedge the waiter.
- Load-sensitivity: the window is normally a few microseconds (continuation-AST construction + one poll boundary). Under CPU saturation the child worker thread can be preempted inside that stretch, widening it to milliseconds while the test fiber's busy-spin wait (`waitFor`, spec:236-240 — `repeatUntil`, no sleep) observes `tags.nonEmpty` within microseconds and fires `fiber.interrupt` immediately. That combination matches a once-per-many-thousands flake (RAI-225: one occurrence; RAI-227: zero in 35; this campaign: zero in 32).
- Candidate fix shape if a future card proves the red: span one uninterruptible mask from the emission through arming — `ZIO.uninterruptibleMask(restore => ev(_.phaseStarted(...)) *> restore(planAttempt(...)).onExit(...))` — so a signal arriving in the window is recorded-but-not-processed until after the fold frame is armed, at which point the existing cleanup path records `phase_finished` (pairing invariant `started ⇒ finished` preserved). This is NOT landed here: the card forbids product changes on the no-repro branch.
