## Resulting behavior

`ReleaseStage.Request` now optionally accepts distribution files as source paths
and release-relative paths. It stages them with changelog/provenance in the
existing temporary release directory, includes every staged distribution path
in `SHA256SUMS`, substitutes `VERSION` and `REPLACE_WITH_RELEASE_SHA256` in
text files containing those markers (the SHA is the staged fat-JAR SHA when a
`raider-cli.jar` is included), and copies other inputs byte-for-byte. The
existing single atomic directory move promotes the complete set. Interrupted
staging reconciles the names in both temporary and installed trees; the release
directory is absent when interruption occurs before promotion. No push,
publication, or deployment is performed.

The release contract and staging behavior are exercised by `ReleaseStageSpec`;
existing `LocalReleaseHandler` and `LocalReleaseAcceptanceSpec` continue to
exercise the SDLC local-release route. The documentation shows how its
configured `ReleaseStage.Request` includes the JAR, launcher, and formulae.
