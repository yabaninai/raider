## Resulting behavior

Confirmed and rebuilt the existing sbt-assembly distribution. It creates
`modules/cli/target/scala-3.9.0/raider-cli.jar`, with `raider.cli.Main` as the
assembly entrypoint and the current `raiderCli` dependency graph. Added a
Coursier-compatible installed launcher layout, Homebrew formula template, Scoop
manifest, and fresh-prefix install/checksum smoke script. The launcher uses
Coursier `cs launch --jar` when installed, falls back to `java -jar`, and
provides wrapper-level `--version` from adjacent metadata. The CLI jar itself
does not implement `--version`.

The SDLC dogfood/integration deliverable is incomplete. Existing
`LocalReleaseHandler`/`ReleaseStage` acceptance passes, but `ReleaseStage`
currently fixes release contents and checksums to `CHANGELOG.md` and
`release.json`; it has no distribution-artifact staging hook. Calling it and
copying the JAR afterward would leave the service's checksum/provenance and
atomic-install contract false. This lane did not add a second release writer or
modify out-of-scope SDLC/CLI source. No distribution-inclusive
`artifacts/release/<version>/` output or LocalRelease run is claimed.
