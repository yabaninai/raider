## Resulting behavior

New named test suite
`modules/runtime/src/test/scala/raider/runtime/fairness/CrossRootFairnessSpec.scala`
(package `raider.runtime.fairness`) covering cross-root fairness of the shared
Model-slot pool (runtime-contracts §6, `Admission.scala` fair FIFO). Product
code is untouched; admission semantics are unchanged. The audit found NO
defect in `Admission` — no typed reproducer / contract-change request is
needed.

- FAIR-01 (`CrossRootFairnessSpec`): deterministic contention scenario, 2
  roots × 6 requests over 1 Model slot. Requests are forked so that every
  release moment has two waiters in an established park order (surviving
  cross-root request first, freshly forked second); a pure checker asserts the
  exact bounded-FIFO grant order `A1,B1,A2,B2,...,A6,B6` (each request granted
  within ≤ 2 queue positions — no starvation), peak concurrent slot holders
  == 1, per-root attempts == 6 (both roots complete everything), and exact
  ledger settlement (`observedTotal` == planned sum, `reservedActive` == 0,
  `uncertainTotal` == 0, `unpricedAttempts` == 0). Ordering links are
  established by polled observables (`Admission.queued`, grant log) plus 5 ms
  settle sleeps; wall-clock is never trusted for ordering.
- FAIR-02a (negative control): the SAME scenario + the SAME pure checker run
  against a test-local `UnfairPool` (single-slot pool with root-priority
  dispatch). The checker reports the grant-order violation and the observed
  overtake (`A2` granted before the earlier-queued `B1`) — proof the
  acceptance is not a tautology.
- FAIR-02b (per-root budget independence): with `maxAttempts = 2`, root A's
  third attempt fails typed (`RA-LBUDGET`, dispatch never runs, no money
  moved, no slot leak) while root B is admitted on the same exhausted pool
  (`attemptsA == 2`, `attemptsB == 2`, exact sums). Note: `maxAttempts` is a
  per-root counter shared as a ceiling by all roots of one `Admission`; the
  hard USD cap is pool-global by contract — per-root budget dimension used is
  `maxAttempts`.
- FAIR-03 (parallel admissions, no loss/duplication): `ZIO.foreachPar` over a
  fixed interleaved plan of 12 requests from both roots — every token
  `(rootId, tag)` admitted exactly once, peak concurrency == 1 under full
  contention, exact ledger sums, `availableSlots(Model) == 1` after (no leak).
  The pre-existing `BudgetAdmissionSpec` stays green ×3 (run together with the
  new suite, 18 tests passed per run).

Development note (honest trail): the first FAIR-01 red was a fixture
assumption bug, not an SUT defect — three initial requests raced for the FREE
slot, which no fair FIFO can order deterministically; the fixture was fixed to
serialize the initial acquisition (request 1 alone takes the free slot, then
waiters are parked in established order). Under contention the SUT behaved as
bounded fair FIFO in every observed run.

  "per-root budget independence" is asserted against the per-root ceiling —
  consistent with the current product semantics.
