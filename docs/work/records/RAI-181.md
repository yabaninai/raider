## Resulting behavior

Added the end-to-end LocalRelease adapter-to-service fixture to the existing disposable-Git release suite. The fixture supplies parsed accepted check, review, and integration records bound to one candidate digest, invokes `LocalReleaseHandler` and the real `ReleaseStage`, then verifies `CHANGELOG.md`, `release.json`, and `SHA256SUMS` under `artifacts/release/1.2.3/`, the local `v1.2.3` tag, and the typed `local-release-result` roundtrip through run.json and events.jsonl. Capability and checkpoint negative variants return stage refusals without release artifacts or tags. All Git operations are confined to the disposable repository; no remote operation is invoked.

Review fix round closes all three findings. Integration evidence is refused when its policy digest differs from the candidate policy digest. The LocalRelease stage no longer trusts caller-supplied capability/checkpoint strings: it requires an RAI-179 `CheckpointDispatch`, re-evaluates it at the stage boundary against current state, and checks the runtime-issued authorization's candidate digest, configured `local-release` checkpoint, and expiry. The authorization carries the checked expiry. Materialization is interruptible; on interruption the release service performs read-only reconciliation of staged/installed artifact names and tag presence, returns a typed interrupted error, and the stage adapter records an unsuccessful interrupted `StageResult` with the reconciliation detail. A local tag is created only after the complete artifact directory is installed. Interruption during staged-artifact creation is covered; its fixture asserts all three staged artifact names, no installed release directory, no tag, and a typed interrupted outcome.
