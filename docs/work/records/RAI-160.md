## Resulting behavior

The owner-flagged RAI-155 chain gap is closed: the chat can now produce the
editable workflow artifact.

- **Adapter** (`TaskWorkflowAdapter`): pure 1:1 mapping of the RAI-155.b
  `TaskSelection` snapshot onto the RAI-155.c `raider.dsl.workflow.StsSelection`
  renderer input (ADR-033 §4): turn kind/status strings map onto the dsl enums
  1:1 (unknown strings are typed refusals, never coerced); turn text is the
  bounded payload-free captured request (`TurnLedger.boundedRequest`,
  re-applied at the boundary); named checks map argv-identically; the agent
  stage bound flows 1:1 from `maxRoundsBound`; the origin is built ONLY from
  non-secret config references (chat transport -> provider kind:
  `openai` -> `openai-compatible`, `anthropic` -> `anthropic-compatible`; the
  mock/fallback transport is a typed refusal — no mislabeled origin). The R4
  secret scan runs AGAIN at the adapter boundary (defense in depth, independent
  of select-time validation; the matched value is never echoed). The
  externalized task params (`targetPath`, `summary`) are NOT invented from
  captured text — they are explicit inputs of the export command.
- **Command** `:export-workflow [--out <dir>] [--name <name>] [--target-path
  <path>] [--summary <text>]` (proposal now implemented): dispatches the stored
  selection snapshot through the adapter into
  `raider.dsl.workflow.ChatWorkflowExport.exportTo` unchanged (staging+rename,
  never-overwrite, R5 path rules inherited). Typed refusals surface as
  `export refused [RA-INP]: CWF-R…` lines: R2 (legacy/no-ledger session — the
  canonical `TurnLedger` text), R1 (ledger captured but no snapshot; missing
  externalized params naming the flags), R4 (secret-bearing snapshot at the
  adapter boundary), R5 (existing target / staging remnant). The success
  message names the artifact, manifest and input-example paths (the §6.2
  layout) plus the identity digests. The REPL handler is a thin blocking
  printer over `ExportWorkflowCommand.execute` (the console-adapter discipline;
  the same function the fixtures drive). `ChatLoop.RunCtx` gained a non-secret
  `baseUrl` field (defaulted `""` so existing constructions compile unchanged);
  it is an ADR-033 §5.1 configRefs reference, never a credential. `:help` and
  the command list name `:export-workflow`.
- **Chain gate** (EW-01, acceptance core): REAL chat capture (turns through
  `ChatLoop.processMessage` over a scripted backend with live
  JobManager/EventHub/Admission — the TaskCaptureSpec pattern) -> `:task`
  mark/select through the real `TaskCommands` -> `:export-workflow` through the
  real `ChatLoop.exportWorkflow` -> pinned-dotc compile via the existing
  `raider compile` surface (`WorkflowCompile.command`) -> smoke `raider
  workflow run` (`WorkflowRun.run`) against a scripted local OpenAI-compatible
  stand: the generated source is DERIVED (contains the captured intent token
  and refinement text, which appear nowhere on disk before the export — no
  pre-baked example) and the run produces a real tool effect (marker file on
  the fresh workspace) with an independent check verdict
  (`trusted-checks-passed` in run.json).
- **Determinism**: same snapshot re-exported ×2 to distinct targets is
  byte-identical (all three §6.2 files); escape/refusal disciplines are
  inherited from the renderer unchanged.

Exact user command sequence that works (validated end-to-end by
`ChatExportChainGateSpec` EW-01): chat turns arrive -> `:task mark 1 intent`,
`:task mark 2 refinement`, `:task check marker /bin/test -f marker.txt`,
`:task select 2`, then
`:export-workflow --out <dir> --name ew01_chain --target-path marker.txt --summary <text>`;
then `raider compile <dir>/ew01_chain.scala --out <build>` and
`raider workflow run --classes <build> --input <input.json> --out <out>` (input
JSON supplies the fresh workspace + per-run task; `RAIDER_API_KEY` supplies the
credential reference).

  `modules/repl` — an area this card neither touches nor depends on; the test
  passes deterministically in isolation, and the full-suite re-run is green.

  it warrants a flake-budget calibration card (the pattern of the recent
  `gate-budget` commits), not an assertion change.
- The chain gate compiles and runs the generated artifact inside the sbt-test
  gate using the product `WorkflowCompile`/`WorkflowRun` surfaces; it does not
  exercise the packaged CLI assembly (`raider` launcher binary) — that is the
  RAI-155.d/.e surface and its own acceptance.
- The exported origin's `baseUrl` is the session's non-secret transport
  reference; the default export name is derived from the intent turn id
  (`task_<turnId>`) — provenance, not a user-facing naming policy. Both are
  editable artifacts, per ADR-033 §6.5.
- Scope note: `make quality-changed` auto-classified profiles
  [contracts, static, unit]; the `ci` profile was added per the card packet's
