## Resulting behavior

`--format portable` on `:export-workflow` exports a selection to the frozen
portable v1 document format while the default Scala export stays unchanged:

- `PortableChatExport` (dsl): renders an `StsSelection` into a portable
  workflow document (profile/toolset trusted references are NAMED, never
  inlined), self-validates the rendered document through the frozen v1
  gate, emits a closed-schema manifest (document/input-example sha256
  digests, exporting launcher, pinned registry snapshot) plus an input
  example, stages into a `.raider-portable-export-staging` sibling and
  publishes atomically. Refusals: CWF-R3 when the selection carries named
  trusted checks (portable v1 has no user-named check construct; the
  message names the retained Scala export), CWF-R1 for unsafe artifact
  names, >256-char provenance, and R5 never-overwrite / staging-remnant
  discipline at publication.
- `ExportWorkflowCommand --format portable`: parses the flag (unknown
  format → usage refusal), dispatches through the same adapter seam with
  THIS launcher's pinned registry (`coder` profile, `workspace` toolset,
  `workspace-marker-present` check, pinned snapshot), renders success
  lines naming the three artifacts, digests and validate/run next steps.
  By construction the chat command refuses CWF-R3 for every supported
  selection (ADR-033 §4.1 requires ≥1 named check); the portable happy
  path is exercised at the dsl layer (check-free selections from other
  launchers) and through the shipped recipes.
- Recipe pair under `docs/examples/portable-workflows/`:
  `checked-repair` (draft/op/check: budget exhaustion, typed uncertain,
  interruption latch, stale-snapshot refusal) and

## Limitations / blockers

- Through the chat command, `--format portable` refuses CWF-R3 for every
  supported selection, because the frozen selection shape (ADR-033 §4.1,
  `TurnLedger.validateSelection` — outside this card's allowed paths)
  mandates ≥1 named trusted check while portable v1 carries only
  launcher-pinned trusted references. This is the card's required
  "unsupported export explains the step and retains the existing Scala
  option" behavior, documented in the command Scaladoc. A follow-up card
  could map named checks that exactly match launcher-pinned trusted
  checks onto `trustedCheck` steps; that is a contract-adjacent decision
  and was deliberately not made here.
- The two execution quality failures in the first gate run were
  environmental, not code: missing worktree toolchain cache (fixed by
  bootstrap) and scalafmt on the new files (fixed by `sbt scalafmtAll`;
  all gates rerun to green after the format pass).
- CLI portable tests cover the command seam and refusal paths; the
  R5/atomic-publication and digest-binding cases run against the dsl
  exporter directly (the command delegates to it unchanged).
