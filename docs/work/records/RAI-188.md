Status: accepted after integrated gates and independent review approval. Date: 2026-10-23. Lane baseline: `1e9fe75`; integrated merge: `6f4e560`.

## Resulting behavior

`--chat` now runs inside `TabShellHost`'s existing JLine input loop. Ordinary input, including colon-prefixed text that is not a frozen shell command, starts a chat turn; the existing `CommandRouter` continues to own its frozen commands. `:cancel`, `:chat`, and chat scroll controls are intercepted as chat-mode commands. `:aux`, `:tabs`, `:help`, `:quit`, and the other frozen shell commands remain on their existing route. The prior synchronous custom chat loop was removed; `TERM=dumb` retains its ordinary line-REPL fallback.

The loop and renderer use a one-writer bridge. Interpreter-world `ChatLayoutSink` sends complete ANSI frame payloads to a JDK `Consumer` obtained from shared JVM properties. The console-owned bridge enqueues those frames; a scoped host pump calls `ShellTerminal.printAbove`. The sink does not write to `System.out`. Terminal dimensions are refreshed from the JLine terminal and used for subsequent chat reflows.

`ReplCommands.startChat` starts one session-owned steerable job through the existing facade/job manager, then forks an asynchronous managed-job waiter for completion. The mutable `ReplEngine` remains serialized on the TabShell input thread; background model deltas reach the host only through the render bridge. `:cancel` requests cancellation through the job manager. Already-rendered assistant text remains in chat history, later deltas are ignored after cancellation, and the view reports whether cancellation was requested or the job had already completed. The scripted chat fixture paces mock deltas by 180 ms for deterministic PTY overlap; live model calls are not made by these tests.

No new dependency or ADR-024 event contract was added. `MainTabsPtySpec` exercises the legacy `--tabs` entry unchanged.

## Limitations / blockers

The REPL render bridge uses a bounded in-process queue; terminal rendering follows JLine's `printAbove` serialization. The scripted fixture's delta pacing validates the input/render race deterministically but does not claim provider-specific cancellation latency. Integrated acceptance is based on the root gates above and the merge's independent review approval. TAB-02 (RAI-172) remains an exception/watch and was not observed red.
