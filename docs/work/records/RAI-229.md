## Resulting behavior

`stop_stands` in `contracts/acceptance/cross-ecosystem/scenarios/lib.sh` is now honest:

- Durable registration: `start_stand` writes `$OUT/stand-<name>.pid` immediately after spawning. This is required because drivers call `PORT_A=$(start_stand A ...)` inside a command substitution, so the in-memory `STAND_PIDS` mutation never reaches the driver shell (discovered during this card: the first fixed run logged `stop_stands: no stand pids registered` and the base code's `wait 2>/dev/null || true` was a no-op for the same reason — the orphan shape is the default shape of these drivers, which is why wave-D leaked silently).
- Per-pid stop: SIGTERM → bounded wait (`XE_STOP_TERM_TIMEOUT`, default 10 s) → bounded SIGKILL escalation (`XE_STOP_KILL_TIMEOUT`, default 5 s) → each exit verified by polling process liveness (`kill -0` plus `ps -o stat=` so zombies do not count as alive); exited children are reaped.
- Failure is never masked: a stand that survives SIGKILL, an invalid/malformed pid registration or pidfile, or a pid whose process is not a `Stand` (recycled pid / foreign process) produces a diagnostic and a nonzero `stop_stands` exit. The identity guard refuses to signal a foreign process; a failed stop retains the pidfile for post-mortem.
- `run-all.sh` propagates a stop failure (explicit check, nonzero exit, no checker run); `run-budget.sh` captures the stop result, still produces and verifies the budget evidence, then exits nonzero. `start_stand` FATAL paths (stand died / no PORT) now run a best-effort `stop_stands` before exiting 2 so an already-started sibling stand is not leaked.

No stand, checker, consumer, corpus scenario expectation, or gate-policy change.

## Limitations / blockers

- Crash-path leak window (pre-existing, disclosed): if a consumer run fails, `set -e` aborts the driver before `stop_stands`, so stands leak with their pidfiles retained on disk. Observed once during the first concurrent drill (consumer `observe-dedup` failed `observations-nonempty` at load ~313; both worktree stands 60884/60903 were reaped manually — they die on plain SIGTERM; pidfiles had been retained as designed). An EXIT-trap cleanup in the drivers is the follow-up candidate; this card's scope was stop honesty + propagation only, so no trap was added. The rerun of the same drill was green on both sides (observe-dedup PASS in both checkouts).
- The survive-SIGKILL branch (nonzero exit for a stand alive past `XE_STOP_KILL_TIMEOUT`) is verified by inspection and shares the refusal path's plumbing (exercised by ADV-2); a genuinely SIGKILL-immune process cannot be safely planted in user space on this host.
- Two concurrent drivers in the SAME checkout share `$OUT` pidfiles and remain unsupported (unchanged pre-existing property; the isolation contract is per-checkout).
- First `run-all.sh` execution (rc=0) ran on the intermediate fingerprint before the pidfile fix was added; it exposed the subshell registration defect and leaked my two stands (44286/44309), which I reaped manually. Corpus evidence binds to the final code (run 2, budget run, concurrent drill).
- Target shell is bash 3.2.57 (macOS system bash); all new syntax verified on it.
- `stand pid already exited` may be logged twice for one pid when both the pidfile and the in-memory array contain it (idempotent double visit; cosmetic).
