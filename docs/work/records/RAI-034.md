## Resulting behavior

Implemented the pi RPC external backend per the PIRPC-01/02/03 specs:

1. **`modules/backend-pi`** (`raider.backend.pi`), Scala 3 + ZIO only, no new
   dependencies (uses the pinned zio/zio-json/zio-streams closure already in
   `scripts/build/compile.sh`):
   - `PiRpcConfig` — validated spawn config (`make`: command/versionCommand/
     expectedVersion/envExtra/maxFrameBytes/dispatchTimeoutMs/settleWaitMs/
     gracefulStopMs/forceStopMs; `Either[RaiderError.Configuration, _]`,
     fail-closed typed `RA-CFG` on bad values, version gate before spawn),
     `PiVersionInfo` (line + `matchesExpectation`), `PiCancelOutcome`
     (`Acknowledged(settledAborted, detail)` / `Uncertain(detail,
     childDestroyed)`).
   - `PiRpcCapabilities` — honest capability report with canonical rendering
     (sorted keys, 2-space indent, no trailing newline). Values: backend
     `pi-rpc`, protocol pins upstream commit
     `55a5c6914570e2ae31ca36297654483bbbf46883`, streaming `supported`,
     tools `supported-externally-owned` with explicit disclaimer that Raider
     tool policy is NOT enforced inside pi, nestedAccounting `unknown`,
     cancellationAck `supported`, sessionSupport/structuredOutput/steering
     `unsupported`, priceModel records `priceKnown=false` (pi reports cost;
     Raider does not price pi usage), schemaVersion `1`.
   - `PiRpcBackend` — one inference attempt per `run` call: spawn the pi
     child (`RA-UNAVAIL` typed on spawn failure), write the prompt frame
     (`{"id":"c-1","type":"prompt",...}`), stream normalized
     `raider.core.ModelEvent`s until exactly one terminal event. Strict
     framing: byte-level LF splitting (U+2028/U+2029 are data, never
     terminators), blank/garbage/truncated/oversized frames and `response`
     frames with ids Raider never issued are `RA-STREAM` violations; stream
     end without `agent_settled` is a truthful uncertain failure
     (`RA-UNAVAIL`/`RA-CANCEL`, "uncertain" language). Completion is only
     `agent_settled(aborted)`; `agent_end`/`turn_end` are metadata, never
     terminal. Delta normalization: text deltas; reasoning deltas as
     `pi.reasoning` metadata; tool argument fragments accumulate into
     `ToolCallReady` with exact arguments JSON; usage maps to
     `UsageObserved(priceKnown=false)` with pi cost recorded as
     `pi.usage.cost.usd` metadata (never priced). Cancel: id-matched `abort`
     request, bounded settle wait (`settleWaitMs`) → `Acknowledged` when
     `agent_settled(aborted=true)` arrives; on deadline the child is
     stopped/destroyed and the outcome is `Uncertain` with the terminal
     `Failed(RA-CANCEL)` observable as the last stream event. Scope
     finalizer performs orderly release (stdin close → graceful destroy
     window → destroy/destroyForcibly), dispatch watchdog bounds
     request/response gaps (`dispatchTimeoutMs`).
2. **`contracts/backends/pi`** — `pi-rpc-capabilities.schema.json` (exact
   key set, enum domains, honest-unknown requirements, `backend` const
   `pi-rpc`, additionalProperties false), byte-exact golden
   `golden/pi-rpc-capabilities.json` (SHA-256
   `d2b061864f2cfc9e98ff51ff8578955e66915cb7ebe902821e02b6f7bc93a79b`, no
   trailing LF), and README describing framing rules, upstream pin, trust
   boundaries, and the process model.
3. **Acceptance specs** (`raider.backend.pi` test scope) — plain-main specs
   (compat pattern; exit code carries the verdict) proving the contract
   against a REAL subprocess stand (`PiRpcStand` + `StandHandle` spawn the
   test JVM as a child process; no in-process mock): PIRPC-01 end-to-end
   prompt+tool run; PIRPC-02 robustness (accepted-not-final latency,
   stdout noise, corrupt JSON, abrupt crash exit 7 → uncertain RA-UNAVAIL,
   rogue response id, version probe/mismatch fail-closed); PIRPC-03
   (U+2028/U+2029 byte-exact through LF framing, retry-then-settle as
   `pi.retry.*` metadata, cancel matrix: ack→Failed(Cancelled),
   ignore-abort→Uncertain+destroyed, unsettled abort→Uncertain).

## Limitations / blockers

- **Registration (coordinator follow-up)**: `modules/backend-pi` is not
  registered in `build.sbt` (coordinator-owned file, outside this card's
  allowed paths). Proposed registration for the coordinator:
  `lazy val raiderBackendPi = (project in file("modules/backend-pi")).settings(commonSettings, testSettings, name := "raider-backend-pi").settings(libraryDependencies += "dev.zio" %% "zio-streams" % zioVersion).dependsOn(raiderCore)`.
  Until registered, `sbt-compile`/`scalafmt-check`/`sbt-test` are vacuous
  for this module (they still passed for the rest of the tree). Real
  compile/spec coverage is the pinned-dotc compile + standalone java spec
  runs above. The specs are plain-main because no zio-test jars exist in
  the pinned closure; after registration they should be re-hosted as
  zio-test suites or kept as `runMain` acceptance mains.
- **Speaker notes**: the stand emits all diagnostics on stderr; only JSONL
  protocol frames are on stdout, and it keeps running after
  `agent_settled` until stdin closes (orderly-shutdown contract), so
  harnesses must close stdin to reap the child.
- Evidence logs live in the gitignored temp tree
  (`/var/folders/.../opencode/rai034-*`) and are not reproducible from a
  fresh clone; the in-tree immutable evidence is the golden fixture
  (hash above), the schema, the specs themselves, and the runner manifests
  under gitignored `artifacts/quality/` on this lane's disk.
- Runtime scope: this backend executes the pi child with the process's own
  permissions; Raider tool policy is not enforced inside pi (stated in the
  capability disclosure). No network/paid calls were made; the version
  probe and every spec used the local test stand.
- Python usage: none in shipped code (probe utilities only in the gitignored
  temp tree).
