# RAI-121: work record — :scrollback precedence, alignment with frozen :switch

Status: done (lane `lane/rai-121`, not integrated; push/merge prohibited — coordinator handles integration). Date: 2026-10-12T19:38:38Z. Baseline commit: `8d07036` (worktree `wt/rai-121`; verified at start: `git log --oneline -1` == `8d07036`, branch `lane/rai-121`).

## Decision and rationale

Chosen **option (a)**: `ScrollbackCommands.resolve` resolution order aligned with frozen `CommandRouter.resolveTab` (`:switch`) — an all-digit token is resolved FIRST and EXCLUSIVELY as a 1-based index from the `:tabs` listing: if in range, it resolves; if out of range, typed `RegistryError.UnknownTab`; falling through from a digit token to id/label/prefix is excluded. Non-digit tokens retain the registry read-model steps (exact tab-id → exact label → unique prefix) — this is an extension not present in `:switch`, because its token form is `<n|label>`, without tab-id.

Rationale for choosing (a) over (b):

1. The user model is consistent: a user who has learned `:switch` gets **the same** result from a numeric token in `:scrollback` (the original RAI-113 concern, minor). Option (b) would preserve the discrepancy and require users to remember how each command interprets numbers.
2. Both corner cases from the card under option (a) become **matches with frozen behavior** (not “our local choice”): a tab with label `"2"` is unreachable with token `"2"` (as in `:switch`); a lone tab `2024-report` does not “resurrect” out-of-range `"2"` through prefix matching.
3. Unification through a shared helper remains a contract-change request (frozen `modules/ui/**` was untouched — non-goal respected); aligning order reduces any future unification diff to a pure extract-method.

The noted asymmetry is intentionally retained: the digit step in `:switch` fails with typed `BadTabIndex`, while in `:scrollback` it fails with typed `RegistryError.UnknownTab` (P2SR-02, changing the error type is outside allowed semantics; the error carries the raw token). This is a difference in LAYERS (error types), not RESOLUTION ORDER — the docstring states that “mirrors” refers only to precedence and honestly names the read-model steps that `:switch` lacks.

## Resulting behavior

`:scrollback [tabId]` resolves a token in this order: (1) empty → typed `UnknownTab("")`; (2) all-digit → 1-based `:tabs` index, exclusively (in-range → tab id; otherwise typed `UnknownTab(raw)`), with no fallthrough — byte-for-byte precedence of frozen `:switch`; (3) non-digit → exact tab-id → exact label → unique prefix → typed `UnknownTab(raw)`. All failures are typed, with no phantom tabs; one-writer/printAbove dispatch discipline is untouched (diff only in the pure `resolve` function + docstrings).
