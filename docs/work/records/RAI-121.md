## Решение и обоснование

Выбран **вариант (a)**: порядок резолюции `ScrollbackCommands.resolve`
выровнен с frozen `CommandRouter.resolveTab` (`:switch`) — all-digit токен
резолвится как 1-based индекс `:tabs`-листинга **ПЕРВЫМ и ИСКЛЮЧИТЕЛЬНО**:
в диапазоне — резолвится, вне диапазона — typed
`RegistryError.UnknownTab`, fallthrough digit-токена на id/label/prefix
исключён. Non-digit токены сохраняют read-model шаги registry (exact tab-id
→ exact label → unique prefix) — это расширение, которого у `:switch` нет по
причине формы его токенов (`<n|label>`, без tab-id).

Обоснование выбора (a) против (b):

1. Пользовательская модель одинакова: изучивший `:switch` получает **тот же**
   результат от числового токена на `:scrollback` (исходная претензия
   RAI-113, minor). Вариант (b) закрепил бы расхождение и потребовал бы от
   пользователя помнить, какая команда как считает числа.
2. Оба corner-case из карточки в варианте (a) становятся **совпадением с
   frozen-поведением** (не «наш локальный выбор»): вкладка с label `"2"` не
   достижима токеном `"2"` (как и в `:switch`); одиночная вкладка
   `2024-report` не «воскрешает» вне-диапазонный `"2"` префикс-матчем.
3. Унификация через общий helper остаётся contract-change request (frozen
   `modules/ui/**` не тронут — non-goal соблюдён); выравнивание порядка
   уменьшает будущий diff унификации до чистого extract-method.

Отмеченная асимметрия сохранена осознанно: digit-шаг у `:switch` падает
typed `BadTabIndex`, у `:scrollback` — typed `RegistryError.UnknownTab`
(P2SR-02, вне allowed-семантики менять тип ошибки; ошибку несёт raw токен).
Это различие СЛОЁВ (типы ошибок), а не ПОРЯДКА резолюции — docstring
формулирует претензию «mirrors» только про precedence и честно называет
read-model шаги, которых у `:switch` нет.

  no fallthrough; non-digit → id/label/prefix. Семантика совпадает.
- **Принято**: spec-дополнения — `view`-хелпер (поля совпадают с
  `TabView` — сверено с `SessionRegistry.scala:75-84`) и три named-теста
  SCB-01a/b/c.
- **Исправлено**: рваный перенос в class-docstring (строки «…unique / label
  prefix. Every / failure…» нормализованы, слова не менялись); затем
  `scalafmt` (3.8.6, project config) переformatил оба docstring'а
  (word-wrap only, код не менялся — проверено diff'ом до/после).
- Существующие ассерты **не ослаблялись и не требовали правки** — построчное
  обоснование (карточка требует построчно при варианте (a)):
  - `pick("2") == Right(beta)`: digit; в обоих порядках — индекс 2 (id-step
    и label/prefix-step по `"2"` пусты на этом наборе вкладок) → ожидание
    истинно до и после.
  - `pick("1") == Right(alpha)`: аналогично, индекс 1.
  - `pick(alpha.value) == Right(alpha)`: `SessionRegistry.create`
    генерирует `TabId(UUID.randomUUID().toString)`
    (`SessionRegistry.scala:309`) — UUID содержит дефисы, никогда не
    all-digit → идёт по non-digit ветке (exact id), порядок которой не
    менялся.
  - `pick("beta")`, `pick("be")`, `pick("d")`, `pick("nosuch")`,
    `pick("")`: non-digit/empty — ветки не менялись.
  - `pick("99") == Left(UnknownTab("99"))`: digit вне диапазона — в новом
    порядке typed unknown сразу; в старом падал сквозь пустые
    id/label/prefix к тому же typed unknown. Результат идентичен.
  - `MainScrollbackPtySpec`: использует `alpha` (label), `ghost`
    (non-digit unknown), `1` (digit → индекс 1 = созданная первой вкладка) —
    результаты идентичны в обоих порядках, ассерты не тронуты.

## Resulting behavior

`:scrollback [tabId]` резолвит токен в порядке: (1) empty → typed
`UnknownTab("")`; (2) all-digit → 1-based `:tabs`-индекс, exclusively
(in-range → tab id; иначе typed `UnknownTab(raw)`), без fallthrough —
байт-в-байт precedence frozen `:switch`; (3) non-digit → exact tab-id →
exact label → unique prefix → typed `UnknownTab(raw)`. Все failure — typed,
без phantom-вкладок; one-writer/printAbove-дисциплина dispatch не тронута
(диф только в чистой функции `resolve` + docstrings).
