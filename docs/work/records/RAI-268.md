## Limitations / blockers

- **Two `RecoveryClass` enums (pre-existing hazard, disclosed).** `raider.core.RecoveryClass` (tool stamps) and `raider.runtime.lineage.model.RecoveryClass` (graph verdicts) are distinct types. Universal equality lets a cross-enum `==` compile (my first consistency-test assertion compared the enum instances and failed at runtime — caught by the focused run before any gate). The comparison therefore stays on the file's established `.toString` convention. A single shared enum is a schema-card decision, not a local edit.
- **First execute-gate attempt failed** on `scalafmt-check` (Test config of the touched spec files). Recorded honestly as manifest `20261102-015832-72088-0001`; remedied by formatting only.
- Hash-policy note (unchanged semantics): `GraphHash` includes the recovery verdict, so historical graphs recorded while the two names were classified ReadOnly (via a stale recording-time taxonomy) will re-hash if re-reduced today. This is the documented reclassification-by-design behavior (TAX-03 hash policy, pinned in `RecoveryTaxonomySpec`); no shipped fixture or golden contains the two names (`rg` over `contracts/` and cli/runtime tests: 0 hits).
