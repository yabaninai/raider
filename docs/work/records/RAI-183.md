## Resulting behavior

Chat settlement passes the exact answer returned by `processMessageBody` alongside the captured terminal event stream. The chat lineage producer records actual `ToolCallStarted` arguments and `TextReceived` content from the session trace, and replaces the final round's truncated trace text with the exact settled answer. These captured model responses are written into the existing `ModelCallData.response` field; no lineage schema or pointer protocol changed. Replay selects the recorded model identity, so a chat-origin run replays to `Match`; changing its pin produces `DifferentEnvironment(Match)`.

The LIN8B-03 fixture runs chat, headless, and campaign producers concurrently in distinct output roots. Each gets its own catalog run directory and readable toolchain pin. Chat and headless produce pointer-resolved lineage snapshots. The existing campaign bundle fixture is nodeless, so it correctly produces no lineage pointer rather than an invented snapshot. A chat republish is interrupted after complete generation files are written and before pointer replacement; the prior chat pointer remains readable, and the headless/campaign entries and pins remain unaffected.
