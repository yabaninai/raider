## Focused completion round (2026-10-23)

### Contract ruling

`docs/ci-runtime.md` §§2, 7–8 specify the decision semantics: check failures can be converted only by an explicit advisory policy; blocking rejection maps to exit 10; the declared success policy and threshold are frozen and their provenance recorded. They do **not** define the trusted-check metadata schema, declaration location, threshold representation, or bundle/config serialization for that policy. The current headless CLI exposes no declared-check policy surface. A CLI flag or invented bundle field would choose an unspecified public contract. Ruling: **policy surface gap documented; no advisory policy syntax added**. Contract question for review: which trusted, provenance-bound bundle/pipeline metadata declares check IDs as advisory and the threshold (including default/missing/unknown-ID behavior), and how is that declaration fingerprinted?

### Changed behavior and process evidence

- Summary status/error text is XML-safe, single-line, and neutralizes GitHub workflow-command delimiters. Structured JSON result payloads are unchanged.
- Defects during report/artifact initialization now return exit 27, emit an explicit no-complete-report diagnostic, and do not claim a successful result.
- A real CLI child with hostile output text verifies summary escaping/command neutralization and a full artifact scan for the GitHub/GitLab token sentinels already used by the RAI-185 harness.
- A real CLI child targeting a regular file as the output directory reproduces an artifact-initialization failure and exits 27 with a truthful no-report diagnostic.
