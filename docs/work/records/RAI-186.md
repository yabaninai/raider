## Stabilization round (2026-10-23, baseline `6bca01ba34f672d1166d83b12a7bc6b7f9d3566a`)

### New red diagnosis and correction

The `WrapWiringSpec` failure in manifests `20261023-002344-44457-0001` and `20261023-003107-55816-0001` is deterministic, not a load flake. The exact isolated command failed identically 3/3 at the assertion expecting `unknown --ci 'cirrus'`; the rendered Markdown contained `unknown --ci &apos;cirrus&apos;`. `reportText` had reused the XML escaper, which unnecessarily escaped apostrophes in Markdown. This was unrelated to the I/O-initialization-to-exit-27 mapping; that mapping remains unchanged. The XML escaper now retains apostrophes, which XML permits in the double-quoted attributes used here, while continuing to escape ampersand, angle brackets, double quotes, and invalid controls. The three failing reproductions are retained as evidence; the passing targeted rerun is after the correction.

### Minimal advisory-policy contract proposal (not implemented)

**Preferred surface:** trusted workflow/bundle check metadata, specifically the already-exported `trustedChecks` declaration. This minimal proposal does not add a threshold field: whether advisory checks need a failure threshold is an unresolved contract question for the coordinator/card, not an assumed behavior in this lane.

**Serialization:** serialize the field alongside each trusted check in the workflow/bundle declaration (for the current chat-export shape, the generated Scala declaration corresponding to `(name, argv)` becomes `(name, argv, advisory)`; any persisted bundle encoding/version and legacy decoding rule must be fixed by the contract card before implementation). Do not accept a runtime CLI override or model/input-supplied policy.

**Provenance:** freeze the declaration with the compiled trusted workflow/bundle. Record its policy digest and provenance with the run outcome in the manner required by `ci-runtime.md` §§2 and 7–8: the pinned trusted artifact/source identity binds the policy, and the run records the resolved policy identity used for the verdict. A context-config alternative would require the same trusted-owner boundary and frozen digest, but is not preferred because it splits workflow semantics from the exported workflow declaration.
