## Limitations / blockers

- The adversarial case simulates the broken-certifi condition on the target
  stock-macOS interpreter by a `PYTHONPATH` stub that imports successfully and
  raises from `where()` (verified live before the run), plus
  `RAIDER_BOOTSTRAP_SYSTEM_CA` pointed at an absent file; making a real
  certifi install broken or `/etc/ssl/cert.pem` unreadable would require
  modifying the host. The levers exercise the same code branches as the real
  conditions (exception raised inside `where()`; unreadable-file path), the
  same simulation approach accepted for RAI-218.
- The four named cases ran in scratch copies of `scripts/` +
  `experiments/repl-spike/fetch_toolchain.py` to keep the worktree pinned
  store untouched (it was empty; per-card non-goal "repo commits under
  artifacts/"). The copied `bootstrap_ca.py` is byte-identical to the worktree
  file at gate time; after the cases, the worktree store was populated once
  through the hardened script (also required by the `compile-fixtures` gate)
  and that in-worktree run resolved via certifi, exit 0.
- The first `quality-profile` attempt failed on the empty-store prerequisite;
  recorded verbatim above with its manifest hash. No gate policy, threshold,
  or protected verifier was changed; the 1800 s `sbt-test` policy cap (raised
  2026-10-26) was used as-is, no timeouts occurred.
- Lane-level only: no push, no merge, no board edit; integration gates remain
  the coordinator's obligation.
