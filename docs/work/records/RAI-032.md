## Resulting behavior

The pi profile importer (card RAI-032) is implemented as a bounded, byte-faithful compatibility port of the pinned pi subagent corpus:

- Vendored pinned corpus under `vendor/pi-profiles/upstream/` (10 files from `https://github.com/earendil-works/pi` @ `55a5c6914570e2ae31ca36297654483bbbf46883`, MIT, `packages/coding-agent/examples/extensions/subagent`; `index.ts` intentionally not vendored), with `vendor/pi-profiles/MANIFEST.sha256` (verified exit 0) and `vendor/pi-profiles/PROVENANCE.md` (pin, fetch commands, per-file hashes, update rules).
- New Scala 3 + ZIO module `modules/compat-pi` (6 main sources, no build registration — see blockers): strict bounded frontmatter parser mirroring upstream `agents.ts` semantics (scalars, inline arrays, block lists; unsupported shapes and unknown keys enumerated, never silently dropped), fixed pi→Raider tool mapping table (`read→fs_read`, `grep→fs_search`, `find→fs_tree`, `ls→fs_tree`, `bash→proc_run` degraded, `edit→fs_edit`; `write` rejected; `mcp__*` rejected), profiles without `tools` get pi's default set with policy `kind=piDefault`, `write` rejected as an explicit parity gap. Canonical report (`PiImportReport.renderCanonicalJson`): sorted keys, 2-space indent, trailing newline, `schemaVersion=1`, deterministic `snapshotId` = SHA-256 over `commit=<c>\n` + sorted `file <path> <sha>\n` lines (independently re-derived in Python: match). Counts are arithmetic over report sections: supported=43, ignored=9, rejected=1 for the pinned corpus. Typed import errors (`PiImportError`, `NoStackTrace`); missing corpus is a typed `CorpusMissing`, environment/IO failures are defects.
- Contracts: `contracts/compat/pi/pi-import.schema.json` (draft 2020-12, `additionalProperties: false`, hash/enum patterns) validating the golden (structural validation PASS including `$ref` resolution and a negative control), `contracts/compat/pi/README.md` (mapping table, counts semantics, honesty rules, re-pin policy), `contracts/compat/pi/golden/pi-import-golden.json` (pinned canonical report, sha256 `a4293b8464004375285fb14b8c3f0e4fbed977a4096fdff3fbe98931d64f857c`).
- Specs (plain-main, runnable standalone without sbt): PIIMP-01 `PiImportGoldenSpec` (30 checks; `--update` re-pin mode) and PIIMP-02/03 `PiImportAdversarialSpec` (12 checks: unknown tool rejected-not-mapped, malformed file rejected with typed reason, missing description rejected, inline arrays parsed, unknown keys enumerated, mutation → new snapshotId, reloading never widens, missing corpus → typed error).

## Limitations / blockers

- **Blocker B1 (registration)**: `modules/compat-pi` is not registered in `build.sbt` — the file is coordinator-owned and outside this card's allowed paths. Proposed registration for the coordinator: `lazy val raiderCompatPi = (project in file("modules/compat-pi")).settings(commonSettings, testSettings, name := "raider-compat-pi").dependsOn(raiderCore % "compile->compile;test->test")`. Until registered, `sbt-compile`, `scalafmt-check` and `sbt-test` are vacuous for this module; real compile coverage is `compile-fixtures` (219 files, exit 0) and spec coverage is the standalone java runs. The specs are plain-main because no zio-test jars exist in the pinned closure.
- **Blocker B2 (gate registry)**: `vendor/**` and `THIRD_PARTY_NOTICES.md` map to no `path_profiles` entry in `scripts/quality-policy/registry.json`, so every `QUALITY_EXECUTE=1` run fails closed with `changed files map to no profile`. Per the RAI-281 precedent this is gate-policy class: a separate reviewed card must add a real check (e.g. a vendor-audit gate proving `MANIFEST.sha256` agreement + `PROVENANCE.md` pin, and mapping `^vendor/pi-profiles/|^THIRD_PARTY_NOTICES.md`), never a silent skip entry. Until that lands, no runner manifest can be produced for this tree; the lane evidence is the direct execution of each profile's gate argv (all exit 0, listed above), not a runner manifest.
- `python3-jsonschema` is unavailable in the environment; schema validation used a hand-rolled structural checker (required/additionalProperties/enum/pattern/`$ref`/const) with a working negative control. Full library validation should be part of the gate-policy card in B2 if the runner gains that capability.
- Red-probe logs and gate logs live in the gitignored temp tree (`/var/folders/.../opencode/`) and are not reproducible from a fresh clone; the immutable evidence in-tree is the pinned corpus hashes, `PROVENANCE.md`, the golden file, and the specs themselves.
- Runtime scope: the importer validates byte-faithful porting of profiles/prompts/tool policies; it does not execute imported profiles (no provider runs), so no paid calls were made and none were needed.
