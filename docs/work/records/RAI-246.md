## Resulting behavior

Test-only deterministic trigger for the outbound terminal-pick window, per the card: a private[processapi] `ProbeSeam` (four `AtomicReference[Option[Promise[Nothing, Unit]]]` hooks, all `None` when disarmed) plus three seam sites in `Outbound` — (1) signal when a receipt admission finds the queue full and is about to park as a waiter, (2) hold a woken waiter between the wake and its landing modify, (3) signal the writer's arrival at the terminal pick and hold it post-pick/pre-write. Every site short-circuits to a no-op when disarmed: no allocation, no scheduling point, no behavior change; no production caller touches the seam. A new `OutboundSpec` probe test ("RAI-246 deterministic trigger: the terminal pick never overtakes a woken waiter's landing") arms the seam and drives the interleaving deterministically: saturate 64 receipts → fork the 65th (registers as a waiter) → fork a writer frozen on its first write → install the terminal (its single wake moves the registered waiter to the landing hold) → drain → observe whether the writer's terminal pick precedes the woken waiter's landing → release the landing, then the writer. On the pre-RAI-232 base (`f771f8d` product file, SHA-256 `3a83c597b71651996c3bdbbf7e4d2e85631fa34be69277d5d02fb01d5a2a285f`) the trigger deterministically strands the woken waiter's frame (accepted count 64, depth 1); with the delivered RAI-232 empty-point gate the pick is refused until the landing completes (accepted 65, depth 0, terminal last). Public API/schema: none (seam is `private[processapi]`; no production consumers changed).

## Review fixup (2026-10-31)

Coordinator review verdict: APPROVE with three advisory P3 findings; all applied as comment/record edits, no behavior change.

1. **Stale comment + overstatement** (`Outbound.scala`): the `ProbeSeam` Scaladoc and the `probeSeam` field comment still referenced the discarded nullable design ("null") and claimed "no allocation" on the seam path. Both now describe the committed design: `AtomicReference[Option[Promise[Nothing, Unit]]]` hooks, `None` = disarmed; a disarmed seam site costs one volatile reference read and short-circuits to a no-op (no scheduling point, no behavior change), and a site allocates or schedules only when a test arms its hook.
2. **Imprecise `test_summary` wording** (this record, gates row in "Acceptance evidence"): each manifest's `test_summary` counts that single run's gate results (EXECUTE manifest: 10 passed / 0 failed / 0 skipped; fast-ci manifest: 11 / 0 / 0), not unit tests; the row now states this exactly and points to the `sbt-test` gate log for per-suite unit-test totals.
3. **Writer-hold interrupt asymmetry** (`Outbound.scala`, `probeTerminalPickSeam`): resolved comment-only — the asymmetry is intentional and safe. The writer-side post-pick hold deliberately registers no `onInterrupt` cleanup: by suspension time the pick has already removed the terminal from `State` and the writer holds no gate or seam registration, so an interrupt unwinds the writer exactly as an interrupt inside `boundedWrite` would and nothing can pin the empty-point gate. The waiter-side landing hold keeps its interrupt removal because the waiter is still registered in `State.waiters` (pinning the gate) while suspended. Documented in the method Scaladoc and in a one-line note at the hold site.
