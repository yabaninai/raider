## Resulting behavior

Palette/help на продуктовой поверхности TabShell (raider.repl.TabShellHost →
raider.ui.TabShell), реализовано минимальной аддитивной частью в modules/repl
(frozen modules/ui не менялся; TabShellHost.scala — только аддитивный хук):

- `raider.repl.ShellPalette` (NEW, pure): каталог команд продукта ДЕРИВИРУЕТСЯ
  из frozen `CommandRouter.parse` routing-пробой (registered = роутится не в
  `UnknownCommand`; только `:`-имена), а не ручным списком — иначе
  freshness-тест невозможен по определению. Prefix-поиск (`complete`),
  ближайшая команда для неизвестного токена (`nearest`: prefix →
  Levenshtein ≤ max(2, len/4), tie-break shortest/lex).
- `raider.repl.PaletteCompleter` (NEW): JLine Completer над каталогом — TAB
  на `:`-слове; уникальный префикс дополняет до полной команды (≤2 нажатия:
  prefix+TAB+Enter = найдено и исполнено), пустой/неоднозначный — листинг
  всего каталога. Вне `:`-слов TAB инертен (поведение до RAI-106 не меняется).
- `raider.repl.PaletteShellTerminal` (NEW): тот же ONE-writer
  (RAI-061/RAI-102 семантика JLine — printAbove/orDie, EOF→None, idle
  Ctrl+C→пустая строка — mirroring frozen ShellTerminal.JLine) + completer в
  LineReader + decorator `withPaletteHints`: блок
  `hint: unknown command: X` (точный frozen-render anchor, запинен спекой)
  получает вторую строку `  did you mean: :help?` В ТОМ ЖЕ атомарном
  printAbove-блоке — один writer и сохранение draft не задеты. Нет ближнего
  совпадения — блок проходит без изменений (P2W-02-транскрипт не менялся).
- `raider.repl.TabShellHost`: аддитивный хук `paletteTerminal` (новый def);
  `run` строит терминал через хук (default = PaletteShellTerminal.jline).
  Остальное тело не тронуто; frozen RAI-102 PTY-приёмка прогнана в гейтах
  без изменений исходников.

## Limitations / blockers

- Скоуп палитры — TabShell/CommandRouter (ShellCommand-frozen API, как
  предписано packet'ом). Консольные команды REPL-цикла (raider.repl.Main:
  :jobs/:cancel/:log/:reset — «chat»-команды другого поверхности) в палитру
  НЕ включены: у них свой completion-контракт (RAI-068 EngineCompleter) и
  свой help (Commands.helpText); их freshness — отдельная карточка, чтобы не
  задевать RAI-068 в этой.
- Листинг кандидатов JLine4 после TAB-TAB: accept первого `:quit` может быть
  отложен на одно нажатие (наблюдение задокументировано и покрыто retry в
  драйвере); на UX не влияет (человек видит свежий prompt), для скриптинга
  задокументировано.
- Атомарность строк оценивается по финальному очищенному транскрипту (тот же
  класс ограничений, что у референсной RAI-102 acceptance); capability-запросы
  отвечаются по чанкам.
- compile-fixtures требует artifacts/tools/m2 (untracked, скопирован из root
  в worktree по packet); manifestы гейтов лежат в untracked artifacts/ —
  evidence привязан sha256 в этом record.
- Frozen-файлы TabShellHostPtyApp/TabShellHostPtySpec не менялись;(child моей
  PTY-спеки — тот же TabShellHostPtyApp) — при merge конфликтов с
  RAI-103/104/105 не ожидается: мои пути — только новые файлы + аддитивный
  хук в TabShellHost.scala.
