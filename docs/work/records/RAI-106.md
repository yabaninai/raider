## Resulting behavior

Palette/help on the product TabShell surface (`raider.repl.TabShellHost` →
`raider.ui.TabShell`), implemented as a minimal additive change in `modules/repl`
(`modules/ui` was frozen and unchanged; `TabShellHost.scala` received only an additive hook):

- `raider.repl.ShellPalette` (NEW, pure): the product command catalog is DERIVED
  by routing probes through frozen `CommandRouter.parse` (registered means it
  routes to something other than `UnknownCommand`; only `:` names), not from a
  hand-maintained list — otherwise a freshness test is impossible by definition.
  Prefix search (`complete`), nearest command for an unknown token (`nearest`: prefix →
  Levenshtein ≤ max(2, len/4), tie-break shortest/lex).
- `raider.repl.PaletteCompleter` (NEW): JLine Completer over the catalog — TAB
  on a `:` word; a unique prefix completes to the full command (≤2 keystrokes:
  prefix+TAB+Enter = found and executed); an empty/ambiguous prefix lists the
  entire catalog. TAB is inert outside `:` words (behavior before RAI-106 is unchanged).
- `raider.repl.PaletteShellTerminal` (NEW): the same ONE-writer
  semantics from RAI-061/RAI-102: JLine `printAbove/orDie`, EOF→None, idle
  Ctrl+C→empty line, mirroring frozen `ShellTerminal.JLine`), plus a completer in
  `LineReader` and the `withPaletteHints` decorator: the block
  `hint: unknown command: X` (exact frozen-render anchor, pinned by the spec)
  receives a second line, `  did you mean: :help?`, in the SAME atomic
  `printAbove` block — one writer; draft preservation is unaffected. If there is
  no nearby match, the block passes through unchanged (P2W-02 transcript unchanged).
- `raider.repl.TabShellHost`: additive `paletteTerminal` hook (new def);
  `run` creates the terminal through the hook (default = `PaletteShellTerminal.jline`).
  The rest of the body is untouched; the frozen RAI-102 PTY acceptance was run
  by the gates without source changes.

Acceptance (P2P-01..03) — real PTY runs of the product host (child =
frozen `TabShellHostPtyApp` = product wiring; driver modeled on RAI-102:
`/usr/bin/script` openpty relay, responses to capability queries, ANSI cleanup,
registry report as oracle; the spec is a SEPARATE file, frozen files were not
edited):

- P2P-01: `:pl`+TAB+Enter → `:plugins` executes (“(no plugins)”), `:he`+TAB

- P2P-03: during active streaming from a real hub feed (221 events @6ms,

## Limitations / blockers

- Palette scope is TabShell/CommandRouter (frozen ShellCommand API, as
  specified by the packet). REPL loop console commands (`raider.repl.Main`:
  `:jobs`/`:cancel`/`:log`/`:reset` — “chat” commands from a different surface)
  are NOT included in the palette: they have their own completion contract
  (RAI-068 EngineCompleter) and help (`Commands.helpText`); their freshness is a
  separate card, so this one does not touch RAI-068.
- JLine4 candidate listing after TAB-TAB: accepting the first `:quit` may be
  delayed by one keystroke (the observation is documented and covered by a
  driver retry); this does not affect UX (the user sees a fresh prompt), and is
  documented for scripting.
- Line atomicity is evaluated from the final cleaned transcript (the same class
  of limitation as the reference RAI-102 acceptance); capability queries are
  answered in chunks.
- compile-fixtures requires artifacts/tools/m2 (untracked, copied from root
  into the worktree per packet); gate manifests are under untracked artifacts/ —
  the evidence is bound by sha256 in this record.
- Frozen files TabShellHostPtyApp/TabShellHostPtySpec were not changed (the
  child of my PTY spec is the same TabShellHostPtyApp), so merge conflicts with
  RAI-103/104/105 are not expected: my paths are only new files plus an additive
  hook in TabShellHost.scala.
