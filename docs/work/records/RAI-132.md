## Resulting behavior

The P3 send/steering obligation is closed end to end on scripted backends, consuming the FROZEN runtime steering layer (RAI-065/074 `raider.runtime.mailbox`) with zero runtime changes:

1. **Facade send wiring** (`modules/repl/.../facade/FacadeOps.scala`, new `facade/Steering.scala`): every facade-started job (`scout("p").start()`, `agent.start(prompt)`, mapped descriptors) opens a `SteerChannel` over a real runtime `Mailbox` (capacity 32, the frozen delegation default), published under the real `JobId` through a promise — the same publish-then-await shape as the frozen `DelegationToolset` wiring. `JobHandle.send(text)` (previously a typed W10-refusal throw at `FacadeOps.scala:249-251`) now delegates to the mailbox and returns a **typed receipt**; it is total, never an exception, never a silent no-op.
2. **Steering-aware turn loop** (`steerableAttempt`): the facade-side twin of the frozen `childTurns` — steering is drained at turn boundaries only and appended as ONE `owner steering:\n- [msgId] <text>` user message before the next `textAttemptMessages` call (the ONE execution point; no second runtime). Unsteered jobs behave exactly as before (one turn, no sections; pinned by a dedicated fixture). A daemon terminal watcher seals the mailbox at the observed terminal status and resolves every leftover receipt (expired) — an ack is never silently converted into a loss.
3. **Typed receipts** (`SteerReceipt`): `Queued` (acks from the mailbox, resolves via `settled` to `Applied` — drained at a boundary and part of the next model-turn input — or to expired-`None`), `Rejected` (verbatim `MailboxError`: `UnknownJob` / `Full` / `TerminalJob`). Receipt rendering is a pinned one-liner. Applied messages are tracked per channel (registration BEFORE the mailbox send, so a racing boundary drain can never miss a receipt).
4. **REPL command `:send <jobId> <text>`**: dispatched through `Commands.handle` via the pure `Commands.parseSend`; registered in `Commands.helpText` and the `ReplChatCommands` freshness catalog (RAI-111 precedent) between `:cancel` and `:log`; the stale "send steering" out-of-slice prose is gone. Usage refusals (bare command, missing text, blank text including a quotes-only `""`) never dispatch. Arguments are escaped into generated string literals (`Commands.escapeScala`, same discipline as `Main.scalaStr`). `ReplCommands.printSend` prints the receipt verbatim.
5. **`:jobs` marks steerable jobs**: `[steerable]` is appended when the channel exists and the job is not terminal (`FacadeOps.isSteerable`).

Cancellation/deadline semantics untouched; no mailbox semantics changes; no cross-process steering; no live providers; no second scheduler.

## Limitations / blockers

- **Pre-existing environmental finding (not changed under this card; candidate for a separate card):** in the dotty in-process REPL, `zio.Console.print`/`printLine` (implemented via `ZIO.attemptBlockingIO`) from INTERPRETER-world background fibers never reaches the process stdout, while the identical call on the foreground (unsafe.run) path does, and raw `java.lang.System.out` works from the same fibers. Reproduced with a zero-facade repro in the interpreter (`forkDaemon` + `zio.Console.printLine` vanishes; raw print appears). The product delta echo for BACKGROUND facade jobs (`FacadeOps.echoBackend`) is therefore invisible in the legacy cycle in this build; this predates the card (the W10 `Task(textAttempt)` start path used the identical echo call chain on the same JobManager fiber). Consequence for STR-03 evidence: the PTY fixture backend prints its paced deltas via raw `System.out`+flush from the SAME job fiber — the same async writer surface — so the interleaving/prompt-tear oracle is real; the echo itself is unit-verified to work in a plain JVM runtime. No product echo code was modified.
- The applied receipt is observable programmatically (`receipt.settled`) and in tests, but the console `:send` answer prints only the QUEUED line (application is visible through the job's next turn). A `:receipts`-style surface was deliberately not added (not in the card contract).
- Send ids are generated (`st-N`), so facade-level sends are not idempotent by caller-supplied key (the runtime mailbox dedup remains available to callers who bring ids; REPL steering does not).
- `:send` text is single-line (the `:` fast path is one physical line, consistent with the other commands); multi-line steering text needs the Scala-level `handle.send(...)`.
- The banner `cmds :` line was NOT extended with `:send` (MainScrollbackPtySpec/MainTabsPtySpec pin it byte-exactly; :help is the documented surface) — flagged for the coordinator in case a follow-up card wants the banner updated together with those pins.
- Honest red trail before green: one EXECUTE run failed `scalafmt-check` (exit=1, artifacts/quality/20261014-000833-15635-0001) → `sbt scalafmtAll` (touched only the 11 lane files) → rerun passed. Four red PTY runs during fixture bring-up (compile errors of the typed-over-PTY fixture backend, then the missing-delta finding above); final fixture green ×3.
- Evidence applies to the tree at commits `7ae56f7..5b36d9f` (source unchanged after the passing gate runs; commits only). PTY temp evidence dirs from earlier runs were superseded; the final pair is preserved under `artifacts/rai132-pty/` (gitignored path, hashes recorded above).
