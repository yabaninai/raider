## Resulting behavior

`raider --help` and `raider help` now exit 0 and print the command list to
stdout (empty stderr). Previously both fell through to
`HeadlessRunner.exitCodeFor(Configuration)` = exit 21 (audit:
`docs/work/records/AUDIT-20261101.md`, candidate JAR sha256
`e629ab0bd14a54f333c777884e184a3e7c3a58b5748ef02501acbb424e23f152`,
`java -jar … --help` → 21).

The help text (in `modules/cli/src/main/scala/raider/cli/Main.scala`) lists
exactly the commands `Main` dispatches today — `run`, `chat`, `process-api`,
`compile`, `workflow run` (compiled and portable forms), `workflow check`,
`workflow explain`, `plugin`, `replay`, `resume`, `verify-artifacts` — with
their real flags, plus:

- the REPL separate-distribution pointer ("The interactive Scala REPL ships
  as a SEPARATE distribution (raider.repl.Main); this headless CLI carries no
  REPL compiler or terminal dependencies") — no REPL is advertised as a
  command of the headless artifact;
- the unknown-flag/subcommand behavior (nonzero exit 21 + diagnostic + this
  list);
- the ci-runtime §8 exit-code legend (0, 10, 20, 21, 22, 23, 24, 25, 26, 27,
  130/143).

Unknown flags and unknown subcommands keep their existing exit 21 and their
existing `raider: RA-CFG:` diagnostic line; the entrypoint now appends the
pointer line `raider: run \`raider --help\` for the command list` to every
`CliArgs` parse failure. Routing is a pure seam `helpCommand(argv)` — it
matches `--help`/`help` only as the FIRST argv token (prefixes such as
`--helpful`/`helper` fall through), performs no stdout writes, no
`System.exit`, and no provider/runtime initialization, and `main` dispatches
it before all other routes. Command behavior for all existing routes is
untouched (module dependency graph unchanged; no `build.sbt` changes — the
headless CLI stays REPL-free).
