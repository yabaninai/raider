# RAI-269: thread the configured workspace root into the coder system prompt (RAI-259 follow-up)

Status: done. Date: 2026-11-02T05:03:12Z. Baseline commit/source: `72b1407` (branch `lane/rai-269`, worktree `artifacts/lanes/rai-269`).

## Resulting behavior

`CoderPrompts.CoderSystemPrompt` is now `def CoderSystemPrompt(workspaceRoot: Path): String` — the base prompt plus the project-instructions section loaded from the **configured workspace root** instead of the process CWD. Both frontends pass the same root value they hand to the coding toolset, so the prompt is now composed at the root the write-path policy enforces:

- `ChatLoop` (interactive chat): `CoderPrompts.CoderSystemPrompt(Paths.get(wsPath))` — the same `wsPath` already handed to `CodingToolset.make` on the line above.
- `HeadlessRunner` (`--agent coder`): `CoderPrompts.CoderSystemPrompt(wsPath)` — the same `wsPath: Path` value the toolset gets.

The card's disclosed limitation from RAI-259 is closed: an explicit `--workspace` pointing away from the CWD now feeds the prompt from THAT root. With no `--workspace`, both frontends default `wsPath` to `Paths.get("").toAbsolutePath` (RAI-258 CliArgs default). Exactness note (review advisory): the no-flag composed prompt is byte-identical to RAI-259's only for a CWD with NO symlinked path component; when the CWD itself resolves through a symlink, RAI-259's raw-path composition silently dropped the instructions while the new canonicalization loads them — a divergence strictly toward tool parity (the tools always enforced the real-path root). CPR-02 pins equality to the real-path loader semantics, `ProjectInstructions.surface(base, cwd.toRealPath())`, not to RAI-259's raw-path behavior.

Canonicalization detail: the root is resolved to its real path before composition (`private def canonicalRoot(root: Path): Path = try root.toRealPath() catch case _: Exception => root.toAbsolutePath.normalize()`), matching the resolution `Workspace.make` performs (`p.toRealPath()`) and that `WritePathPolicy` enforces via `workspace.root`. This matters because `ProjectInstructions.load` checks `candidate.toRealPath().startsWith(rootReal)` — a raw symlinked path (e.g. a macOS `/var/...` temp dir whose real path is `/private/var/...`) would silently drop otherwise-valid instructions. The canonicalization is fail-open: a missing or broken-symlink root falls back to the normalized absolute path, where the loader finds no instruction file and the base prompt is used byte-identically; the bounded toolset diagnostics for an invalid root remain owned by `CodingToolset.make` (CPR-03 pins both sides: prompt fail-open AND `toolset.isLeft` typed error).

Composition remains a pure read (`ProjectInstructions.surface`), `def` not `val`, so every session build re-reads the current instruction file. The frozen base text (`CoderBasePrompt`) is byte-identical to the pre-change literal (1036-char literal diff-verified against `HEAD:.../CoderPrompts.scala`); RAI-270 owns any refresh of that text.
