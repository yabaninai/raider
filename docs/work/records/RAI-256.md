## Resulting behavior

The source-inventory composition behind every quality fingerprint is isolated from sibling worktrees and local tool state, and is now explicitly versioned:

- Registry `fingerprint_excludes` gains `"wt"` (segment at any depth): git worktrees of parallel lanes (`wt/<card>` per `docs/parallel-development.md` §1b) are operational copies, never product inputs. This closes the audited defect: the 2026-11-01 integrated eval manifest inventoried 23,515 `wt/` paths, and the merged self-check timed out inside the frozen 120 s budget hashing sibling worktrees (board wave H). No thresholds or checks were changed.
- `".opencode"` stays a base exclusion (local opencode install state: `node_modules`, `package.json`, ...), but the checked-in product-input prompt directories `.opencode/agents/**` and `.opencode/commands/**` are re-included by a root-anchored carve-out in `_excluded` (`OPENCODE_PROMPT_INCLUDES`). They are gate-policy inputs (AGENTS.md execution mode) and were always covered by the documented fingerprint spec (`docs/quality-gates.md` §2: "tracked + nonignored untracked product source/config/specs/prompts"). The carve-out is root-anchored, so `wt/raider-sibling/.opencode/agents/x.md` stays excluded (its `wt` segment decides).
- `artifacts/**` (lane evidence) was already excluded by segment and is now pinned by a self-test.
- Inventory versioning: `CURRENT_INVENTORY_VERSION = 2` in `scripts/quality/quality.py`. `execute` records `source.inventory_version`; `inventory` writes the version into base manifests; strict `verify` rejects schema-v2 manifests whose recorded version differs, with a migration diagnostic; `fingerprint` refuses to diff a base manifest across compositions (regenerate, never diff two universes). Real pre-change manifests also fail the policy-hash check (the registry changed in this card), so historical `--allow-stale` verification does not apply to them either (RAI-209/RAI-135 precedent for registry changes).
- The inventory walk skips a per-entry `OSError` (file vanishing mid-walk under concurrent gate runs) instead of crashing; a vanished included file re-appears as a diff on the next recomputation (fail-safe direction).
- Registry `path_profiles` gains `"^.opencode/agents/|^.opencode/commands/" → ["docs"]` so a prompt edit classifies and gates instead of hard-failing as `__unmapped__`. The dots are deliberately unescaped: the matcher only strips `^` (a backslash would never match; existing registry style, cf. `^README`). The latent `^\.scalafmt.conf` backslash form in the neighboring pattern was left untouched (out of scope).
- No gate definitions, thresholds, profile memberships, or gate-verifier rejection semantics were changed; the self-test battery grows (`_self_test_inventory_isolation`, pre-isolation-v2 verify cases, versioned-base-manifest probe, `.opencode` classify cases).

## Limitations / blockers

- Record-finality disclosure (RAI-253/RAI-255 protocol): this record was written after the gate runs above, so those manifests list it as a post-gate operational-record ADDITION (visible notice, not a problem, by the RAI-054 additive records policy; records are excluded from the fingerprint). The record was not edited after any gate run.
- The root-checkout benefit (the 23,515 `wt/`-path inventory and the 120 s timeout) manifests at the root checkout with live `wt/**` worktrees; this lane has no `wt/` directory, so the lane budget delta is only the 5 included prompts (+~7 s self-check). The coordinator should observe the post-merge self-registry-check duration at the root; no threshold was changed either way.
- All manifests and base inventories produced before this card were built by composition v1 and must be regenerated; strict verify (and manifest-diff classification against old bases) refuses them with precise diagnostics. Snapshot lanes re-bootstrap with `make quality-inventory`.
- `legacy_inventory` (schema-v1 path) keeps its live-registry exclude set, so v1 exclude-set semantics are approximate after any registry change; v1 manifests also bind a policy hash and are already invalidated by this card's registry edit (documented in the function docstring).
- The `.opencode` prompt path mapping (`^docs` profile) is proven at classification level (unit case) and at inventory level (ISO-04); no gate run was executed on a prompt edit itself, since editing `.opencode/**` is outside this card's allowed paths.
- `.opencode/agents|commands` prompts are hashed as product inputs from now on; any edit to them flips the fingerprint and re-gates — intended (they are gate-policy inputs), but reviewers should expect prompt edits to require `docs`-profile reruns.
