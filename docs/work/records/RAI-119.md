## Resulting behavior

Устранены load-флейки PTY/plan-семейства детерминизм-паттернами прецедентов
(71d0aa3 quiescence drain; 91a6575 retry со свежим рендером), ассерты НЕ
ослаблены, таймауты как «лекарство» не удлинялись, продуктовый код не менялся:

1. **Driver-infra fix (обе PTY-спеки, воспроизведённый красный att1):**
   `drive()` создавал evidence-dir только в `persist()` — ПОСЛЕ тела сессии.
   Первый PTY-тест против свежего `RAI105_PTY_EVIDENCE_DIR`/`RAI113_PTY_EVIDENCE_DIR`
   спавнил ребёнка, чьи репорт-записи молча фейлились (`.ignore`):
   phase-оракул слеп, ВСЕ `waitForReport` честно таймаутят при ПОЛНОСТЬЮ
   корректном поведении child (exit 0, бейджи рендерятся). В дефолтном пути
   (tmp-dir) баги нет — поэтому изолированные прогоны зелёные, а acceptance
   прогоны с env-var красные. Фикс: `Files.createDirectories` ДО старта child.

2. **PlanPanelSpec «:reject cancels the LIVE plan»** (wave-4 flake 1/4,
   подпись LIN-14: ready2/approved2=false, labels List("plan","plan") без
   "plan-exec"):
   - drain (71d0aa3-класс): после печатного исхода :reject тест дожидается
     ТИПИЗИРОВАННОГО поселмента отменённой работы `session.awaitPlan(planJob)`
     (Left = типизированная отмена; Right невозможен и ассертом запрещён) —
     конвейер отмены дренирован ДО старта повторного плана, два daemon-watcher'а
     больше не могут интерливить записи в общий outcomeRef вокруг второго
     `track`;
   - retry со свежим рендером (91a6575-паттерн): при промахе фазы Ready —
     принудительный `panel.refresh` (свежий re-derive) и повторное ожидание;
     ассерт по-прежнему требует Phase.Ready.

3. **TabShellUnreadPtySpec**: добавлен `waitQuiet` (byte-stable quiescence,
   прецедент 71d0aa3):
   - p2u03: drain после settled-репорта ПЕРЕД badge-ожиданиями (бейдж-маркер
     недетерминирован, пока pump рендерит burst) + drain перед `:quit` (класс
     «1 torn row» из RAI-113 хронологии: echo :quit вклеивается в бар-строку);
     новые манифест-поля `burstDrained`/`drained` + ассерты;
   - p2u01: ВОСПРОИЗВЕДЁННЫЙ промах маркера (см. PTYD-02 round 1 run9) —
     drain перед `(2 unread)`-ожиданием + retry со свежим `:tabs`-рендером
     (91a6575 дословно); новые поле `drained` + ассерт.

4. **MainScrollbackPtySpec**: waitQuiet-тайминги НЕ воспроизведены (8 полных

## Limitations / blockers

- **Wave-4 классы, НЕ воспроизведённые в этой lane** (честный статус):
  PlanPanelSpec labels/ready2 (18 попыток под нагрузкой 40–164) и
  MainScrollbackPtySpec waitQuiet (8 попыток) — фиксы PlanPanelSpec применены
  ПО ПРЕЦЕДЕНТАМ как превентивная детерминизация реальной harness-гонки:
  watcher план-работы #1 и watcher повторного плана пишут типизированные исходы
  РАЗНЫХ работ в ОДИН общий `outcomeRef` в произвольном порядке; запись (h1,
  Left), опоздавшая после (h2, Right), навсегда клинит snapshot в Planning
  (collect-фильтр по id отбрасывает чужой исход). Test-side это полностью не
  устранимо (outcomeRef приватен, наблюдаемого сигнала завершения watcher'а
  через публичную поверхность нет) — drain сужает окно, refresh-retry лечит
  stale-случай. Если flake воспроизведётся снова — кандидат в contract-change:
  per-job скоупинг outcomeRef в PlanPanel (продуктовый код, вне этой карточки).
- Подпись wave-4 (approved2=false + НЕТ plan-exec в labels) не полностью
  объясняется wedge-гонкой (она клинит только snapshot): одновременное
  отсутствие plan-exec указывает и на второй механизм (approve2 не дошёл до
  startExecution — напр. подвисание/фейл job2 под штормом). Воспроизвести не
  удалось; drain-cancelled-settlement добавляет недостающую синхронизацию и
  для этого пути. Наблюдение передано координатору на случай рецидива.
- PlanPanelSpec не имеет per-test timeout — awaitPlan-drain в тесте
  гарантируется ZIO-семантикой поселмента отменённой работы (promise
  публикуется в settle()), зависание невозможно; тем не менее отмечаю для
  ревью.
- Load-стенд — приближение 8-lane шторма (4 клона baseline 8d07036 за
  пределами репозитория + CPU-бурнеры, load до 164), не точная реплика
  (соседние lane-воркtrees не трогались). Все числа нагрузки зафиксированы
  честно в логах.
- Evidence-каталоги (artifacts/rai-119/**) вне git — координатору при merge:
  Manifest hashes гейтов в таблице выше; PTY-summaries/транскрипты сохранены
  в worktree до merge.
- Полный `sbt --batch test` прогнан 1 раз (по карточке ×1), под остаточной
  нагрузкой (load 44–93); gate-прогоны — на тихой машине (шторм погашен до
  гейтов, что честнее для официального evidence).
