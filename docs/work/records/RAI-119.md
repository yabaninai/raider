## Resulting behavior

Load flakes in the PTY/plan family were eliminated using determinism patterns from precedents
(71d0aa3 quiescence drain; 91a6575 retry with a fresh render). Assertions were NOT
weakened, timeouts were not extended as a “cure,” and product code was not changed:

1. **Driver-infrastructure fix (both PTY specs, reproduced red att1):**
   `drive()` created the evidence directory only in `persist()` — AFTER the session body.
   The first PTY test using a fresh `RAI105_PTY_EVIDENCE_DIR`/`RAI113_PTY_EVIDENCE_DIR`
   spawned a child whose report writes silently failed (`.ignore`):
   the phase oracle was blind, and ALL `waitForReport` correctly timed out despite FULLY
   correct child behavior (exit 0, badges render). The default path
   (tmp-dir) had no bug — so isolated runs passed while acceptance
   runs with the env var failed. Fix: `Files.createDirectories` BEFORE starting the child.

2. **PlanPanelSpec «:reject cancels the LIVE plan»** (wave-4 flake 1/4,
   LIN-14 signature: ready2/approved2=false, labels List("plan","plan") without
   "plan-exec"):
   - drain (71d0aa3-class): after printing the :reject result, the test waits for
     TYPED settlement of the cancelled work `session.awaitPlan(planJob)`
     (Left = typed cancellation; Right is impossible and forbidden by assertion) —
     the cancellation pipeline is drained BEFORE the replacement plan starts, so the two daemon watchers
     can no longer interleave writes to the shared outcomeRef around the second
     `track`;
   - retry with a fresh render (91a6575 pattern): on a Ready phase miss,
     force `panel.refresh` (a fresh re-derive) and wait again;
     the assertion still requires Phase.Ready.

3. **TabShellUnreadPtySpec**: added `waitQuiet` (byte-stable quiescence,
   precedent 71d0aa3):
   - p2u03: drain after the settled report BEFORE waiting for the badge (the badge marker
     is nondeterministic, while the pump renders a burst) + drain before `:quit` (class
     “1 torn row” class from the RAI-113 timeline: the `:quit` echo gets appended to a bar row);
     new manifest fields `burstDrained`/`drained` + assertions;
   - p2u01: REPRODUCED marker miss (see PTYD-02 round 1 run9) —
     drain before waiting for `(2 unread)` + retry with a fresh `:tabs` render
     (91a6575 verbatim); new field `drained` + assertion.

4. **MainScrollbackPtySpec**: waitQuiet-timing failures were NOT reproduced (8 complete
   load runs, load 40–122, all passed including the red reproduction att1) —
   semantics were NOT changed for this card. The only change was driver infrastructure (item 1).

## Limitations / blockers

- **Wave-4 classes NOT reproduced in this lane** (honest status):
  PlanPanelSpec labels/ready2 (18 attempts under load 40–164) and
  MainScrollbackPtySpec waitQuiet (8 attempts) — the PlanPanelSpec fixes were applied
  BASED ON PRECEDENTS as preventive determinization of a real harness race:
  the plan-work watcher #1 and replacement-plan watcher write typed outcomes
  for DIFFERENT jobs into ONE shared `outcomeRef` in arbitrary order; a write (h1,
  Left) arriving after (h2, Right) permanently wedges the snapshot in Planning
  (the collect filter by id discards the unrelated outcome). This cannot be fully
  eliminated on the test side (`outcomeRef` is private, with no observable watcher
  completion signal on the public surface) — drain narrows the window, refresh-retry fixes
  the stale case. If the flake recurs, a candidate contract change would be:
  per-job scoping of `outcomeRef` in PlanPanel (product code, outside this card).
- The wave-4 signature (`approved2=false` + NO `plan-exec` in labels) is not fully
  explained by the wedge race (which only wedges the snapshot): the simultaneous
  absence of `plan-exec` also points to a second mechanism (`approve2` did not reach
  `startExecution` — e.g. job2 hung or failed under the storm). It could not be
  reproduced; drain-cancelled-settlement adds the missing synchronization for
  this path as well. This observation was reported to the coordinator in case it recurs.
- PlanPanelSpec has no per-test timeout — `awaitPlan` drain in the test is
  guaranteed by ZIO semantics for settlement of the cancelled work (the promise
  is published in `settle()`), so it cannot hang; still recording this for
  review.
- The load harness approximates an 8-lane storm (4 clones of baseline 8d07036 outside
  the repository + CPU burners, load up to 164); it is not an exact replica
  (neighboring lane worktrees were not touched). All load numbers are honestly recorded
  in the logs.
- Evidence directories (artifacts/rai-119/**) are outside git — for the coordinator at merge:
  gate manifest hashes are in the table above; PTY summaries/transcripts were saved
  in the worktree before merge.
- Full `sbt --batch test` was run once (×1 as specified by the card), under residual
  load (load 44–93); gate runs were on a quiet machine (storm stopped before
  the gates, which is more honest for official evidence).
