## Resulting behavior

Lineage wire schemaVersion 2 (ADR-032, owner-authorized 2026-10-13), additive
over the FROZEN 13-payload ADR-024 seam (which is NOT modified):

- **Phase payloads (wire-native phases).** `phase_started {type, name,
  recovery, note?}` / `phase_finished {type, name}` decode on the v2 wire;
  the reducer creates a `SessionNode.Phase` at enter (parent: innermost open
  phase, else the round it opened inside, else the job base — degenerates to
  the exact v1 shape when no phase payload occurs) and closes the innermost
  open phase with that name at exit (LIFO per job). A phase still open at the
  job's `Terminal` is legal — the node stands.
- **Multi-job correlation.** Optional envelope field `invocationId` (emitted
  last, omitted when absent). Optional on v1 envelopes and on v2 envelopes of
  the root job; REQUIRED on v2 envelopes of non-root jobs (typed
  `ReduceError.MissingCorrelation`). A `schemaVersion: 1` envelope carrying
  `invocationId` is refused typed (`LineageWireError.InvocationIdOnV1`) —
  never silently ignored.
- **Cross-run provenance record.** `run_provenance {type, parentRunId?,
  artifacts:[{kind, path}]}` — at most one per stream (second →
  `ReduceError.DuplicateProvenance`); returned as
  `LineageReduction(graph, provenance)` from the new versioned entries
  `reduceWire`/`reducePartialWire`. `parentRunId` absent = root run, never
  guessed. The `SessionGraph`/`SessionNode` model is NOT modified.
- **Versioning policy (pinned in ADR-032 §2).** Allowed revisions are exactly
  {1, 2} at the versioned entries (`reduce`/`reducePartial` stay strictly 1
  and are behaviorally unchanged); any other version → typed
  `SchemaVersionUnsupported`, never guessed. v1 documents decode UNCHANGED
  bit-for-bit: the payload union routes frozen type names to the frozen
  `EventCodecs` and a v1 envelope re-encodes to the frozen bytes (asserted
  for all 13 payload cases). The frozen `LineageEventReader`, `LineageError`,
  and their pinned v2-rejection behavior are untouched; the versioned
  `LineageWireReader` is a parallel reader with its own error enum
  (`LineageWireError`).
- **GraphHash canonicalization (DECIDED: excluded by contract, ADR-032 §3).**
  New v2 metadata (phase recovery, `invocationId`, provenance) does NOT enter
  the canonical form; `GraphHash` is byte-for-byte unchanged, no hash-version
  bump, v1 hashes remain comparable. Justification: GraphHash identifies
  call-graph shape (ADR-027 §2 replay success); artifact pointers are
  environment-relative (hashing them would make replay hashes
  machine-dependent); zero migration for comparators and frozen v1 pins; the
  model gains no fields, so canonical-form injectivity is preserved. Pinned
  by test: a wire-reduced v2 graph hashes exactly like the hand-built
  equivalent v1 graph, and two reductions differing ONLY in provenance share
  one hash.
- **lineage-data schema v2 (ADR-032 §4).** `contracts/lineage/
  lineage-data.schema.json`: `schemaVersion` now `enum [1, 2]`; optional
  top-level `provenance` (`parentRunId` string|null, `artifacts` required),
  forbidden on v1 documents by a draft-07 `if/then`; optional
  `phaseData.recovery` (closed enum) and `delegationData.invocationId` —
  version coupling of the data-entry fields is validator-checked (draft-07
  cannot reference the document version from data entries): the DSL codec
  refuses a v1 document carrying any v2 field with typed
  `LineageDataError.V2FieldOnV1`. v1 golden fixtures are untouched and remain
  valid (verified structurally; goldens byte-identical per git).
- **DSL codec v2.** `LineageDataDocument.provenance`,
  `PhaseData.recovery`, `DelegationData.invocationId` — optional, omitted on
  encode when absent, so v1 documents encode byte-identically to the frozen
  revision (asserted). `LineageDataFile.read` accepts versions {1, 2};
  versions ≥ 3 stay refused typed.

types and the hash-policy decision, so neither half is independently

## Limitations / blockers

- This card defines the v2 contract and its codec/reducer/validator support;
  it does NOT implement multi-job export (RAI-144), the unified projection
  (RAI-145), the independent acceptance corpus (RAI-146), or the user-guide
  update (RAI-147).
- `contracts/lineage/README.md` prose still describes schemaVersion 1 as the
  only revision — README is outside this card's allowed paths; the update
  belongs to RAI-146 (documented in ADR-032 §4). Until then, ADR-032 is the
  authoritative contract prose for v2.
- `phaseData.recovery` / `delegationData.invocationId` version coupling is
  validator-checked (draft-07 limitation), not schema-enforced — same
  split as all other cross-reference invariants in this contract.
- Phase recovery metadata is stream-carried + lineage-data-resident; it is
  deliberately NOT a `SessionNode.Phase` field (ADR-032 §5 model boundary —
  out-of-path constructors in `modules/cli/**` and hash comparability stay
  untouched). If a future live-rerun card needs recovery in the graph model,
  that is a separate schema decision.
- Evidence binds to fingerprint `d5ee961e86ce9f18bef30cd2395850e0f5d7f6175a5afb063de66c5fd13043b3`
  (both manifests). This record was written after the gate runs; per the
  evidence policy, code/spec/build/fixtures/gate policy are inside the
  fingerprint and the record itself is operational.
