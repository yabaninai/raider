# RAI-218: bootstrap.sh CA resolution on stock macOS

Status: done. Date: 2026-10-26 (UTC). Baseline commit/source: `b90a191` (branch `lane/rai-218`).

## Resulting behavior

`sh scripts/bootstrap.sh` now resolves a TLS CA bundle automatically before the
pinned-coordinate downloads, so a stock macOS python.org distribution needs no
manual `SSL_CERT_FILE` (observed as a manual workaround on the RAI-203/RAI-207
lanes, 2026-10-25; board follow-up #5). Resolution order:

1. A caller-provided `SSL_CERT_FILE` is honored untouched (no probe, no override).
2. certifi, when importable by the same `python3` that will download and its
   bundle file exists.
3. The macOS system bundle `/etc/ssl/cert.pem`, when it exists and is readable
   (candidate path overridable via `RAIDER_BOOTSTRAP_SYSTEM_CA` for tests and
   sandboxes).
4. The interpreter's default OpenSSL verify paths, when already usable — the
   resolver emits the token `none` and bootstrap.sh sets no override (protects
   environments whose defaults already work, e.g. typical Linux).
5. Otherwise: a typed failure (`bootstrap: error: no TLS CA bundle resolved for
   pinned-coordinate downloads (RAI-218)`) listing each unavailable source plus
   a remediation hint (Install Certificates.command / `pip install certifi` /
   explicit `SSL_CERT_FILE`), exit 1, before any download starts — never a
   traceback.

The new resolver is `scripts/bootstrap_ca.py` (stdout: exactly one line, the
bundle path or `none`; stderr: diagnostics; exit 0/1). Pinned Maven
coordinates, versions, and the frozen `experiments/repl-spike/fetch_toolchain.py`
are unchanged. The fix is Python/bash glue per the language policy; no product
code is involved.

## Limitations / blockers

- The adversarial case was simulated on the target stock-macOS python.org
  interpreter by import-shadowing certifi and overriding the system-bundle
  candidate path (`RAIDER_BOOTSTRAP_SYSTEM_CA`); making `/etc/ssl/cert.pem`
  genuinely unreadable would require root. Both simulation levers exercise the
  same code branches as the real conditions (ImportError path; unreadable-file
  path). A real cert-less python.org install was not available on this host.
- The fallback demonstration downloads through `/etc/ssl/cert.pem` were
  performed against repo1.maven.org (ordinary pinned toolchain fetch, the
  bootstrap's purpose; no paid calls).
- Two `sbt-test` contention timeouts (900 s policy cap, tests progressing at
  kill) are recorded verbatim above; the full suite passed on the same tip
  under idle host conditions. The 900 s cap is protected gate policy and was
  not touched; the multi-lane host-contention issue remains a coordinator-level
  infra item (see board 2026-10-25 precedent and the 2026-10-26 timeout raise).
- Lane-level only: `main` integration gates remain the coordinator's
  obligation; no push/merge/board edit was performed by this lane.
