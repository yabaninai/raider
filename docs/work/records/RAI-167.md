## Resulting behavior

Added bounded workflow orchestration for commit → PR-create → PR-status → merge. The trusted `IntegrationRules` input is authoritative for target branch, required checks, required review, policy digest, and granted integration capabilities. Required check evidence must pass for the exact candidate and policy; required review evidence must be acceptable and bound to that candidate/task/plan/policy. Mutating verbs read the forge state immediately before dispatch and compare repository, target branch/ref, candidate identity, policy, and capabilities. Divergence produces typed refusal evidence; mutations are called once. An unknown/uncertain mutation outcome is followed only by read-only reconcile. Each stage, including refusal, carries a typed integration record containing the candidate identity; successful records link the check/review evidence digests.

Defect fix (independent RAI-169 finding): `IntegrationWorkflow.scala` mapped both `ForgeOutcome.TimedOutUncertain` and `ForgeOutcome.Unknown` to `Refusal.UnknownOutcome`, which serialized both as `IntegrationOutcome.Unknown`. The timeout path now retains `IntegrationOutcome.TimedOutUncertain`; unknown-result and reconcile-required paths retain `IntegrationOutcome.Unknown`. Both paths still perform read-only reconciliation and issue no retry. The typed evidence vocabulary already contains both states, so neither the RAI-174 carrier schema nor schema v1 required a change. This preserves the RAI-166 meaning: a timed-out effect may be observed and settle `AlreadyApplied`; `UnknownResult` means no effect and reconciles to `Rejected`.
