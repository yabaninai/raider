Status: done; independent review pending. Date: 2026-10-18. Baseline commit/source: lane HEAD `2d2edbf1c22d9f33c766e0e8410315aadad65672` before review-fix edits.

## Resulting behavior

Headless artifact publication now writes immutable generation-specific data/source files and atomically replaces `lineage-commit.json` last. The pointer names both files and pins SHA-256 digests. `LineageSnapshot.read` validates the manifest, both files, both hashes, and the lineage-data document; it never falls back to fixed-name files. ReplayCli and the product replay command use this reader. Existing fixed-name artifacts remain available for compatibility, but are not the snapshot authority. The contract authorizes the local pinned dotc 3.9.0 validation on the source resolved from a committed snapshot; this compiles locally without provider calls and does not alter session exit semantics.

Frozen lineage schema and GraphHash normalization were not changed.

## Review finding closure

The concurrent-reader fixture now seeds a valid committed data/source snapshot before releasing its reader/writer start latch. During replacement, every read must return a valid committed pair: a typed `Missing` result now fails the observation instead of being ignored. A separate pre-publication test asserts the exact typed `LineageSnapshot.Error.Missing` result when no initial commit exists. No production code or other assertions were changed. The targeted 28-test suite passed three consecutive runs (84 test executions total) after the final formatting pass; each protocol run included the new missing-before-first-commit test. The first quality execution identified only a scalafmt issue in this test file; it was corrected with the scoped formatter, and the three suite runs were repeated afterward.
