## Resulting behavior

The forbidden-apis scanner no longer descends into build-output directories: the source walk (`rglob("*.scala")` → new `_scala_files()`) prunes every directory named `target` at ANY depth (sbt convention `modules/*/target/...`, including `project/target`), closing review finding F-223-1 — the scanner used to read stale generated artifacts under `target/` and could report findings that depend on build state. This matches the quality runner's segment-based fingerprint excludes (`"target"` in `scripts/quality-policy/registry.json`). The walk is read-only and tolerates vanishing entries: a directory that disappears mid-walk is captured via `os.walk(onerror=...)` and surfaced as a `[forbidden-apis] WARN walk:` line on stderr, never a crash; an unreadable file is a WARN as before.

Detection semantics are frozen (RAI-223 non-goals honored): all six rules and regexes, the 15-char placeholder threshold, the location allowlist (`raider.cli.Main`, `raider.cli.workflow.WorkflowRun`), exit codes (0/1/2), `_blank_in_place` true-line attribution, and the missing-`modules/` honest failure (`FAIL: no scala sources found under modules/`, exit 2 — now also demonstrated for an empty `modules/`) are byte-for-byte unchanged. `strip_comments`, `scan_text`, `scan_file`, `RULES`, and `ALLOWLIST` were not touched.
