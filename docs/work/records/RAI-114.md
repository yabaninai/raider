## Resulting behavior

Детерминированный scripted scenario-corpus плана-режима (RAI-107/ADR-028)
в raiderRuntime TEST scope — сценарии КАК ДАННЫЕ + один спека-раннер,
пригодные будущему eval-профилю (профиль в registry НЕ регистрируется —
non-goal карточки, регистрирует coordinator):

- `PlanScenarioCorpus` (данные): 6 сценариев, 1:1 на behaviors ADR-028 §4:
  - `s1-ro-work` — ReadOnly-инструмент реально исполняется в plan-фазе,
    план принят, артефакт записан;
  - `s2-mutating-denied` — попытки Mutating/Idempotent → 2×typed
    policy-denial (RA-TOOLDENY/tool_denied), не исполнены (counts 0), loop
    жив, ReadOnly исполнился;
  - `s3-malformed-repaired` — malformed финал → structured
    plan_rejected/RA-PLAN-REJECTED repair-фидбек → восстановленный план
    принят и персистится;
  - `s4-malformed-exhausted` — malformed после repair-лимита (maxRepair=1)
    → typed `PlanPhaseError.PlanRejected` (code RA-PLAN-REJECTED,
    attempts=2), каталог артефактов ПУСТ;
  - `s5-approve-exactly-once` — approve → РОВНО одна `plan-exec`-джоба с
    планом в leading context; второй approve → typed `AlreadyApproved`;
  - `s6-cancel-replan` — cancel живой plan-джобы → bounded cleanup
    (reservedActive=0, uncertainTotal=250 сохранён, slots 1/1, состояние
    Cancelled, approve-after-cancel → typed Cancelled detail, после cancel
    0 новых модельных вызовов), повторный план зелёный, lineage
    List("plan","plan") без ghost-джоб.
- Каждый `Scenario` — чистые данные: tools (по frozen `RecoveryClass`),
  scripted plan-calls (ToolRound/FinalText), maxRepairAttempts, maxRounds,
  estimateMicros, protocol (PlanPhase / Approve / CancelThenReplan) и
  PINNED typed verdict (точные значения: counts, codes, ledger micros,
  labels — не «не упало»).
- `exec(scenario)` — прогон сценария на свежем стеке (уникальный TempDir
  `raider-plan-corpus-<id>-*`, свой Admission/JobManager/ScriptedBackend/
  AgentLoop/PlanSession) — изоляция без общих записей; `verify(scenario,
  observed)` сверяет pinned verdict c фактом.
- Corpus сериализуем как данные для будущего eval-профиля: `jsonlLines` /
  `parseJsonl` (строгий decode: unknown RecoveryClass/конструкторы — typed
  decode failure) + `sha256Hex`; детерминизм без wall clock/RNG.
- Cancel-сценарий: GatedBackend паркует dispatch ПОСЛЕ записи запроса
  (дисциплина RAI-107 bounded-cancel acceptance); два ИДЕНТИЧНЫХ script-a
  в данных — любой исход отмены-race оставляет повторный план валидным,
  sequence не исчерпывается (flake-free by construction).
- PLAN-спеки RAI-107 (AgentLoopPlanModeSpec и др.) не тронуты и не
  ослаблены; protected corpus contracts/eval/** и gate registry — не
  тронуты.
