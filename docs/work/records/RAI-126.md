## Resulting behavior

PTY probes no longer overwrite the caller's `COURSIER_CACHE`. In all three
subprocess-environment construction sites, the hard assignment
`env["COURSIER_CACHE"] = <constant>` was replaced with
`env.setdefault("COURSIER_CACHE", <same constant>)`:

- Without `COURSIER_CACHE` set, setdefault inserts the previous default, so
  behavior remains bit-for-bit unchanged (confirmed by CC-01 runs).
- With `COURSIER_CACHE` set, the probe uses the caller's cache and does not
  overwrite it (observed directly: an empty tmp cache is populated with run
  artifacts, CC-02).
- Passing the cache again is idempotent (CC-02b: same cache, warm reuse, 180
  files before and after, all_pass).

Default constants were not changed (`tabs_pty_probe.py:63`,
`renderer_pty_probe.py:71`). Oracles, patterns, thresholds, Makefile default, and
gate policy were untouched.
