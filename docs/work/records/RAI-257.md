## Resulting behavior

Delegated children now carry the delegating parent's CONFIGURED model on their
provider requests (audit follow-up `docs/reviews/2026-11-01-readiness.md`,
"P1: native delegated children use a test model identifier"):

- `DelegationToolset` no longer hardcodes `scripted:<agent>` as the child
  model. A new `defaultChildModel` parameter (default: the `ScriptedModel`
  sentinel `"scripted"`) supplies the parent's configured model; the sentinel
  preserves the historical `scripted:<agent>` child label byte-compatibly for
  the scripted backend (same rule as the REPL facade
  `FacadeOps.textAttemptMessages`).
- `DelegateArgs` gained an optional `model` field: an explicit per-child
  override in the delegate tool arguments wins over the parent default. Absent
  `model` decodes as `None`, so the historical args shape (and the whole
  scripted corpus) is unchanged.
- `CoderDelegationWiring.augment` takes the run's configured model (new
  required `model` parameter) and passes it as `defaultChildModel`;
  `HeadlessRunner` passes `args.model` — the same id the parent loop
  dispatches under. The REPL facade was already correct and is unchanged.
- The `delegate` tool description documents the optional override.

Red-first evidence: against the unfixed tree the new product-entry stand
spec recorded the child's live-wire request as `model = "scripted:scout"`
(the stand refuses any non-configured id with HTTP 400), the child settled
Failed, and both propagation assertions failed. After the fix the same stand
records `stand-model` for both campaign and child, and the child reports
`Succeeded`.
