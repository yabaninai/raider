## Resulting behavior

- Frozen v1 metadata declares `advisory: Boolean` on each trusted exported-workflow check. Absence decodes to `false`; thresholds are not defined. The field is emitted in the generated `trustedChecks` tuples and provenance manifest, and is included in the STS/spec digest.
- `ci-runtime.md` and `contracts/ci/trusted-check-policy.schema.json` define workflow-bound policy, the canonical policy digest, verdict labels, exits, and fail-safe unknown/missing/duplicate/skipped evidence behavior.
- `CiReport.classify` uses actual `CheckResult` evidence, rejects absent/mismatched metadata as blocking, classifies only declared advisory failures as advisory, and maps advisory to exit 0 and blocking to exit 10. The generic HeadlessRunner uses blocking declarations for its own checks and records policy digest with runner-owned evidence in `run.json` and `result.json`.
- Exported metadata remains fail-closed: the generated workflow still treats check failures as blocking. The current exported-workflow launcher does not yet pass check evidence and its trusted policy into the RAI-186 report/exit path, so advisory exported-check failures are not yet end-to-end behavior.
