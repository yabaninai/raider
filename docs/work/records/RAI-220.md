## Resulting behavior

The RAI-214 seam is wired into the portable launch route. `raider.cli.portable.PortableRun` now performs a zero-dispatch document gate as the FIRST step of the flow (`loadDocumentGate`):

- `PortableBundleVerifier.detectForDocument(args.doc)` decides whether the `--doc` path carries the export-bundle contract (a sibling `X-manifest.json`). A plain document keeps the existing un-manifested read — byte-for-byte the pre-RAI-220 behavior.
- A detected bundle is `verifyBundle`-ed and the flow consumes ONLY the returned `PortableVerifiedBundle.documentBytes` — the launcher never re-reads a verified document from disk, so validation, digest splicing (`docDigest`), lowering and the root output all use exactly the bytes the manifest pins (the verify→lower TOCTOU window stays closed). A `Diagnostics` event `bundle verified: <manifestFileName> (document …, input example …; on-disk bytes match the manifest pins)` records the engagement.
- Any verifier refusal (tampered digest, missing manifested file, unmanifested extra entry, non-regular entry, oversized/invalid manifest, bundle-dir missing/unreadable/too-large, declared-names collisions) maps via the existing `PortableBundleRefusal.toRaiderError` onto `RaiderError.InputValidation("CWF-R1: …")` — the run fails typed BEFORE validation, credential resolution, launch-layer assembly, lowering or dispatch (no `effective launch limits` diagnostics, no dispatch, truthful `Failed` run.json without a `taskVerdict`).

No public contract/schema changes: the RAI-214 API is consumed read-only; the exported-bundle contract (`ExportWorkflowPortableSpec` "runs green through native lowering") now verifies in-run and stays green unchanged.
