## Resulting behavior

Diff seam per the 2026-10-24 coordinator decision: `ChatLayout` (raider-ui) accepts an additive parsed-hunk model — `ChatLayout.DiffLine` (Context/Add/Remove) and `ChatLayout.DiffHunk(header, lines)` — with a new optional `Frame.diffHunks` parameter (default empty) rendered as styled rows (cyan `@@` header, red `-`, green `+`, cell-width clipped). Parsing stays caller-side: `ChatLayoutSink` in the REPL chat path extracts complete ```diff fences from the streamed assistant text, parses them with the existing `raider.tools.files.edit.UnifiedDiff.parse`, and maps the resulting `UnifiedDiff.Hunk`/`HunkLine` values into the renderer model. No module-graph change (`raider-repl` already depends on both `raider-tools` and `raider-ui`); no second diff parser; no tools changes. Streaming is safe by construction: an unterminated fence matches nothing yet, a typed parse error drops only that fence (the raw text still renders inline), hunks reset per assistant turn and are recomputed statelessly from the accumulated text per delta, and CR/CRLF is normalized before parsing so carriage returns never reach rendered rows. The message-inline fenced-diff coloring from the renderer slice remains; parsed hunks render additively below the conversation, which is the seam RAI-192 per-hunk review will build on.

The scripted REPL fixture answer is now injectable via the `raider.chat.testAnswer` system property (default unchanged: `[scripted-fixture] mock answer`); only the test-scope `ChatLayoutPtyApp` sets it, under the `RAI191_COMBINED_FIXTURE=1` environment switch.

The RAI-188 chat shell PTY suite gained one end-to-end case: a single chat turn rendering a markdown heading, syntax-highlighted Scala, and a parsed unified diff through the real product entry (`Main --chat` + `ChatLayoutPtyApp`), asserting the visible text, the Scala keyword ANSI (`ESC[34mval`), the diff removal/addition ANSI (`ESC[31m-old`, `ESC[32m+new`), a clean exit, and no exceptions. A dedicated REPL unit fixture (`ChatLayoutSinkDiffSeamSpec`) proves the parse→hunks→render chain: fences parsed by `UnifiedDiff.parse` map to `DiffHunk`s whose headers/lines equal the direct parser output, render with expected styling, and malformed/incomplete/CRLF input cannot corrupt the frame.
