## Resulting behavior

When the portable output target resolves to an agent step instead of the root trusted check, the portable launcher now records typed verdict evidence and never claims `taskVerdict` authority from agent output:

- New pure resolver `raider.dsl.portable.PortableVerdictEvidence` classifies the evidence origin of a validated document by mirroring the frozen RAI-198 lowerer target precedence (bindings first entry, else `verdict.from`; `stepIdFromPointer` = first segment after `#/steps/`). Four codes: `trusted-check` (direct check, sequence-last-child chain, or conditional whose BOTH branches are checks — value discipline unchanged), `agent-step` (agents, all-agent joins/conditionals, map templates — permissive, never claims/vetoes), `mixed` (join mixing agent and check, differing conditional branches, repair/checkpoint kinds, unknown step id, cycle — permissive), and `contradictory` (any non-trusted origin whose recorded output asserts a top-level string `status`; recorded verbatim, never claims).
- `PortableRun` resolves the origin after the output target and before dispatch (zero extra model calls), records structural evidence in `run.json` as `verdictEvidence` `{origin, target, steps, assertedStatus?}` even for failed runs, refines it with the observed output before projection, and prints a `verdict evidence origin: <code|none>` diagnostics line to events. Projection stays origin-aware: `trusted-check` + passed claims the verdict (unchanged, pinned), `trusted-check` + failing keeps RA-OUT exit 10 with the check status verbatim (unchanged, pinned), `agent-step`/`mixed`/`contradictory` are permissive (exit reflects run success only, no claim, no veto, RA-OUT-safe mapping preserved).
- Corpus finding pinned in tests: the frozen validator makes map-over-check documents unexpressible (map-template pointers are restricted to `#/item`/`#/index`, and `#/item` is agent-template-only), so the resolver's map-over-check `mixed` branch is defensive totality for documents that bypass validation.
- Root trusted-check verdict behavior, contracts, frozen corpus, lowerer, validator, and gate policy are unchanged (additive `run.json` field only; parity assertions are substring-based and stay green).
