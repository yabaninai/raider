## Resulting behavior

`scripts/repro-jar` no longer destroys the raw assembly it keeps (RAI-252 review P3-4). The packaging flow is consolidated into one implementation, `package(raw, out, raw_keep, main_class)`, with all path derivation for an invocation in one place in `main()`. In the default in-tree flow (sbt build + default binding-path output, where the raw assembly path IS the output path) the raw-keep copy at `raider-cli-raw.jar` is now captured from the true raw bytes BEFORE the canonical jar is written over the binding path, and published only AFTER the canonical jar is published; previously the copy was taken after the overwrite, so the kept file duplicated the canonical jar and the raw bytes were lost. New structural assertion: every staged output is read back and rejected (exit 5) before publication unless it has no duplicate entry paths and exactly the analyzed entry count. Staging files (`.repro-jar-tmp-*`, `.repro-jar-raw-tmp-*`) are created with `tempfile.mkstemp` in the target directory (unique per invocation, safe under concurrent invocations) and removed on every failure or cancellation path, so no partial raw copy or partial output is ever left behind. The raw-keep rule is unchanged and now single-sourced: only the default in-tree flow keeps the raw assembly; `--out`/`--from-assembly` variants do not. The canonical zip policy is byte-for-byte the RAI-240 policy; a cross-version A/B on the same raw input produces identical bytes from the base and fixed scripts. An embedded `--self-test` (12 hermetic cases, no sbt/JVM/network, temp fixtures only) covers the rule, the P3-4 defect guard, diagnoses, the structural assertion, unicode paths, stability/idempotence, and concurrency.

The card's contract — canonical output byte-identical across consecutive clean invocations — is satisfied independently of the raw hash.

Re-pinning is a coordinator action under a separate card per the RAI-253 procedure; no pin was touched here.
3. **Base-script A/B via an extracted copy.** The lane worktree's `scripts/repro-jar` was already fixed, so the base version for the A/B came from `git show 964a388:scripts/repro-jar` (sha `cd46602e…`), written to session temp and executed from there.
4. **Coverage of failure windows while staging.** The raw-keep copy window is now covered by an injected-failure test (RF-1 self-test case 13: partial write then `OSError(ENOSPC)` → exit 6, staging file removed). Remaining uncovered windows are exotic: a failure of `mkstemp` itself (no file exists yet, so nothing can leak) and a stdout `EPIPE` between `mkstemp` and the try block (no bytes of the staged file written yet); neither leaves staged file content behind.
5. **Log interleaving, cosmetic.** In combined logs, `ERROR:` lines (stderr, unbuffered) can appear before the buffered stdout context lines ("raw assembly:", "raw sha256:"); exit codes and diagnoses are unaffected.
6. **Concurrency evidence scope.** Real-process concurrency is evidenced with two parallel CLI invocations in separate scratch roots (both exit 0, identical bytes, no leftovers); the in-process threading case in `--self-test` caught and now guards a real staging-name collision (fixed via `mkstemp`).
7. **Record/manifest ordering.** This record was written before the gate runs; the gate rows above were filled in from the executed manifests afterwards — a record-only, operational edit under the exclusion policy; no product-input file changed after the gate runs.

## Review fix RF-1 (blocking item from the RAI-265 review, applied)

**Finding (blocking).** `stage_raw_keep` called `shutil.copyfile(raw, staged)` without a handler. An I/O error mid-copy (ENOSPC/EIO) raised before `package()` held the `staged` path, leaving a partial `.repro-jar-raw-tmp-*` file on disk — contradicting the module docstring and this record ("a failure at any stage leaves no partial raw copy behind").

**Remedy (reviewer's option (a)).** The copy is wrapped in `try/except OSError`: on failure the staging file is removed via `discard_staged(staged)` and the script exits with a new documented code **6 (I/O failure while staging a copy)**, following the existing scheme (3 missing, 4 malformed, 5 structural, sbt pass-through unchanged). Exit code 6 is documented in the module docstring and in `stage_raw_keep`'s own docstring; the handler carries an RF-1 comment stating the leak it prevents.

**Docs disclosure.** `scripts/README.md` (outside this card's allowed paths) documents the repro-jar exit-code table (0/3/4/5/other) and has no row for 6; the in-repo README will need a one-row addition under a docs-allowed change. No other doc claims were left stale: the module docstring, the function docstring, and this record now state the same behavior the code implements.

**Regression test (reviewer's optional item, applied).** Self-test case 13 `mid-copy-io-failure-exit6-no-partial-raw-copy`: monkeypatches `shutil.copyfile` to write partial bytes and then raise `OSError(ENOSPC)`, calls `stage_raw_keep` directly, asserts exit 6, asserts the OS error text appears in the diagnosis, asserts the raw-keep target was never published, and asserts zero `.repro-jar-*` leftovers in the target directory. Battery result on the RF-1 revision: **13 cases passed, exit 0** (`after/self-test-rf1.log`); script sha256 `5cc75c2424c026124f85b0924c1130c56c541a89e4d03784e16eafb46ef778fd`.
