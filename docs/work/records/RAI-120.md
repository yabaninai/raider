## Resulting behavior

`IsolatedRerun.requireIsolatedTarget` (LIN6-02 product-path guard, review finding LIN-15) no longer compares target and original syntactically. Before executing a mutating replay, a canonical directory identity comparison was added using `Files.isSameFile` (device/inode; new private helper `isCanonicalAlias`):

- a syntactic alias of the original (`original.resolve("..").resolve(original.getFileName)`) — typed rejection `RerunError.MutatingUnisolated` BEFORE execution (previously: `Right(())`, replay would have run IN-PLACE);
- a symlink alias of the original — the same typed rejection;
- a nonexistent target — `NoSuchFileException` → “not the original” → byte check returns an accurate typed rejection `MutatingUnisolated` (not a silent pass);
- a nondeterministic IO failure `isSameFile` — fail-closed (rejection): the guard does not risk an in-place mutating replay when the answer is unknown;
- a legitimate isolated copy (`WorkspaceIsolation.isolate` — a different directory with identical bytes) passes the guard as before; ReadOnly-writes are not isolated (`Right(())` without checks) as before.

Semantics `WorkspaceIsolation`/`isolate` did not change; no new typed cases were introduced (reused `MutatingUnisolated`); `RerunError`-set was not expanded.
