## Resulting behavior

`IsolatedRerun.requireIsolatedTarget` (LIN6-02 product-path guard, review finding LIN-15) больше не сравнивает target с original синтаксически. До исполнения mutating replay добавлено каноническое сравнение идентичности каталога через `Files.isSameFile` (device/inode; новый приватный хелпер `isCanonicalAlias`):

- синтаксический алиас оригинала (`original.resolve("..").resolve(original.getFileName)`) — typed отказ `RerunError.MutatingUnisolated` ДО исполнения (раньше: `Right(())`, replay ушёл бы IN-PLACE);
- symlink-алиас оригинала — тот же typed отказ;
- несуществующий target — `NoSuchFileException` → «не оригинал» → байт-проверка даёт честный typed отказ `MutatingUnisolated` (не молчаливый pass);
- недетерминируемый IO-сбой `isSameFile` — fail-closed (отказ): guard не рискует in-place mutating replay при неизвестном ответе;
- легитимная изолированная копия (`WorkspaceIsolation.isolate` — другой каталог с равными байтами) проходит guard как раньше; ReadOnly-записи не изолируются (`Right(())` без проверок) как раньше.

Семантика `WorkspaceIsolation`/`isolate` не менялась; новые typed-кейсы не вводились (переиспользован `MutatingUnisolated`); `RerunError`-набор не расширялся.
