## Review fix round: explicit frozen TestClock proof

Baseline for this round: `bed831bc287649087348f5b6e0db13755687e82c` on `lane/rai-180`.

`ClockPollSpec` now establishes `Instant.EPOCH` with `TestClock.setTime` in all three cases. The pinned ZIO 2.1.26 TestClock API has no `freeze` method; its service is intrinsically frozen and advances only through explicit `adjust`/`setTime` calls. Each case reads `Clock.currentTime(NANOSECONDS)` immediately before and after its poll and asserts equality, alongside the existing wall-clock bounds and timeout outcome. No production code changed.

The optional unwrapped-sleep negative control was not added. Under this frozen TestClock, an unwrapped `ZIO.sleep` would suspend; a timeout driven by the same virtual clock would suspend as well. A bounded negative-control assertion would therefore require additional live-clock supervision, and was not necessary for the requested proof.
