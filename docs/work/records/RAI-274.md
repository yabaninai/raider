## Resulting behavior

Two results, both on top of the RAI-272 clean baseline:

1. **SuiteWorkdir symlink safety (RAI-272 review advisory A1).**
   `modules/cli/src/test/scala/raider/cli/testkit/SuiteWorkdir.scala` now
   deletes symlinks themselves, never their targets: `deleteRecursively` tests
   `Files.isDirectory(p, LinkOption.NOFOLLOW_LINKS)` /
   `Files.exists(p, LinkOption.NOFOLLOW_LINKS)` and uses `Files.delete` for
   non-directories, so a directory symlink inside a suite-work dir is removed
   as a link (target untouched), dangling symlinks are removed without
   following, and symlink cycles cannot recurse. Covered by new regression
   spec `SuiteWorkdirSpec` (2 tests: directory-symlink wipe deletes the link,
   not target contents; dangling symlink wipe removes the link). Wipe-on-first
   use semantics unchanged; all migrated suites still pass.

2. **Test/parallelExecution stance re-evaluation: the serial stance stays**
   (`Test / parallelExecution := false` in `build.sbt` `testSettings`,
   unchanged; `Global / concurrentRestrictions += Tags.limit(Tags.Test, 2)`
   unchanged). RAI-272 removed the shared fixed-path hazard, so the pin is now
   defense in depth, not a workaround — and the RAI-266-style probe plus new
   measurements show the flip buys nothing:
   - The stance surface is two mechanisms: `Test / parallelExecution` governs
     suite concurrency only in **in-process** modules; three modules fork
     tests (`Test / fork := true`: raiderCli per RAI-109 at `build.sbt`,
     raiderRepl, raiderReplEngine), and sbt runs suites sequentially inside
     one fork regardless (default `Test / testForkedParallel := false`), so
     flipping is inert there.
   - Marker probe (temporary suites writing epoch-ms markers under
     `target/stance-probe-markers` at the build root; marker state
     `rm -rf` + existence-verified clean before every run; 20 s sibling wait;
     probe A intentionally "fails its wait" when serial, so exit 1 is the
     designed serial signature):
     raiderCore pin → A 1793838357875, B 1793838378034 (+20.02 s, serial, A
     failed wait as designed); raiderCore flip → A 1793838203445,
     B 1793838203444 (−1 ms, genuine overlap, both passed); raiderCli pin →
     A 1793838328373, B 1793838348510 (+20.14 s, serial); raiderCli flip →
     A 1793838107358, B 1793838127488 (+20.01 s, still serial despite the
     applied `set raiderCli/Test/parallelExecution := true`, verified via
     `show`). Probe suites were created for the probe, then removed; never
     committed.
   - Measured full `sbt --batch test` on the same tree (sequential runs, JDK
     21 pin per §1d): serial **595 s** wall (sbt Total 592 s) vs flipped
     `sbt --batch 'set every Test/parallelExecution := true' test` **637 s**
     wall (sbt Total 632 s) — both green, 1824 tests, 0 failed, exit 0;
     flipping adds contention, not throughput, consistent with RAI-266
     (680 s serial vs 700 s parallel).
   - Under the flip, the migrated suite set showed no cross-suite
     interference: the completed flipped run passed 1824/1824 and the
     suite-work audit afterwards found only per-suite directories under
     `modules/cli/target/suite-work/` (5 migrated suites + 2
     SuiteWorkdirSpec dirs), with `modules/cli/target/lineage-compile/` and
     `modules/cli/target/chat-workflow-compile/` not recreated.

`build.sbt` comment in `testSettings` and `docs/parallel-development.md` §1e
updated to the re-evaluated rationale (including the forked-module nuance and
the note that true fork-level concurrency would additionally require
`Test / testForkedParallel := true`, proposed and measured by no card).

## Limitations / blockers

- The flipped-parallel full-suite run was run twice because attempt 1 was
  killed by an **external SIGTERM** (exit 143) at 273 s — not a gate timeout
  and not a test failure (8 module summaries were green, 938 tests, 0 failed
  at kill). Attempt 2 completed green. The kill also left zinc state that
  later produced a dotc `StaleSymbolException` in raiderReplEngine's next
  incremental compile (fast-profile attempt 1 sbt-test red); healed by
  `raiderReplEngine/clean` + recompile (§1c-style infra-marker handling), and
  attempt 3 of the fast profile passed 10/10 on the final sources. This
  chain is disclosed in full; none of these reds were product errors.
- Fast-profile attempt 2 was killed by a local 30-minute tool timeout; the
  orphaned sbt kept one hung forked test JVM (0% CPU; thread dump shows the
  sbt ForkMain and the ZIO scheduler fully parked — consistent with
  test-spawned child processes dying in the killed process group). That run
  produced no manifest and is void; the orphan was killed after capturing
  the thread dump. No hang occurred in any clean (non-killed) run today.
- Probe suites were temporary and never committed; probe logs remain in
  `artifacts/quality/rai274-evidence/` (gitignored, values recorded here —
  RAI-266 discipline).
- Forked-module tests (cli/repl/repl-engine) run one-fork-sequential; this
  card did not propose or measure `Test / testForkedParallel := true` (out of
  card scope, noted in §1e for any future card).
- The `build.sbt` comment cites measured runtimes from this host (18 cores);
  absolute numbers vary with host load, the pin/fork mechanism and the
  serial-vs-flipped ordering do not.
