## Resulting behavior

Existing typed SDLC stages/evidence remain, with deterministic candidate identity hashing and strict v1 artifact evolution handling added. Candidate digest is SHA-256 over the domain tag `raider-sdlc-candidate-v1`, a NUL byte, then each identity field in fixed declaration order as a 4-byte big-endian UTF-8 field-name length/name and a presence byte; present values additionally use a 4-byte big-endian UTF-8 value length/value. This makes absent optional fields distinct from empty strings and is independent of JSON map ordering and run IDs. The evidence artifact decoder now rejects any unknown outer field with `ArtifactDecodeError.UnknownFields`; changes to accepted field shapes/schema versions require a new explicit supported schema rather than silent decoding.

The requested headless projection wiring is not implemented: the frozen v1 `EventPayload` has a closed set of cases and its contract explicitly makes new cases a schema decision. Typed SDLC evidence cannot be emitted into `events.jsonl` as a typed event without changing the frozen event schema. No new case was added and no v1 event shape was altered. `run.json` additive extra fields alone cannot satisfy the requirement that both persisted outputs carry typed records. Contract-change request and minimal reproducer are documented below.

## Limitations / contract-change request

Frozen event contract: `modules/runtime/src/main/scala/raider/runtime/events/events.scala` declares schemaVersion 1 and `EventPayload` as 13 frozen cases; its comment states adding a case is a schema decision, never a silent shape change. `EventsJsonlWriter.append` accepts only `EventEnvelope`. Minimal reproducer:

```scala
import raider.core.sdlc.SdlcEvidence
import raider.runtime.events.EventPayload

val evidence = SdlcEvidence.artifact("candidate-identity", "typed-payload")
val event: EventPayload = evidence // does not compile: String is not an EventPayload case
```

Request: authorize a separately reviewed, versioned event-contract migration (new schema version and consumer compatibility policy) or specify a distinct additive JSONL record union that v1 consumers are required to ignore. Until that contract exists, wiring evidence as a new event case or untyped Diagnostics string would violate the frozen typed-event contract or the typed-evidence requirement. Existing `run.json` additive extras are technically possible but would leave `events.jsonl` incomplete and therefore do not fulfill this card's paired persistence acceptance.

The integrated-candidate evidence/manifests are produced by the final gates; a skip, timeout, missing gate, or scanner error is not a pass. RAI-163 independent review and RAI-169 verification remain separate obligations.
