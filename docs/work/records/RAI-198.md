# RAI-198: work record

Status: partial; the lowerer now emits validated root ceilings as additive launch
metadata. Launch-path intersection/enforcement, RAI-164 repair-stage composition,
exhaustive pointer typing, and independent review acceptance remain incomplete.
Date: 2026-10-24. Baseline commit: `722192c` on `lane/rai-198`; worktree
`wt/rai-198`. The lane merged `main` (`cd6c532`) before implementation.

## Resulting behavior

Round 1 adds a pure Scala preflight API which checks the UTF-8 byte ceiling,
rejects malformed UTF-8/JSON and duplicate object keys, recognizes unknown
major versions, enforces the frozen schema depth/enum bounds, and checks
selected graph/reference/predicate constraints. The Scala test executes all 17
refusal manifest entries and compares all five diagnostic fields exactly; all
10 positive fixture documents pass preflight. No model, tool, registry, or
runtime dependency is called by validation.

Round 2 adds a lowering adapter that resolves agent/check descriptors from a
caller-supplied trusted registry and lowers agent/check leaves and ordered
sequence nodes to the existing lazy `Program`/`Task` composition. It returns a
structural node tree for pre-dispatch inspection. Unsupported step kinds and
unresolved trusted descriptors fail preflight. The structural spec covers one
agent and an agent/check sequence.

Round 3 adds structural lowering for bounded map and join using the existing
`batch`/`all` composition, a structural `isPresent` conditional evaluator,
safe-operation descriptor resolution for repair, and checkpoint descriptor
resolution. Descriptor registries remain caller-owned; the portable document
cannot supply callbacks or authority. All ten positive fixture documents now
lower structurally with trusted scripted descriptors. This does not establish
full runtime acceptance: repair invokes its descriptor once and does not itself
apply RAI-164 stage retry semantics; checkpoint authorization must be supplied
by a descriptor bound to the existing approval path; and declared portable
root limits are not yet intersected into native launch accounting by this
adapter. Cancellation, failure propagation and root budget acceptance for
lowered workflows therefore remain incomplete.

No public schema, build, runtime, or fixture files changed.

Round 5 corrects branch-ID validation so only conditionals require `then` and
`else`, reports wrong JSON types for schema `required` and `properties`, and
rejects enum values and string/item bounds inconsistent with the declared
schema type. New scripted cases exercise these checks. `raiderDsl` does not
depend on the runtime module, and `Program` does not expose token usage, so this
lane cannot directly connect portable attempt/token ceilings to invocation-owned
`Admission`/`BudgetLedger` without a shared build/runtime boundary change outside
RAI-198's allowed paths. Runtime-admission maxLLM=1 proof and declared
attempt/token accounting remain open; DSL-only tests do not establish them.

Round 6 adds `PortableLaunchMetadata` to `PortableLoweredWorkflow`, carrying
validated attempts, parallelism, deadline, token, and child ceilings. The
focused DSL test verifies these against the frozen `root-limits.json` fixture.
This is metadata production only: the portable CLI launch route is downstream
RAI-199 and no launch owner in this lane consumes the metadata. No attempt/token
exhaustion, Admission intersection, maxLLM=1 launch result, or RAI-164 repair
composition is claimed.

Round 7 review ruling scope: each of the ten accepted positive fixtures is now
invoked through the lowered native `Program` using scripted descriptors; all
returned typed values are observed as successful `Json` results, and construction
remains separately covered by the zero-dispatch spy. The validator now checks
every declared step output-schema name and resolves direct step input/items,
conditional predicate, binding, verdict, and artifact pointers against the
frozen input/output schema subset, including map-local pointer scope. Focused
negative cases cover a dangling nested predicate pointer and an unknown output
schema. This is additional pointer resolution evidence; it does not establish
exhaustive schema-field conformance or cross-endpoint type compatibility.
RAI-164 stage composition is still not implemented: current repair lowering
remains a one-shot safe-operation call, with no candidate-bound stage evidence
or typed exhaustion fixture. RAI-199 continues to own launch enforcement.

## Limitations / blockers

The implementation still does not establish exhaustive JSON Schema
keyword/type compatibility or full pointer/reference type compatibility. The lowerer emits
portable launch metadata, but no consuming portable launch path exists in this
lane, so the declared limits are not yet intersected with invocation-owned
Admission/BudgetLedger and attempts/token accounting. Runtime artifacts,
maxLLM=1 launch acceptance, RAI-164 typed stage evidence, and bounded repair
exhaustion composition remain unproven. Round-7 gates passed; independent review
is pending. Therefore RAI-198 remains partial and is not accepted. Earlier gate
evidence belongs to earlier source fingerprints and does not verify this round.
