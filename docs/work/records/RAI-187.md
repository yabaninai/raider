## Resulting behavior

- `raider.cli.Main run` gains `--deadline <seconds>`: a parse-time validated positive-integer bound on the BUNDLE program's work (ci-runtime §6: internal deadline shorter than the CI timeout, leaving time for cleanup and artifact upload). Validation is typed and pre-dispatch: missing, non-numeric, zero, or negative values are `Configuration` refusals (exit 21) before any dispatch or spend; combining `--deadline` with `--agent` is a typed refusal, so the flag is never silently ignored.
- When the deadline fires, the program fiber is interrupted inside the admitted budget slot (a real failed attempt in the ledger), the typed `DeadlineExceeded` error (`RA-DEADLINE`) carries exit 24 (§8), and the normal artifact path renders the truthful failure: `run.json` (status failed, exit 24, `RA-DEADLINE`, real `accounting` splice), `result.json` (typed error verdict document, `task-failed`), `summary.md` (`FAILED — RA-DEADLINE: ...`), `checks.junit.xml`, and a complete `artifacts.json`. Nothing is reported as succeeded. Preflight and artifact/report writes stay OUTSIDE the deadline window.
- Joint First CI acceptance extends the RAI-185 process-boundary suite with FCI-LIFE-01 (real-deadline run plus typed deadline-refusal tests) and FCI-LIFE-02 (parent-delivered OS SIGTERM to a real CLI child that owns a real grandchild: exit 143 within 30 s, grandchild destroyed within 10 s, streamed `events.jsonl` persisted, `run.json`/`result.json` absent, no success line). The whole First CI matrix is bound to one machine-readable map.
