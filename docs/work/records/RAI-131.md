## Resulting behavior

- **Trust preflight (CI-ADP-02)**: new `--require-provenance <manifest.json>`
  run flag. The manifest (operator-declared, trusted allowlist input) pins
  `{"bundle_sha256":"<hex64>","policy_sha256":"<hex64>"?}`. Before admission
  and before the first model dispatch, the runner hashes the resolved
  `--bundle` jar (and the declared policy file when wired) and refuses the
  launch TYPED on mismatch, missing/malformed manifest, or unreadable file
  (`RaiderError.InputValidation` → preflight-failure exit family 21). A
  tampered or unknown-provenance bundle never reaches a provider; run.json
  honestly shows the failed `bundle-preflight` check and no ledger (no
  `"attempts"` field).
- **JUnit artifact contract**: the runner now writes `checks.junit.xml` next
  to run.json/summary.md — rendered from the ACTUAL executed checks (stable
  IDs, pass/fail/errored/skipped counts, escaped details, empty suite written
  honestly). This closes the ci-runtime artifacts-table item for the current
  slice; it never pretends to verify task correctness.
- **Context parity (CI-ADP-01)**: one fixture bundle run under generic,
  github, and gitlab `--context` files — identical exit codes (0/0/0) and
  identical artifact basenames (run.json, summary.md, checks.junit.xml) per
  context; untrusted contexts export the redacted view (RAI-086, unchanged).
- **SIGTERM discipline (CI-ADP-03)**: the runner-fiber interrupt path under
  github and gitlab contexts — bounded wait for the events file, interrupt
  joins finalizers, every COMPLETE events line decodes; an EMPTY events file
  after an immediate interrupt is an honest artifact (created before the
  first envelope flush), not a failure.
