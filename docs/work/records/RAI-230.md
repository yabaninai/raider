## Resulting behavior

- `OutboundSpec.scala` contains zero timing sleeps (`grep -c "sleep"` on the final file: `0`; no `ZIO.sleep`, no `Thread.sleep`, no polling loop). The comment-sensitive grep surface is clean on the final fingerprint.
- **Waiter wakeup test rewritten as a deterministic promise protocol.** The sequential saturation phase fills the bounded outbound queue to its exact capacity (64 ordinary frames, asserted via the `full` counter), eight surplus receipts are enqueued and each suspends inside `receipt` on the full queue; the writer fiber is started; the completion promise resolves only after the sink has observed all 72 expected write events (`updateAndGet(_ :+ typeOf(json))` + one-shot `succeed` at the expected count). The main fiber awaits the promise (a bounded, deterministic wait — no polling, no sleep), joins the writer, and then asserts queue drained to 0 surplus (`bounded <= 64`), `full == 64`, and the exact write-event sequence head. The former `pollUntil` polling helper is deleted.
- **Coalesce test hardened (scope judgment, disclosed).** The card's Context claimed RAI-225 had already made the coalesce test deterministic; this is false on base `531d57c` — the test carries two pre-existing races, both reproduced and root-caused during this card:
  1. *Late-admission strand*: a `flushGap` receipt suspended on the full queue can be admitted after the writer's `WriteTerminal` case, which ends the writer loop without further picks — the frame strands unwritten and `gapFrames` comes back empty.
  2. *Early-Done race* (dominant): the test closed the input before installing the terminal, so the writer draining the queue observed the input-closed `Pick.Done` branch before the terminal existed, exited legally, and stranded the flush gap plus terminal (`terminalWrittenOrDone` false).
  Both produce the identical failure signature `gapFrames = Vector()` at the same assertion sites. The hardening keeps all three original assertions byte-identical and changes only the fixture sequencing: the sink arms a `flushArmed` promise after picking the first write and blocks on a release latch, so `flushGap` lands while the writer is frozen mid-write with exactly one free queue slot (a single non-suspending `modify`); `closeInput()` is dropped as redundant because `terminal(...)` atomically closes the input, making the Done-without-terminal writer exit path unreachable before `terminalWrittenOrDone` is asserted. Base pre-existence proof: coalesce test run 4 of 4 on the unmodified base tree failed with the identical signature.
- **Product-side finding (out of scope, handoff):** the late-admission strand above is a real pre-existing race in `Outbound.scala` (`writer` exits after `WriteTerminal` without draining receipts already admitted to the waiter list; `flushGap`'s `receipt` can suspend on a full queue). Test-side sequencing hides it; a product-side fix needs its own card.
- Sabotage detection proven in both directions: red-first on the old polling test at base, and after the rewrite on the final fingerprint (both details in Acceptance evidence).
