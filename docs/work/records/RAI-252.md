## Resulting behavior

The last cross-clean-round jar variance (RAI-240 limitation 1) is eliminated at the source. `modules/core/src/main/scala/raider/core/ids.scala` no longer uses a package-level `export ids.*`; it now declares, for each of the 8 id types, an explicit package-scope alias pair (`type X = ids.X` + `val X: ids.X.type = ids.X`). After the change, **consecutive full clean rounds are byte-identical end-to-end — both the canonical wrapper jar and the raw sbt-assembly jar itself** (three clean rounds measured identical raw and wrapper; see evidence). The public Scala API surface is unchanged: `raider.core.SessionId` … `raider.core.ArtifactId` resolve as types and as constructor/pattern terms via `import raider.core.*` exactly as before, and the qualified `raider.core.ids.*` path is untouched. No consumer source change; no repack-script change (`scripts/repro-jar` byte-unchanged, sha256 `cd46602e0590d15b6df3915c87783b3eee3b95a165738d556e12b9cc6da44a57`, the same fingerprint RAI-240 recorded); no golden re-pin; no new dependencies.

### Resolution mechanics (measured)

Top-level definitions in `ids.scala` are compiled into the compiler-synthesized holder class `raider/core/ids$package` (+ module class `ids$package$`, + `.tasty`) named after the file. With `export ids.*`, dotc materialized 8 forwarder methods into that holder in an order that **permuted between clean compile rounds** (hash-map iteration over the export's synthesized members), so the 3 `ids$package*` jar entries differed per round. With explicit `type`/`val` aliases, the holder's members emit in **source order** and are stable. Verified by `javap -p` on the fixed jar: `ids$package$` fields/accessors appear in exact source order (SessionId, RootId, JobId, StepId, AttemptId, ToolCallId, MessageId, ArtifactId). The holder keeps the same entry names, and its `public static` facade methods (`ids$package.ArtifactId()` …) are unchanged in name and descriptor; the only JVM-level delta on the synthetic holder is that the 8 module accessors are `public` instead of `public final` (names/descriptors unchanged). The synthetic holder is a compiler implementation detail, not the supported API; all consumers in this repository recompile from source and the full suite passes unchanged.
