## Resulting behavior

TUI-X.C1 complete on the product chat REPL:

1. **Per-hunk diff review.** Rendered diff hunks carry a `[n:state]` review
   marker (`pending` / `accepted` / `rejected`); the completed-turn footer
   advertises `diff review open: k/N decided | :hunk <n> accept | :hunk <n>
   reject | :hunk apply`. `:hunk` (status), `:hunk <n> accept|reject`,
   `:hunk apply` route through `DiffReviewCommands` and apply ACCEPTED hunks
   only, exclusively through the production `fs_patch` policy path
   (`PatchTool.applySelected`: containment, size bound, sha256 provenance
   anchored at the first decision). Fail-closed rules: no accepted hunks, no
   target header, multiple targets, missing provenance, or an already-applied
   review are refused without partial application; stale target (sha mismatch)
   is refused with the typed detail and the review stays open. A successful
   apply seals the review (`refusing to apply twice` afterwards). Decisions
   reset when a new turn changes the hunk set (review lockstep).
2. **Provider/model switching without REPL restart.** `:model` describes the
   current binding (and is surfaced as a chat status line); `:model
   <mock|openai|anthropic> [model] [baseUrl]` rebuilds the session over a new
   backend — mock replays a scripted stub with no network; openai/anthropic
   construct the production streaming backends (`OpenAIChatStreamingBackend` /
   `AnthropicMessagesBackend`, wrapped in `RateLimitRetries`) exactly like the
   startup prelude. Construction dials nothing; the first live byte happens on
   the next `:chat`. Keys resolve only via `LiveCredentials.resolve`
   (`RAIDER_API_KEY` / `RAIDER_API_KEY_CMD`); a missing key or refused
   configuration fails closed to `model unchanged: <model>` with a sanitized
   reason; raw secrets never enter the transcript (no-key switch verified
   under PTY; a configured fake key switches successfully and never appears in
   the raw output).
3. **Lineage tab reachable in chat layout.** `:aux` from the chat footer
   reaches the lineage tab (`lineage unavailable | validity unknown: set
   RAIDER_LINEAGE_DIR to a run directory` on a fresh session) and `:chat`
   returns.

Defect found and fixed during PTY acceptance: `ModelCommands.describe()`
returned its summary but never emitted it, so a bare `:model` painted nothing
in the interactive layout (unit tests only read the return value). It now goes
through the same status-line emit path as `switch`.

## Fix-up: forbidden-apis fixture literals (2026-10-25, post-integration)

the `secret-literal` rule of `scripts/quality/forbidden_apis.py` (OpenAI-style
`sk-…` shapes with ≥8 trailing chars, and a `secret = "…"` literal ≥16 chars).

≤15-char fixture allowance; the redaction assertions (`!raw.contains(secret)`,
