## Resulting behavior

Bounded scrollback закреплён на продуктовой поверхности REPL-модуля поверх
frozen-слоя (RAI-057 SessionRegistry: ScrollbackView + eviction counter +
typed RegistryError.UnknownTab; RAI-102 TabShellHost wiring). Механика
bounds/cap/typed-error потребляется из frozen-слоя как есть; продуктовая
правка — аддитивный новый файл (frozen-файлы не менялись):

- `raider.repl.TabShellScrollback` (product, NEW):
  - `Screen(label, cap, evicted, lines)` + `render` — продуктовый экран
    scrollback вкладки с ВИДИМЫМ счётчиком вытеснения: заголовок
    `scrollback [label]: last 500 of 10000 lines (9500 evicted, cap 500)`
    над байт-точным окном содержимого (P2S-01).
  - `screen(registry, tabId)` — продуктовое чтение label+scrollback через
    frozen `registry.tab`/`registry.scrollback`: `RegistryError.UnknownTab`
    распространяется TYPED, lookup не создаёт фантомных вкладок (P2S-02).
  - `publishLines(hub, ...)` — продуктовый источник бурста: каждая строка —
    один Diagnostics-конверт через РЕАЛЬНЫЙ hub (ADR-024), тот же seam, что
    у живого runtime; без bypass bounded-фолда (P2S-03). Только wiring:
    ни лупа, ни записи в терминал (ONE writer, RAI-061).
- `raider.repl.TabShellScrollbackSpec` (test, NEW): acceptance P2S-01..03
  на продуктовом wiring `TabShellHost.wiring` (реальный EventHub +
  SessionRegistry). Фича-специфика карточки — большой объём (10k строк),
  eviction counter виден, cross-tab параллельные бурсты; терминальная
  атомарность того же shell-хоста уже PTY-доказана в RAI-102 (P2W-01..03,
  вкл. байт-точный scrollback 220/220) и здесь не дублируется. Pacing
  (чанки по 100 с 10ms yield) удерживает hub `droppedDiagnostics == 0` при
  скоростях теста; дроп проявился бы как честный FAIL (тождество
  `evicted + window == received` сломалось бы).

Acceptance:

- P2S-01: 10k Diagnostics-строк через продуктовый hub → таб держит ровно
  последние `ScrollbackCap`=500 строк байт-в-байт (`alpha ev-9501` …
  `alpha ev-10000`), `evicted == 9500`, `evicted + window == 10000`,
  hub drops == 0, статус Running; экран-рендер: exact заголовок со счётчиком
  вытеснения + окно байт-в-байт.
- P2S-02: `registry.scrollback(TabId("ghost"))` и продуктовый
  `TabShellScrollback.screen` — обе возвращают typed
  `RegistryError.UnknownTab` (message `unknown tab ghost`); до/после
  `tabs.isEmpty` — фантомных вкладок нет.
- P2S-03: 3 таба × 10k строк параллельно (`ZIO.foreachParDiscard`) — у
  каждого таба bounds 500/9500, окно байт-точное со своими метками таба
  (нет потерь: `evicted + window == 10000`; нет дублей/cross-tab bleed:
  окна различны и равны ожиданиям), hub drops == 0, открыто ровно 3 таба.

## Limitations / blockers

- P2S-01..03 исполняются на продуктовой wiring-поверхности
  (`TabShellHost.wiring`: реальный hub + registry, продуктовые
  TabShellScrollback вызовы) in-process, а не под PTY: фича-специфика
  карточки — объём/bounds/счётчик/cross-tab конкурентность, а PTY-механика
  того же shell-хоста (drafts, one-writer, байт-точный scrollback 220/220,
  typed hints) уже принята в RAI-102 (P2W-01..03). Гейт-профиль repl
  подтверждает живость продуктовой REPL-поверхности (repl-smoke).
- Интерактивная shell-команда рендера scrollback внутри frozen
  CommandRouter/TabShell отсутствует (modules/ui/** — запрещённая зона
  этого lane): `Screen.render` возвращает точные строки для печати above
  prompt; подключение в пользовательский ввод — шаг карточек-потребителей
  (по прецеденту RAI-102 record: Main.ttyLoop/chat-интеграция — следующий
  слой). Обоснование продуктовой правки: frozen-слой НЕ предоставляет
  продуктового чтения/рендера scrollback — только registry API.
- `docs/lineage.md` §9.2 (UX07 «продуктовый рендер scrollback») вне allowed
  paths этого lane — координатору на merge (gap закрыт этим срезом на
  уровне продуктового модуля raider.repl).
- artifacts/tools/m2 (+cp-*.txt) скопированы в worktree из root (untracked,
  §1a runbook) — требование гейта compile-fixtures; в git не попадают.
- Pacing бурста (100×10ms) — свойство теста, не продукта: `publishLines`
  сам по себе без задержек; ассерты не ослаблены (drops==0 обязателен).
