## Resulting behavior

Bounded scrollback is established at the REPL module's product surface on top of
the frozen layer (RAI-057 SessionRegistry: ScrollbackView + eviction counter +
typed RegistryError.UnknownTab; RAI-102 TabShellHost wiring). Bounds/cap/typed
error mechanics are consumed from the frozen layer as-is; the product change is
an additive new file (frozen files unchanged):

- `raider.repl.TabShellScrollback` (product, NEW):
  - `Screen(label, cap, evicted, lines)` + `render` — product screen for a tab's
    scrollback with a VISIBLE eviction counter: header
    `scrollback [label]: last 500 of 10000 lines (9500 evicted, cap 500)`
    above the byte-exact content window (P2S-01).
  - `screen(registry, tabId)` — product read of label+scrollback through frozen
    `registry.tab`/`registry.scrollback`: `RegistryError.UnknownTab` propagates
    TYPED; lookup does not create phantom tabs (P2S-02).
  - `publishLines(hub, ...)` — product burst source: one Diagnostics envelope per
    line through the REAL hub (ADR-024), same seam as live runtime; no bypass of
    bounded fold (P2S-03). Wiring only: no loop and no terminal writes (ONE
    writer, RAI-061).
- `raider.repl.TabShellScrollbackSpec` (test, NEW): acceptance P2S-01..03 on
  product wiring `TabShellHost.wiring` (real EventHub + SessionRegistry). Card
  feature specifics are large volume (10k lines), visible eviction counter,
  and cross-tab parallel bursts; terminal atomicity of the same shell host was
  already proven under PTY in RAI-102 (P2W-01..03, including byte-exact
  scrollback 220/220) and is not duplicated here. Pacing (chunks of 100 with
  10ms yield) keeps hub `droppedDiagnostics == 0` at test rates; drops would
  trigger an honest FAIL (identity `evicted + window == received` would break).

Acceptance:

- P2S-01: 10k Diagnostics lines through product hub → tab retains exactly the
  last `ScrollbackCap`=500 lines byte-for-byte (`alpha ev-9501` …
  `alpha ev-10000`), `evicted == 9500`, `evicted + window == 10000`, hub drops
  == 0, status Running; screen rendering: exact header with eviction counter +
  byte-exact window.
- P2S-02: `registry.scrollback(TabId("ghost"))` and product
  `TabShellScrollback.screen` both return typed `RegistryError.UnknownTab`
  (message `unknown tab ghost`); `tabs.isEmpty` before/after — no phantom tabs.
- P2S-03: 3 tabs × 10k lines in parallel (`ZIO.foreachParDiscard`) — every tab
  has bounds 500/9500, byte-exact window with its own tab labels (no losses:
  `evicted + window == 10000`; no duplicates/cross-tab bleed: windows differ
  and match expected), hub drops == 0, exactly 3 tabs open.

  concurrency. PTY mechanics of the same shell host (drafts, one-writer,

  Main.ttyLoop/chat integration is the next layer). Rationale for product
  change: frozen layer does NOT provide product scrollback read/render, only
  registry API.

  lane's allowed paths — coordinator to handle on merge (gap closed by this
