## Limitations / blockers

- Probe suites (`ParallelStanceProbeASpec`, `ParallelStanceProbeBSpec`) were
  temporary: never committed, removed before gating; marker files lived in the
  JVM `java.io.tmpdir` and were verified-deleted before each discriminating run.
- A first probe control (previous session) produced a false "still overlaps
  under `parallelExecution := false`" result caused by an uncleaned marker
  directory (a `/tmp` decoy path was cleaned while the JVM's real
  `java.io.tmpdir` markers survived). Clean-state reruns supersede it; the
  serialization result above is the corrected one.
- Both timing runs carried sibling-lane CPU noise (rai-263/rai-269 compiling on
  the same host); the 700 s vs 680 s difference is within that noise. The
  budget-fit conclusion (≪ 1800 s) does not depend on it.
- Serialization is per module: suites of two different modules may still
  interleave (≤ 2 modules concurrently, by the `Tags.Test` cap). Within-module
  collisions such as the `esc-hostile` fixed-path reuse in
  `LineageCompileGateSpec` / `UnifiedProjectionExecutionSpec` are structurally
  removed; cross-module fixed-path collisions were not audited and remain a
  candidate for a separate cleanup card (unique per-suite subdirectories).
- Evidence logs under `artifacts/quality/rai266-evidence/` are untracked
  (`artifacts/` is gitignored); immutable values are recorded in §1e and in the
  tables above.
