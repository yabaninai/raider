## Resulting behavior

Интерактивная команда `:scrollback [tabId]` на продуктовой поверхности
tabs-режима (`raider repl --tabs`, RAI-108): рендер экрана вкладки через
продуктовый `raider.repl.TabShellScrollback.screen`/`render` (RAI-104)
ABOVE промпта; registration по freshness-прецеденту RAI-111; frozen-слой
(modules/ui/**) не тронут — хватило существующих seam'ов.

- `raider.repl.ScrollbackCommands` (product, NEW):
  - `names` — реестр-источник истины поверхности (`Vector(":scrollback")`);
    парсер матчит ровно реестр (без второй hand-list копии), combined
    nearest-hint каталог (`ShellPalette.allCommands`) ДЕРИВИРУЕТ реестр
    (RAI-111 precedent). TAB-комплит остаётся router-only (задокументиро-
    ванное решение RAI-111 для нероутерных поверхностей; запинено спекой).
  - `parse` — чистый матчинг (первый токен, case-insensitive, как
    Commands.handle/PlanCommands); `:scrollbackx` — never a partial match.
  - `resolve` — резолюция токена над публичным read model реестра,
    семантика frozen `:switch`: 1-based индекс, точный TabId, точный label,
    уникальный префикс label; КАЖДЫЙ провал (нет токена / вне диапазона /
    неизвестный или неоднозначный label) — TYPED
    `RegistryError.UnknownTab` с сырым токеном (P2SR-02); lookup не создаёт
    фантомных вкладок; отсутствующий токен — `missingTab` =
    `UnknownTab(TabId(""))`, НЕ дефолт «фокусной вкладки» (контракт
    карточки: отсутствующий tabId = UnknownTab).
  - `run` — продуктовое чтение через `TabShellScrollback.screen` (typed
    `RegistryError` распространяется as-is).
  - `commandTerminal` — интерцептор-терминал (паттерн RAI-110
    `PlanPanel.commandTerminal`): строки реестра потребляются ДО frozen
    router'а, исход печатается ОДНИМ атомарным блоком через ONE writer
    (`printAbove`), следующая строка читается дальше; не-реестровые строки —
    byte-exact насквозь; EOF — насквозь. Dispatch ИНЛАЙН (в отличие от
    `:approve`): чтение реестра ограничено и без gate — рендер детерми-
    нированно ложится до перерисовки следующего промпта.
  - Исход: успех — ТОЧНЫЙ `Screen.render` (заголовок с evicted-счётчиком +
    окно байт-в-байт); провал — одна строка `error: <message>` (end-trimmed
    для транскрипта; typed-значение сохраняет сырой пустой TabId).
- `raider.repl.TabShellHost` — аддитивный overload `run(wiring, scrollback)`
  (паттерн plan-overload RAI-110/paletteTerminal RAI-106): декорирует
  palette-терминал интерцептором; прежние overloads byte-идентичны.
- `raider.repl.Main.runTabs` — продуктовый вход `--tabs` поднимает шелл с
  интерцептором (`TabShellHost.run(wiring, ScrollbackCommands(registry))`).
  Legacy-цикл (без `--tabs`) не тронут бит-в-бит (Commands/helpText/pipe/tty
  loop без изменений; `:scrollback` в legacy — прежний
  `unknown command … — try :help`).
- `raider.repl.ScriptedTabStream` — env-ручки фикстурного объёма
  (`RAI113_SCRIPTED_TAB_LINES`, `RAI113_SCRIPTED_TAB_DELAY_MS`; дефолты
  220/15ms неизменны — все якоря RAI-108 на месте). Mock-gated by
  construction: стрим форкается ТОЛЬКО при `PreludePlan.isScripted`; живой
  бекенд синтетики не получает никогда. Нужно для P2SR-01: 10k-бурст на
  РЕАЛЬНОМ входе.
- `raider.repl.ShellPalette.allCommands` — += `ScrollbackCommands.names`
  (nearest-подсказка: `:scrollbak` → did you mean: `:scrollback?`); каталоги
  `commands`/`chatCommands` и `complete`/`completeChat` не менялись.

## Limitations / blockers

- PTY-приёмка исполняется на реальном терминальном входе продуктового Main
  (--tabs) под /usr/bin/script (прецедент RAI-108); машинная нагрузка
  соседних lane во время работы была высокой (load average до 129), из-за
  чего PTY-семейство дважды flaked на ПОСТРОЧНЫХ счётчиках транскрипта
  (детали в хронологии). Мои финальные ассерты — merge-иммунные по контенту
  (заголовок + полные payload-хвосты + якоря), что не ослабляет acceptance:
  byte-точность окна доказывается контентом и in-process точным вектором,
  а атомарность строк отдельно держит bad==0 barScan. ПРЕДУПРЕЖДЕНИЕ
  координатору: TabShellUnreadPtySpec P2U-03 (RAI-105) и, вероятно, другие
  PTY-спеки остаются чувствительны к построчным счётчикам при высокой
  машинной нагрузке — кандидат на отдельную follow-up карточку (вне этого
  lane).
- PlanTabsPtyApp.scala (RAI-110 harness) получил 1-строчный механический
  parse-фикс — ВНЕ фичевой поверхности этой карточки, но внутри allowed
  paths; без него scalafix-check красный на чистом дереве ЛЮБОГО lane
  (pre-existing на 4b46dc7). Семантика не менялась (PlanTabsPtySpec 3/3).
  Coordinator'у: зафиксировать в RAI-110 record при merge.
- `docs/lineage.md` §9.2 (UX07 «продуктовый рендер scrollback») вне allowed
  paths этого lane — координатору на merge (gap закрыт этим срезом).
- `:scrollback` НЕ входит в legacy `:help` (Commands.helpText) и в banner
  tabs-режима осознанно: legacy-поверхность обязана остаться бит-в-бит
  (P2SR-03 regression), banner-каталог деривируется из frozen CommandRouter.
  Discoverability — через nearest-hint (deriving реестра) и PTY-доказанную
  работу команды. Если владельцу нужен banner/help-упоминание — отдельное
  owner-решение (меняет legacy/tabs баннеры).
- Резолюция `[tabId]` покрывает индекс/TabId/label/уникальный префикс;
  неоднозначный префикс — честный typed UnknownTab (без выбора «первого»).
  Расширенные типы ошибок frozen-роутера (AmbiguousTabLabel и т.п.) не
  дублируются — контракт карточки называет ровно UnknownTab.
- artifacts/tools/m2 (+cp-*.txt) скопированы в worktree из root (untracked,
  §1a runbook) — требование гейта compile-fixtures; в git не попадают.
- Real paid calls: нет (RAIDER_PROVIDER=mock запинен в PTY-драйвере; все
  источники событий — фикстурные стримы через реальный EventHub).
