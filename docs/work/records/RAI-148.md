## Resulting behavior

The static tool-name → `RecoveryClass` taxonomy of the lineage layer is now ONE canonical public source, `raider.runtime.lineage.model.RecoveryTaxonomy` (ADR-027 §6.2 point 2 discipline unchanged: ReadOnly by default, `Idempotent` never guessed, config-driven extension still reserved for the schema card):

- `fs_patch` added to the write class → **Mutating** (was ReadOnly — the owner-flagged defect: captured BillingCi repairs modified source yet were labeled ReadOnly).
- `proc_run` added to the exec class → **Mutating** (was ReadOnly despite being real command execution).
- All three former private copies now consume the canonical source; no second set literal exists in product code (grep evidence below):
  - `LineageReducer` (runtime, batch reduce) — set-literal copy + private `recovery` removed;
  - `LiveGraphBuilder` (runtime, live fold) — set-literal copy + private `recovery` removed (a third duplication the card text did not enumerate; same drift hazard, within allowed paths);
  - `IsolatedRerun` (CLI, LIN6-02 isolation guard) — set-literal copy + private `isMutatingTool` removed; `mutatingTools` classifies recorded response envelopes through `RecoveryTaxonomy.isMutating`.

Consequence: recorded/captured fixtures whose responses carry `fs_patch`/`proc_run` `tool_calls` envelopes now flow the LIN6-02 isolation guard — a mutating replay aimed at the original (or any canonical alias) is refused typed (`RerunError.MutatingUnisolated(Vector("fs_patch", "proc_run"))`) BEFORE any execution; a faithful `WorkspaceIsolation.isolate` copy proceeds. Genuinely ReadOnly records still need no isolation.

### GraphHash policy for reclassified historical fixtures (contract point 4 — CHECKED, not assumed)

The recovery class DOES enter the canonical hash: `GraphHash.canonicalNode` renders `tool_call|…|tool|recovery|outcome|…` (GraphHash.scala, tool_call case). Therefore:

- The canonical-form scheme stays `session-graph/v1` — the FORM did not change; the classification VERDICT for two tool names changed per this card.
- A historical recorded graph containing `fs_patch`/`proc_run` ToolCall nodes re-reduces to a DIFFERENT GraphHash than its recording-time value (ReadOnly → Mutating). This is intended and pinned by the "TAX-03 hash policy" test (same shape differing only in the verdict hashes differently; identical verdicts hash identically).
- Consumers of old recorded hashes must RECOMPUTE for affected records at re-verification time (the established recompute-never-compare discipline of prior hash-policy changes); records without the two reclassified tools hash byte-identically (existing golden suites green, unchanged).
- No historical fixture in the tree is affected: `contracts/lineage/golden/**` contains no fs_patch/proc_run references, and no test pins a GraphHash literal.
