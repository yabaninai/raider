## Limitations / blockers

1. **Upstream boundary: full-clean-per-build byte-identity is NOT achievable by packaging (measured, not assumed).** Every clean dotc round permutes the `export ids.*` forwarders (`raider/core/ids$package*`, 3 entries) and re-pickles ScalaSignature attributes; raw hashes across clean rounds: `5a070f7b…`, `fef22a01…`, `2d9798de…` (all distinct). The wrapper guarantees byte-identity for consecutive builds of an unchanged tree (three proven pairs) and reduces cross-clean-round variance to exactly 3 entries. Removing the last churn requires a product-source change to `modules/core/src/main/scala/raider/core/ids.scala` (e.g. replacing the package-level `export ids.*` with explicit aliases) — outside this card's allowed paths; a separate card is required.
2. **Revert does not restore the byte-exact hash of the pre-tamper jar.** H4 (`bd83e573…`) ≠ H1 (`8c2f8f6c…`): after the tamper was reverted, zinc recompiled the unit in an incremental round and its bytes differ from the original full-round bytes (round-state pickling nondeterminism, same root-cause class as Limitation 1). State-stability proven (H5 = H4). The card's tamper criterion is sensitivity (hash changes on input change) — proven; byte-exact restoration after source churn is not claimed.
3. **Committed goldens NOT re-pinned (card non-goal).** `run-all.sh` against the wrapper jar fails exactly the 6 `adapterJarSha256` findings; the green checker run uses a clearly marked worktree-local goldens copy outside `contracts/**`. Re-pinning `adapterJarSha256` for the integrated candidate is the coordinator's separate decision; until then, `run-all.sh` green (exit 0) requires the pinned jar or an updated pin.
4. **Concurrency scope.** Concurrent execution is proven for the packaging stage (per-process temp + atomic replace, separate directories, equal outputs). The sbt build stage remains single-JVM per checkout per host discipline (concurrent mutable builds in one checkout are forbidden), so two concurrent FULL wrapper builds in one checkout are neither run nor supported; run them in separate worktrees.
5. **python3 dependency.** The wrapper is python3 stdlib (`zipfile`/`argparse`/`hashlib`) — allowed lane for Python (`scripts/` bootstrap glue, not shipped product); verified on host python 3.12.7.
6. `Makefile` untouched (outside allowed paths); wiring `scripts/repro-jar` into `make raider-jar` / contributor docs is a separate coordinator-owned change.
7. Environment provisioning (gitignored, disclosed): `artifacts/tools/m2` copied read-only from the root checkout (31/31 `consumer-deps.json` closure verified); `artifacts/repro-240/` and `artifacts/xe-out/` hold lane evidence and checker outputs (gitignored). `artifacts/xe-out` had to be created manually before the corpus run (fresh-worktree precondition, same as RAI-231).
8. Host load during runs: 1-minute averages 92–264 (foreign-VM cycling on the shared 18-core host; bounded 120s sleeps applied when > 12, readings recorded in Commands). No threshold or verifier was changed to obtain any green result. Resume-session runs happened at load 4.6–6.0.
9. **Interruption disclosure.** The 2026-10-28 session was terminated during a `make quality-profile PROFILES="fast"` rerun (`20261028-162014-8899-0001`): that directory holds per-check logs but no `manifest.json`, so it is an interrupted run, not a pass, and is not cited as evidence anywhere.
