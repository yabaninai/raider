## Resulting behavior

The forbidden-apis scanner reports true source line numbers. Root cause: `strip_comments()` replaced each multi-line `/* ... */` block comment with a run of spaces of equal total length — including the comment's internal newlines — so every multi-line block comment deleted its newlines from the stripped text and shifted all subsequent line numbers down. Verified on the wave-C file: `modules/cli/src/test/scala/raider/cli/processapi/ProcessApiAcceptanceSpec.scala` has 769 lines; the pre-fix stripping produced 732 lines (37 collapsed newlines), so the sentinel at true line 508 was reported at 471 (508−37=471), matching the wave-C incident (`:471` reported, true `:508`).

Fix (attribution-only): comment bytes are now blanked in place while newlines are preserved verbatim (`_blank_in_place`: block comments first with `re.DOTALL`, then line comments; `//` content is blanked rather than deleted, which also preserves column offsets). Detection rules, regexes, the 15-char placeholder threshold, the allowlist, exit codes, and gate policy are unchanged. Pre-existing best-effort caveats are unchanged (comment markers inside string literals are still mis-stripped — a detection caveat that predates this card and is not touched).

Side effect on the real tree: the 8 allowlist-skip NOTE lines, which were previously mis-attributed by the same mechanism (reported `Main.scala:95/104/116/129/143/149/191` and `WorkflowRun.scala:1207`), now cite verified true lines (`Main.scala:132/141/153/166/180/186/228` and `WorkflowRun.scala:1294`), cross-checked with `grep -n "System\s*\.\s*exit\s*("` on both files.
