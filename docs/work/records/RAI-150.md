## Resulting behavior

`SessionGraphView.toView` (the product cli adapter) now POPULATES both
RAI-141 view fields for the whole graph:

- `NodeView.inputs` (ADR-031 §2.6, half 1): the node's dataflow edges as
  exact id strings, 1:1 in the graph's own edge order — no sorting, no dedup,
  no invention. Nodes without edges (phases by definition; models/tools/
  delegations with no upstream) degrade honestly to the empty vector.
- `NodeView.outcome` (ADR-031 §2.4/§2.5, half 2): the recorded
  `ToolOutcome` class of `SessionNode.ToolCall.outcome` as the frozen
  lineage-data v1 vocabulary string — `Succeeded` / `Failed` / `Cancelled` /
  `Timeout` — via `outcomeClassOf`, case for case the same total mapping as
  the gate adapter (`LineageCompileGateSpec.GraphToView.outcomeClassOf`).
  `None` for the other kinds and for a tool the graph carries no finished
  outcome for. The `Failed` reason never crosses the view boundary
  (payloads stay addressable by dataRef only, §2.5); the renderer's
  failed-marker phrase stays the bounded `recorded outcome: <class>`. The
  mapping is total over the closed `ToolOutcome` enum, so the adapter can
  never emit a class outside the renderer's vocabulary; strings outside it
  remain the renderer's typed `UnknownKind` rejection (future wire
  revisions).

The adapter stays pure (no IO), deterministic (same graph → structurally
equal view on repeat), and confined to the cli layer; the dsl types,
renderer, wire schema and graph model are untouched (non-goals respected).

Because product and gate adapters now agree, the frozen goldens render the
same bytes through either adapter, and `SessionGraphViewSpec` expectations
flipped to EXACTLY the gate-pinned shapes (the RAI-141 review risk, closed):
the tiny-graph recorded-Failed tool (n3, edit_file) renders the typed
`LineageStep.failed("n3", NodeKind.ToolCall("edit_file", "Mutating"),
Some("d3"), ...` short-circuit with `reason = "recorded outcome: Failed"`,
and the deep-tree n3 ← n1 cross-scope edge threads as the `Vector("n1")` id
literal — the same two shapes `LineageCompileGateSpec` pins for the same
frozen documents.

`SessionGraphViewSpec` pins: the four-kind unit graph with model → tool edge
(n2 ← n1), cross-node tool → tool edge into the FAILED tool (n3 ← n2),
multi-input edge order (n5 ← (n1, n3)); outcome classes on the unit graph
(n2 `Some("Succeeded")`, n3 `Some("Failed")`, all non-tool kinds `None`,
rendered failed shape with payload-free reason, `exit 1` never rendered);
honest empties (inputs on n0/n1/n4 and all tiny-graph nodes; outcome None
for every non-tool kind and for the deep-tree tool whose wire outcome is
null); golden deep-tree cross-subtree edge (n3 ← [n1]); inputs reference
only existing node ids; triple-conversion determinism; input graph not
mutated; all pre-existing VIEW-A-01/02/03 contract tests.

## Limitations / blockers

1. Adapter duplication by design: `LineageCompileGateSpec.GraphToView`
   remains a test-local copy of the conversion (its documented
   snapshot-discrepancy note says it is to be swapped for a direct
   `SessionGraphView.toView` call "once the adapter lands"). The adapter has
   now landed and the two agree (this card pins that agreement behaviorally
   via the shared frozen goldens), but the copy itself lives in a file
   outside this card's allowed paths — deduplicating it (and retiring the
   note) needs a separate scope decision/card.
2. The gate adapter pins the shared contract for the two frozen goldens;
   the compile gate's `tiny-graph`/`deep-tree` documents carry exactly one
   Failed class and one null outcome respectively. `Cancelled`/`Timeout`
   classes are covered by the unit-graph mapping test surface (the
   `outcomeClassOf` total match) and by the reducer/corpus suites
   downstream, not by a golden — adding a golden would be a contracts-area
   change outside this card's paths.
3. Half-1 limitation history (recorded honestly in the prior revision): the
   outcome half was originally blocked because the lane baseline predated
   RAI-141; resolved by merging main (`62330f4`) — `NodeView.outcome` now
   exists and no dsl/schema change was needed from this lane. The earlier
   contract-change request is thereby satisfied by RAI-141 as merged; no
   further ADR action open from this card.
4. Real paid calls: none; everything ran on local/mock fixtures and the
   pinned local dotc.
