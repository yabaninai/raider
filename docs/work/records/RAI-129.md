Status: done (scoping slice .a; continuation-execution explicitly out of scope). Date: 2026-10-13 (UTC). Baseline commit/source: `0e119da` (branch `lane/rai-129`), deliverable commit `561d537`.

## Resulting behavior

`raider resume <run-dir>` — a new product subcommand of the run module (`raider.cli.Main` → `CliArgs.parse` → `HeadlessRunner.run`, dispatched BEFORE any run/preflight machinery, the RAI-109 `replay` precedent). It recovers the OBSERVABLE state of a PAST run from its journal (`<run-dir>/events.jsonl`, the LIN-03A streamed journal) with zero re-execution:

- **Typed journal re-read** through the accepted LIN-01B reader `LineageEventReader` (reuse, not duplication): every complete line must decode; an undecodable LAST line is a typed truncated-tail marker (line number + raw prefix length) — never silently dropped, never silently trusted; earlier corruption, wrong schemaVersion and per-job seq gaps are hard typed errors.
- **State restoration as pure data** through the accepted LIN5-03 `LineageReducer.reducePartial`: the recovered prefix is re-folded into the `SessionGraph` (root/session, node counts by kind, deterministic `GraphHash`). This is the card's "replay from the last consistent point WITHOUT replaying mutations": a deterministic fold over envelopes — no model call, no tool call, no workspace write, no journal append. A run without a `Terminal` record is reported `interrupted (last observed: <status>)` (§13 restart marking; the last tool is never executed automatically).
- **Artifact pointers**: known run artifact names present in the run dir (`events.jsonl`, `run.json`, `summary.md`, `transcript.json`, `lineage.scala`, `lineage-data.json`, `checkpoint.json`) reported with size + SHA-256.
- **Read-only guarantee**: the run directory stays byte-identical. Unlike `JobJournal.replay`, resume does NOT truncate a torn tail — nothing ever appends to a past run's journal, and the uncertain bytes stay preserved for reconciliation (card compatibility note).
- **Honest typed errors**: missing run dir / missing journal → `typed-error: resume journal missing: <path>` exit 21; empty journal, mid-file malformed line, unsupported schemaVersion, seq gap → typed `LineageError` exit 21; an unfoldable prefix → `ReduceError` exit 20; usage errors → exit 21. No fabricated recovery, no silent skips.
- **Exit codes** (frozen ci-runtime §8 mapping only): 0 = recovered, journal consistent (the report states honestly whether the run itself reached a terminal status); 26 = recovered to the last consistent point with an UNCERTAIN truncated tail; 21 = usage / journal missing / journal unreadable; 20 = journal does not fold. Rationale for 26 on a torn tail: the bytes after the cut are lost, so the run's tail outcome is honestly uncertain — a CI consumer must distinguish this at the exit-code level, not only on stdout (ReplayCli precedent: `Tampered → Uncertain`).
- **Surface**: run-module CLI subcommand, NOT a REPL command. Justification: the journal and artifacts live in the run module's `<out>/work-<uuid>` invocation dirs (the REPL has no run-dir surface); RAI-109 wired `raider replay` exactly this way (raw-argv target case, dispatch-before-preflight, `Outcome(result = None)` — a recovery of a PAST run never creates a new invocation root); exit-code consistency is a ci-runtime §8 run-module concern; recovery of interrupted CI runs is an operator CLI workflow (target application: CI pipelines).

**Slicing** (proposed before coding, per card order): 129.a (this slice) = the recovery/read/state-restoration surface above; 129.b (future, after the owner schema-card) = continuation EXECUTION from the restored prefix (serialized plans / registered named steps, P2 §13 — requires phase/recovery wire events, a card non-goal here); 129.c = retention/redaction policy, archive/reopen workflow. The slice unlocks the owner decision on the schema card (board obligation W08).

## Limitations / blockers

- **No continuation execution**: resume recovers state; it never re-dispatches a run (no model/provider calls — no paid calls anywhere in this slice; the only backend in fixtures is mock). Continuation from the restored prefix is slice 129.b and depends on the owner schema-card (phase/recovery wire events are a card non-goal).
- **Torn-tail semantics source**: resume reuses the LIN-01B events.jsonl reader (the accepted reader for THIS journal surface), not `JobJournal.replay` itself — the latter reads `segment-N.jsonl` layouts and physically truncates the tail; both behaviors (a read-only recovery that preserves uncertain bytes, and the journal's repair-for-append) are documented and intentional; the frozen `raider.runtime.journal` types are untouched.
- `session:` renders the journal's actual (possibly empty) `sessionId` — the honest wire value of the current run module (`StatusLedger.sessionId` is empty in this slice); resume invents nothing.
- Process-level smoke ran through the real `raider.cli.Main`; a packaged REPL/CI adapter is out of this card's scope.
- Non-goals honored: no phase/recovery wire events, no retention/redaction policy, no distributed recovery, no frozen-schema change, no second scheduler/runtime.
