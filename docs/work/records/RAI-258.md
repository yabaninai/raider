## Resulting behavior

`raider run --agent coder` now enforces run-aggregate ceilings that bind the
root loop and every delegated child JOINTLY, via a new process-local
`AggregateRunCeiling` shared by all backends of one run:

- New CLI flags `--max-dispatches N`, `--max-tokens TOTAL`,
  `--run-deadline SECONDS` (positive integers; parse/validation refusals are
  typed `Configuration` errors with flag-named messages). The flags apply to
  `--agent` runs only; `--bundle`/`--workflow` runs and non-coder agents get a
  typed refusal naming the flags (other agents do not delegate).
- Enforcement: every model dispatch of the run (root actor `"root"`, children
  `"<agent>#<n>"`) is admitted by the ceiling BEFORE the wire call. Tripped
  dimensions refuse subsequent admissions typed: dispatch/token caps →
  `ProviderBudget` (exit 23 via the frozen §8 mapping), run deadline →
  `DeadlineExceeded` (exit 24). In-flight honesty: usage that arrives past the
  token ceiling still accumulates (the spend happened); the FIRST dispatch past
  the ceiling is what is refused. Accounting is per-actor + run-total with
  `Math.addExact` overflow guards; concurrent admissions are atomic under one
  lock, so parent/child interleaving cannot overshoot a cap.
- Cancellation: the delegation toolset arms a watcher once at first spawn. It
  races the run deadline against the ceiling's trip signal; when either fires,
  every live child is cancelled out-of-band via `jobs.cancelAny` (no model
  admission, no second runtime) and each child records an honest
  `DeadlineOutcome` — `Settled` (terminal within the bounded grace),
  `Uncertain` (not terminal within grace), `AlreadyTerminal` (finished before
  the ceiling fired) — queryable via `ceilingCancellationOutcome(s)`. Existing
  per-child (RAI-063) deadline watchdogs are untouched and separate.
- Honest failure reporting: a ceiling denial surfaces as a typed `RunResult`
  (`status = Failed`, `error = DeadlineExceeded/ProviderBudget`, checks bundle
  records `run-outcome` Failed) with the mapped exit code.
- Portable token/deadline enforcement and bundle deadlines are untouched (no
  double enforcement, no double counting — the ceiling observes wire usage
  exactly once per dispatch).

## Limitations / blockers

- **Blocker for integration (scope):** the `DelegationToolset.scala` change is
  outside the card's literal Allowed Paths (see Changed paths). Behavior and
  evidence are complete; the coordinator must authorize the path amendment (or
  a follow-up card) before wave integration.
- The run deadline is detected lazily at admission AND proactively by the
  delegation watcher (sleep of the remaining deadline). A run with a deadline
  but NO delegation and NO further dispatches reports expiry at the next
  admission rather than at the exact wall-clock instant; this matches the
  ceiling's "no scheduler, no second runtime" discipline. Precision on e2e
  coverage (review A1): the CLI deadline test pins the observable contract
  (exit 24, typed `RunResult`, one mid-dispatch child, bounded time) but its
  `elapsedMs < 30000L` bound passes on BOTH the lazy and the proactive
  detection paths — the DISCRIMINATING pin for proactive out-of-band
  cancellation is `AggregateDelegationCeilingSpec`'s parked-child deadline
  test (a child parked mid-dispatch can only be stopped by the watcher; no
  later admission can detect the expiry).
- `Uncertain` cancellation outcomes are honestly possible for children that
  ignore interruption past the grace window; the tests park children on
  interruptible promises, so recorded outcomes there are `Settled`/terminal.
  No hidden retry or fake `Cancelled` is produced (RAI-063 semantics reused).
- Evidence applies to the post-reformat tree (final fingerprint); the two
  pre-reformat green runs (`rai258-cli-run5/6.log`, `rai258-budget-run4/5.log`)
  are superseded by `rai258-final-rerun.log` and the executed gate manifests.
