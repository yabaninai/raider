## Resulting behavior

Card follow-up to RAI-234's proposal (its "Review and next task" §b/c): make the `phaseStarted` → `onExit`-arming window in `AgentLoop.runPlan` deterministically enterable, prove the red first, then land the minimal mask as defense-in-depth with revert-probe detection.

1. **Test-only injection seam (commit `864edd7`)**: `AgentLoop.planWindowSuspension`, a `private[runtime]` `AtomicReference[Option[UIO[Unit]]]` in the companion object, initialized to `None`; `runPlan` evaluates one extra step between the emission and `planAttempt(...).onExit(...)`: `AgentLoop.planWindowSuspension.get().getOrElse(ZIO.unit)`. With no trigger installed every production run executes a literal `unit` — inertness is asserted by the new spec. This is not a public API change (module-private).
2. **Red-first proof**: new `AgentLoopPhaseWindowSeamSpec` parks the run at the seam (`Promise.await` trigger), delivers an interrupt via the synchronous signal primitive `Fiber.Runtime.UnsafeAPI.interrupt` (verified by bytecode inspection to delegate to `tellInterrupt` — enqueue without awaiting), and only then releases the seam. The strict release-after-enqueue ordering makes the window entry deterministic (no executor interleaving can arm before the signal). On the seam-only tree the run dies inside the window: `5/5 red`, all with the exact pairing violation `lastTag = "phase_started:plan:ReadOnly"` ≠ `"phase_finished:plan"`.
3. **Defense-in-depth mask (commit `8916f6d`)**: the emission, the seam, and the `onExit` arming now run inside `ZIO.uninterruptibleMask { restore => ... restore(planAttempt(...)).onExit(...) }`. A signal delivered inside the span is held until the first interruptible checkpoint after arming, so a started phase always reaches its `phaseFinished` event. The mask delays, it does not swallow: the probe asserts `!exit.isSuccess` (the run still fails with the interruption) in the same assertion set that asserts `phase_finished` arrived. Result: `5/5 green`, whole suite each run.
4. **Revert-probe detection**: the red test remains in the tree permanently; reverting the mask makes the probe fail (proven bidirectionally by the two series above).

Not claimed as a fix for any observed field failure: RAI-234's campaign was a no-repro; this is the defense-in-depth candidate that record proposed, landed with the deterministic trigger that record said was missing.

## Limitations / blockers

- **Defense-in-depth, not a field-bug fix.** The mask hardens a source-plausible window that has one historical red (RAI-225) and one 32-run no-repro campaign (RAI-234). No field failure is claimed fixed.
- **In-JVM seam only.** `planWindowSuspension` is a static in-process hook; processes that do not share the JVM (e.g. `Rai216BoundedFinalizationSpec`'s spawned children) are structurally unaffected — verified by the guard run staying green.
- **Mask span is minimal but not zero-width.** The emission and arming run uninterruptibly (microseconds, synchronous deque add + finalizer registration); a pathological blocking inside `ev(...)` publication would now delay interruption by that duration. Test 2 (post-arming kill within 15 s) bounds this observationally.
- **Sibling-suite overlap:** `AgentLoopPhaseEmissionSpec`/`AgentLoopPlanModeSpec` never arm the seam; their 10 s `waitFor` tolerances are untouched by the brief `unit` seam step (parity 24/24 confirms).
- **Lane worktree needed bootstrap before gates could pass:** the first two `QUALITY_EXECUTE=1` attempts failed on `compile-fixtures` (exit=21, "missing artifacts/tools/m2/.../scala-library-3.9.0.jar — run scripts/bootstrap.sh") and 17 `raiderCli` specs (`IllegalStateException: missing pinned jar`), all one root cause: this fresh worktree's gitignored tool store was unprovisioned. Provisioned via `scripts/bootstrap.sh` (offline m2 copy from the root checkout's store + toolchain download); both gate commands then passed without any product change. Failed-run manifests retained for transparency: `20261030-094125-62163-0001` (missing m2), `20261030-102414-76743-0001` (missing toolchain jar).
- Run logs and baseline logs are gitignored (`*.log`, `artifacts/`); they are retained in the worktree and their decisive excerpts are quoted verbatim in this record. No `evidence/` changes (outside this card's allowed paths).
