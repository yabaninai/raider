## Resulting behavior

Added an independent SDLC acceptance suite and a test-only `ForgePort` adapter that drives `IntegrationWorkflow` against the real `LocalForgeStand` protocol. The adapter records reconcile/mutation order, maps typed outcomes, and uses the pending mutation's stable operation ID when reconciling uncertainty. Integration success exercises commit → PR creation → PR status → merge; injected stale-ref, conflict, duplicate, timed-out-uncertain, and unknown-result outcomes stop the workflow with typed non-success. Both uncertainty cases are reconciled read-only; an immediate blind retry is refused by the stand and the integration workflow issues no retry.

The verifier also maps and repeats the actual stage/evidence, approval, launcher, in-memory stand, and disposable-Git suites. The launcher case observes the approval request artifact and exit 25, then tests a fresh invocation with a decision, candidate drift, and expiry. No production API or runtime implementation was added.

Independent verification found that `IntegrationWorkflow` collapses `TimedOutUncertain` to `IntegrationOutcome.Unknown`, losing the distinction explicitly present in the typed outcome taxonomy and ADR-030 §4.2. The local adapter preserves the stand's response; no production fix was made because it is outside this card's adapter scope. The acceptance assertion remains red pending a separately scoped integration fix.
