  - slot-пулы = bounded ZIO-Queue (fair FIFO; interrupted take не теряет permit);
  - порядок приобретения §6: queue-capacity/eligibility → permit (deadline во
    время ожидания → `DeadlineExceeded`, queued job отменяется, не висит) →

## Исправленные в ходе карточки реальные дефекты

1. Sticky-interrupt ZIO 2: accounting-продолжение после `.exit`-ловли
   прерывалось на первом suspension → перенесено в bracket-release
   (гарантированная финализация). Промежуточный вариант с daemon-work fiber +
   `work.interrupt` в финалайзере давал hang на Promise-based use — заменён на
   bracket+Ref (observed) без дополнительных fibers.
2. Unpriced-резервация без записи в `records` → settle падал InputValidation;
   unpriced-попытки теперь settle-able, observed usage пишется.
3. Тест maxChildren: при llm=1 второй op честно блокируется на слоте ДО
   maxChildren (порядок §6) — тест исправлен (llm=2), семантика кода верна.

## Non-goals / obligations (честно)

- Cross-process distributed hard cap — вне карточки (§7); gateway billing lag
  не устраняется локальным ledger.
- Проверка «fair admission между roots» — FIFO очереди ZIO задокументирована,
  выделенного теста нет (обязательство RAI-010/017 при реальном fanout).
- Профили карточки `performance` — milestone obligation: в registry нет такого
  профиля (RAI-004 stage-aware); gate-инвентарь не расширялся без отдельной
  карточки (не выдумывать гейты).
- Смешанный provider-root покрыт на уровне ledger (разные amounts в одном root,
  тест exact-sums); wire-уровень появится с RAI-011/013.
