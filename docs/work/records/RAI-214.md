## Resulting behavior

Launcher-side manifest digest verification for `chat-portable-export-manifest-v1` bundles, as a pure additive DSL component. New public API `raider.dsl.portable.PortableBundleVerifier`:

- `detectForDocument(documentPath): Option[PortableBundlePaths]` — engages the bundle contract iff a sibling `<stem>-manifest.json` exists (`manifestNameFor`: `X.workflow.json` → `X-manifest.json`); plain documents are unaffected.
- `verifyBundle(bundle): Either[PortableBundleRefusal, PortableVerifiedBundle]` — verifies BEFORE any lowering that (1) the manifest parses against the frozen closed schema via the existing `PortableChatExport.validateManifest` (zero schema drift), (2) both declared entries exist as regular files with `NOFOLLOW_LINKS`, (3) recomputed sha256 over the actual disk bytes equals the manifest pins (constant-time compare via `MessageDigest.isEqual`), (4) the directory closes the bundle exactly (extras refuse typed), within bounds (`MaxBundleEntries = 16`, `MaxManifestBytes = 65536`). Success returns the verified bytes and recomputed digests so the future launcher lowers exactly what was pinned (closes the verify→lower read window). All refusals are typed (`PortableBundleRefusal` cases with stable `code`s) and convert via `toRaiderError` to `RaiderError.InputValidation("CWF-R1: …")`, matching the export-side error channel.

Tampered, missing, extra, non-regular, oversized, or over-full bundles refuse typed with no lowering work performed (order asserted by tests). Valid published bundles (produced by `PortableChatExport.exportTo`) verify green unchanged.

Scope decision (strict boundary): RAI-211 explicitly owns `modules/cli/src/main/scala/raider/cli/portable/PortableRun.scala` and RAI-212 owns `raider/cli/portable/**` this wave, so the PortableRun wiring is deferred to avoid a three-way merge on `PortableRun.scala`. The ready one-call seam is: `detectForDocument(path)` → `verifyBundle` → `PortableWorkflowValidator.validate` + `PortableWorkflowLowerer.lower` on `PortableVerifiedBundle.documentBytes`/`inputExampleBytes` (never re-read from disk). The card's `raider/cli/workflow/**` grants are intentionally unused: no legitimate seam exists there and inventing one would violate the card non-goals.

## Limitations / blockers

- **sbt-test gate gap (contention, not code):** the full multi-module `sbt --batch test` gate hit its 900 s cap twice consecutively while 8+ lanes compiled concurrently (load average 122–148). Per the card contract this is recorded instead of looped. Compensation: the card's module suite (`raiderDsl/test`, 167 tests) passes standalone on the final sources; the integrated candidate still owes a full multi-module sbt-test pass at merge time.
- **TOCTOU boundary:** `verifyBundle` returns the verified bytes and digests so the caller lowers exactly what was pinned; drift of on-disk files after `verifyBundle` returns is inherent and out of scope by design (the launcher must consume the returned bytes, and the wiring note says so explicitly).
- **Symlink policy:** entries must be regular files read with `NOFOLLOW_LINKS`. A dangling symlink is refused typed as `EntryNotRegularFile` on platforms where NOFOLLOW attribute reads report the link itself (macOS), or `EntryMissing` where nothing backs the name; the spec accepts both as honest refusals and the contract is "never verifies green".
- **Bounds:** >16 directory entries (including dotfiles/fillers) refuse `bundle-too-large` before any reads; manifests over 65536 bytes refuse before parsing. These are component-level guards, not a sandbox.
- **Environment note:** `scripts/bootstrap.sh` fails on this host with the PATH `python3` (Homebrew build without CA bundle); the identical pinned invocation succeeds with `/usr/bin/python3`. Worth a follow-up note for the bootstrap owner; artifacts are gitignored so every fresh worktree needs this once.
