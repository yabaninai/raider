# RAI-210: work record

Status: done. Date: 2026-10-26. Baseline commit/source: `lane/rai-210` @ `b90a191`.

## Resulting behavior

FCI-REPORT-02 post-run artifact integrity is now truthfully checkable against any
headless run directory via a new additive CLI subcommand
`verify-artifacts <run-dir>` (dispatched through `CliArgs.parse` →
`HeadlessRunner.run`, RAI-109/RAI-129 precedent; `raider/cli/Main.scala` is NOT
modified — `outcome.result = None` keeps Main silent on this path).

Semantics (`ArtifactIntegrityCommand`):

- Reads `artifacts.json` (writer: `CiReport`, and per-run writes in
  `WorkflowRun.scala` — both referenced, not modified). Manifest
  missing/unreadable/malformed → typed refusal, never a fabricated pass.
- Required-set coverage check: `run.json`, `result.json`, `events.jsonl`,
  `checks.junit.xml`, `summary.md` (the ci-runtime §7 required set;
  `artifacts.json` itself is self-excluded from the manifest set).
- Per listed entry, in sorted path order, exactly one typed problem:
  path escape (via `CiReport.safeRelativePath`) > missing file > size
  mismatch > sha256 mismatch (re-hash mirrors the writer's lowercase-hex
  format; `DuplicateEntry` and `EntryUnreadable` close the typed set).
- Listed-but-unverified extras (e.g. the best-effort `transcript.json` the
  runner writes and lists) are verified when listed; unlisted extra files are
  deliberately not policed (documented scope, see Scaladoc).
- Exit codes (frozen §8 codes only): 0 = verified (stdout:
  `artifact-integrity: verified <runDir>` + `entries: N (...)` + `bytes: N`);
  27 (`ExitCodes.ArtifactWriteFailure`) for ANY typed integrity refusal
  (stderr: `typed-error: <message>` lines + `exit 27: artifact-write-failure`);
  21 for usage errors (ReplayCli/ResumeCommand precedent). No exit-code or
  gate-policy changes.

The command is a read-only consumer; the run directory is never written.
