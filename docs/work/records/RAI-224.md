under controlled concurrent-lane load on the production host and delivered the calibration evidence
the owner requested for the wave-A follow-up 5 raise-or-dedicated-gate-host decision: 25 isolated

(hardware context, exact commands, per-build calibration table, contention curve, failure
inventory, recommendation). No product, build, registry, or policy change: the `sbt-test` budget
stays 1800 s; the registry was not touched.

Headline results (wall duration of the timed `sbt --batch test`, seconds): base n=1 → 1064;
tier 4 → 1901/1921/1931 (all four OVER the 1800 s budget, running inside an ambient neighbor storm,
1-min load median 158); tier 8 → 1131/1146/1161 (n=7, all within budget); tier 12 →
1253/1482.5/1489 (n=10, all within budget, max = 83% of budget). Peak total java RSS 25.2 GB of
128 GiB, zero OOM — memory never bound; host load peaked at 229 on 18 cores. 9 of 22 full builds
had timing-suite failures confined to the documented load-sensitive families
(`OutboundSpec`, `ProcessApiAcceptanceSpec`, `MultiJobExportSpec`, `ChatWorkflowVerifierE03Spec`).
A previously unrecorded failure mode surfaced: 3 builds at ≥8-way concurrent COLD compiles died with
the identical false compile error `AgentLoop.scala:772: value id is not a member of
raider.core.ToolCall`; proven zinc-state poisoning (byte-identical sources and outputs vs healthy
copies; all three copies compile green after `sbt clean`; 0 occurrences at ≤4-way), self-healing.

Recommendation stated in the research note (recommendation only, per card non-goals): the binding
variable is TOTAL host load, not gate-lane count; at ambient ≤ ~100 the budget holds to 12
concurrent builds; at ambient ≳150 even 1–4 builds breach it and no raise absorbs that regime —
dedicated gate host (or load-aware sbt-test admission, defer above 1-min load ~100) is the primary
recommendation; keeping heavy lanes ≤8 with the current budget is validated for the calm-to-
moderate regime.

## Limitations / blockers

- Single host, single sbt/JDK pin; ambient neighbor load was NOT controllable and is only recorded
  (per-tier min/median/max), so tiers confound own-load with ambient; tier 4 has no calm-window
  datapoint (no calm window existed during the session). The baseline is n=1. Each build ran once —
  no within-tier variance estimate. Claims are strictly scoped to this host/toolchain (research
  note §7.5).
- Measurement runs let over-budget builds FINISH (recording true overruns, e.g. 1901–1931 s) while
  the real gate would kill at exactly 1800 s and classify failed — classification equivalence is
  `run_gate`'s documented timeout semantics, not a replicated kill.
- The zinc-poisoning root cause inside zinc's incremental state is localized but not root-caused to
  a specific zinc mechanism; flagged as a candidate follow-up card (reproduce in isolation).
- Test logs and per-build artifacts live in the session temp dir (hashes pinned in research note
  §8); the temp dir is session-scoped — the note and this record carry the durable values.
- The measured tree is `1351538` (product inputs); this card's docs-only delta does not change
  product inputs, so the calibration remains valid for the integrated candidate at acceptance.
