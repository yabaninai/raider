## Resulting behavior

The product host for the accepted `raider.ui.TabShell` lives in the REPL product module:

- `raider.repl.TabShellHost` (product wiring, ~70 lines): `wiring` builds the
  ADR-024 seam (EventHub + SessionRegistry, RAI-057); `run` starts
  `ShellTerminal.jline` (terminal belongs to the shell — sole `printAbove`
  writer), `CloseChoiceResolver.fromTerminal`, and `TabShell.run` until
  `:quit`/EOF. Aux seam is connected WITHOUT a LineageTab provider (TabShell
  defaults: `views = ShellViews.detached`, `aux = None` — `:aux` gives a
  typed hint). ChatLoop (`modules/cli/chat`) is untouched; raiderCli's
  headless rule is not violated (quality-gates §12 package smoke unaffected).
- `raider.repl.TabShellHostPtyApp` (test-scope PTY harness) hosts exactly
  the product wiring plus a test feeder, publishing a synthetic runtime
  stream (1 JobStatusChanged → Running + 220 Diagnostics per tab) through the
  REAL hub (ADR-024, no bypass), plus an atomic report (read model registry:
  draft/status/lastSeq/unread/scrollback/feedDone, hub drops) as the driver
  oracle. Before starting the shell it sets PTY size with `stty` on its own
  stdin (script-run PTY starts at 0x0; without this, JLine redraws degrade).
- `raider.repl.TabShellHostPtySpec` (Scala PTY driver + 3 fixtures): child JVM
  with harness runs under `/usr/bin/script -q /dev/null` (BSD utility performs
  openpty+setsid+dup2(slave,0/1/2)+exec), master is relayed through pipes; the
  driver answers JLine capability requests (Primary/Secondary DA, mode-2027,
  kitty, XTVERSION — parity with `scripts/quality/tabs_pty_probe.py`), strips
  ANSI from the transcript, and polls the report. No new dependencies, no
  Python, and no mocked shell: the real product TabShellHost runs under PTY.

## Limitations / blockers

- Transcript atomicity is evaluated on the final cleaned transcript (an erased
  and redrawn JLine break is not detected separately) — same limitation class
  as accepted in the RAI-062 probe.
- Capability queries are answered per read chunk (a query split across chunks
  would go unanswered, costing only JLine fallback delay); Ctrl+C/resize are
  outside P2W scope (covered for the same shell by PTY-02 RAI-062 in the
  freezes module; this lane does not duplicate them).
- Driver uses `/usr/bin/script` (darwin/BSD): it performs openpty/dup2/setsid.
  Linux would use the same path (`util-linux script`); the CI mode “packaged
  raider repl --mock” (quality-gates §163) does not use this harness — this is
  component-stage acceptance.
- `artifacts/tools/m2` (+`cp-*.txt`) were copied into the worktree from root
  (untracked, §1a) to satisfy compile-fixtures gate; they are not committed.
- `docs/lineage.md` §9.2 (“TabShell wiring in product REPL”) is updated outside
  this lane's allowed paths by the coordinator on merge (gap closed by this
  slice: product domain = `raider.repl.TabShellHost`).
- Connecting TabShellHost to the user entry point (Main.ttyLoop / chat cycle)
  is the next step for consumer cards (RAI-103+ drafts, etc.); this card provides
  wiring base and PTY acceptance as specified in scope.
