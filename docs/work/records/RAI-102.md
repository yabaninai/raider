   `raiderRepl.dependsOn(..., raiderUi % "compile->compile;test->test")`
   — без циклов (raiderUi зависит только от raiderRuntime, который repl
   уже имеет; JLine-версии совпадают 4.0.14, конфликтов нет).
2. Решить wiring home карточки. Текст карточки/lineage §9.2 указывает на
   `modules/cli/chat` (ChatLoop), но:
   - build.sbt закрепляет «raider-cli ... NO compiler/JLine (headless
     distribution rule)», а docs/quality-gates.md §12 делает package smoke
     «отсутствие compiler/JLine в headless classpath» — JLine-shell внутри
     raiderCli сломает protected gate и headless-дистрибуцию;
   - raiderCli вообще не имеет JLine-депа.
   Рекомендация: продуктовым домом TabShell-wiring назначить
   `raider.repl` (интерактивный продуктовый REPL, JLine уже в classpath);
   ChatLoop в cli/chat остаётся JLine-free. Принцип карточки «владение
   терминалом у shell, а не у ChatLoop» применяется к консольному циклу
   `raider.repl.Main` (ttyLoop) аналогично.
3. После edge: план среза (следующий ready-шаг lane) —
   a) PTY-drivable хост продукта в test-scope `raider.repl` (образец:
      TabShellPtyApp, БЕЗ импорта test-классов в product code) +
      продуктовый wiring `raider.repl.TabShellHost` (shell владеет
      терминалом; сессии = JobManager/EventHub seam ADR-024; aux-seam
      provider без LineageTab-подключения);
   b) PTY-прогон P2W-01 (A→B→A байт-в-байт), P2W-02 (typed error),
      P2W-03 (burst/один writer/редактируемый prompt) по подходу
