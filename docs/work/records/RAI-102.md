## Resulting behavior

Продуктовый хост принятого raider.ui.TabShell живёт в product-модуле REPL:

- `raider.repl.TabShellHost` (product wiring, ~70 строк): `wiring` строит
  ADR-024 seam (EventHub + SessionRegistry, RAI-057); `run` поднимает
  ShellTerminal.jline (терминал принадлежит shell — единственный writer
  printAbove), CloseChoiceResolver.fromTerminal и `TabShell.run` до
  `:quit`/EOF. Aux-seam подключён БЕЗ LineageTab-провайдера (дефолты
  TabShell: `views = ShellViews.detached`, `aux = None` — `:aux` даёт
  typed hint). ChatLoop (modules/cli/chat) не тронут; headless-правило
  raiderCli не нарушено (quality-gates §12 package smoke не задет).
- `raider.repl.TabShellHostPtyApp` (test-scope PTY harness): хостит ровно
  продуктовый wiring + тестовый фидер, публикующий синтетический
  runtime-поток (1 JobStatusChanged → Running + 220 Diagnostics на таб)
  через РЕАЛЬНЫЙ hub (ADR-024, без bypass), + атомарный report (read
  model registry: draft/status/lastSeq/unread/scrollback/feedDone, hub
  drops) как оракул драйвера. Прежде чем поднимать shell, ставит
  размер PTY через `stty` на собственном stdin (script-run PTY рождается
  0x0 — без этого JLine-редрау деградируют).
- `raider.repl.TabShellHostPtySpec` (Scala PTY driver + 3 fixtures):
  дочерний JVM с harness'ом запускается под `/usr/bin/script -q /dev/null`
  (BSD-утилита сама делает openpty+setsid+dup2(slave,0/1/2)+exec), master
  релеится через pipes; драйвер отвечает на capability-запросы JLine
  (Primary/Secondary DA, mode-2027, kitty, XTVERSION — parity с
  scripts/quality/tabs_pty_probe.py), ANSI-чистит транскрипт, опрашивает
  report. Никаких новых зависимостей, никакого Python, никакого мока
  shell: под PTY работает настоящий продуктовый TabShellHost.

Acceptance (P2W-01..03) — реальные PTY-прогоны продуктового хоста:

## Limitations / blockers

- Транскрипт-атомарность оценивается по финальному cleaned-транскрипту
  (стерёзанный и перерисованный JLine разрыв отдельно не детектируется) —
  тот же класс limitation, что принят в RAI-062 probe.
- Capability-запросы отвечаются per-read-chunk (запрос, разрезанный
  между chunk'ами, остался бы без ответа — стоил бы только fallback-задержку
  JLine); Ctrl+C/resize вне scope P2W (для того же shell покрыто PTY-02
  RAI-062 на freezes-модуле; этот lane их не дублирует).
- Драйвер использует `/usr/bin/script` (darwin/BSD): сам делает
  openpty/dup2/setsid. На Linux путь был бы тем же (`util-linux script`);
  в CI-режиме «packaged raider repl --mock» (quality-gates §163) харнесс
  не участвует — это component-stage acceptance.
- artifacts/tools/m2 (+cp-*.txt) скопированы в worktree из root
  (untracked, §1a) — требование гейта compile-fixtures; в git не попадают.
- `docs/lineage.md` §9.2 («TabShell-wiring в product REPL») обновляется
  вне allowed paths этого lane — координатором на merge (gap закрыт этим
  срезом: продуктовый дом = raider.repl.TabShellHost).
- Подключение TabShellHost в пользовательский вход (Main.ttyLoop / chat
  цикл) — следующий шаг карточек-потребителей (RAI-103+ drafts и др.);
  эта карточка даёт wiring base и PTY-приёмку, как и прописано в scope.
