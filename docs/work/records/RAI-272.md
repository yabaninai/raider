# RAI-272: work record

Status: done. Date: 2026-11-02. Baseline commit/source: `4c01934` (branch `lane/rai-272`, worktree `artifacts/lanes/rai-272`).

## Resulting behavior

The five pinned-dotc compile suites no longer share module-local fixed working
directories. Each suite now writes all compile artifacts into its own
per-suite directory `modules/cli/target/suite-work/<Suite>/`, produced by the
new test-scope helper `raider.cli.testkit.SuiteWorkdir.forSuite(module,
suite)`; the directory is recursively deleted and recreated on first use per
test JVM. Migrated suites: `LineageCompileGateSpec`,
`UnifiedProjectionExecutionSpec`, `LineageProjectionExecutionSpec`,
`LineagePlainRunCompileGateSpec` (all four previously shared
`modules/cli/target/lineage-compile/` — the esc-hostile pair coupling cited in
RAI-266 §1e) and `ChatWorkflowCompileGateSpec` (previously fixed
`chat-workflow-compile/`). Suite plumbing (`findAncestor`, `m2Jar`,
`compilerClasspath`, `writeRender`, `dotc`, `freshDir`) is otherwise
unchanged; only each `compileDir` lazy val and the affected doc comments
changed. The historical shared dirs are no longer written by any suite.

The RAI-266 execution stance is unchanged (`Test / parallelExecution := false`
in `build.sbt`); this card only removes the structural coupling a stance
re-evaluation would have to care about. `docs/parallel-development.md` §1e
gains an update paragraph naming the migrated suites, the remaining fixed
paths with their single-writer safety argument, and amended lane guidance.

## Limitations / blockers

- The first `quality-changed QUALITY_EXECUTE=1` attempt failed: the helper's
  initial wipe was non-recursive (copied the suites' `freshDir` pattern, which
  only works because dotc emits flat class files into `out-<tag>/`), so a
  suite dir holding non-empty `out-<tag>/` leftovers from an earlier test JVM
  made `forSuite` throw `DirectoryNotEmptyException` inside `writeRender`'s
  try block. The pre-gate manual run had passed only because the dir was
  purged beforehand — happy-path validation, insufficient; the repeat-with-
  leftover-state runs are now part of the evidence. Both failing and passing
  manifests are kept under `artifacts/quality/` as the honest record.
- Execution stance intentionally unchanged (`parallelExecution := false`);
  enabling free suite concurrency remains a separate card with its own
  stance probe and budget/cancellation evidence.
- Runtime module fixed dirs (`lineage-replay-*`, `*-corpus-spec`) were left
  in place: each is suite-exclusive (single writer), so they are outside the
  hazard class this card removes; migration was judged unnecessary churn.
- Probe-based serial-stance evidence is transient (temporary suites, removed
  before gating); the durable evidence is the gate `sbt-test` pass over the
  migrated tree.
- `modules/cli/target/**` (including `suite-work/`) is gitignored; the
  per-suite dirs are build output, not committed content.
