## Resulting behavior

Two review findings of RAI-124 are fixed inside `modules/repl/**` only:

1. **PTY oracles de-tautologized (TYPED-01).** `TypeCommandsPtySpec` no longer
   accepts a pre-saturated answer. The old oracles
   `bindingType=waitFor("Long")` and `jobType=waitFor("JobHandle[String]")`
   passed on the ECHO of the previous steps (`val counter: Long = 7L`,
   `val j: ...JobHandle[String] = ...`) before `:type` was even sent. Every
   `:type` oracle now goes through `PtySession.sendAndWaitAnswer`: (a) send the
   query; (b) wait for the anchor — the query's own echoed line, text that
   cannot exist before the send; (c) require the answer strictly AFTER the end
   of the LAST anchor occurrence. The binding reprs of earlier steps always sit
   before the anchor and can never satisfy the oracle. The usage oracle uses
   the same positional form with the prompt-adjacent anchor (`raider> :type`).
   The count-based `waitForCount`/`countSubstr` helpers became redundant and
   were removed; the plain echo oracles of the just-sent `val` lines (`bound`,
   `jobStarted`) are kept as binding probes.
2. **Honest compile-error prefix for type queries (TYPED-02).**
   `Commands.handle(":type …")` renders a compile error through the new pure
   `Commands.compileErrorText(msg, typeQuery = true)`: the full honest compiler
   diagnostic verbatim, with no misleading `command failed (prelude broken?)`
   prefix (a type query compiles the user's expression against the live
   session — a failure is the expression's own problem). The stateful facade
   commands (`:jobs`, `:cancel`, `:log`) keep the legacy prefix via
   `typeQuery = false` — their generated `ReplCommands.print*` sources really
   can fail because of a broken prelude, so the existing semantics of all
   other commands is unchanged (`Main.printCaptured` untouched). A global
   `!text.contains("prelude broken")` assertion was added to the PTY scenario.

Non-goals respected: no compiler-layer changes (`modules/repl-engine`
consumed as frozen `ReplEngine.eval`), no new commands, chat module untouched,
oracles TYPE-01..03 not weakened (made strictly stronger).

## Limitations / blockers

- No paid calls, no network: PTY/unit fixtures use the scripted/mock backend;
  no provider credentials read (env kept clean in the PTY launcher).
- The positional oracles rely on the observed transcript shape: JLine renders
  the typed line contiguously (`raider> :type counter`), confirmed on all runs
  (×3 positive + negative + pre-fix). A JLine/terminal change that breaks
  input echo would fail these oracles loudly (anchor timeout), not silently.
- `artifacts/` is gitignored: PTY evidence and gate manifests are lane-local
  on disk under this worktree and referenced here by path+sha256; the
  integrated candidate needs its own verification at merge (lane evidence does
  not rebind to the merged tree).
- The legacy `prelude broken?` prefix of `Main.printCaptured` (W10 shell
  commands) and `Commands.compileErrorText(_, false)` is intentionally kept —
  out of card scope; semantics of non-type commands unchanged.
