## Assessment

Raider now contains a native Scala 3 + ZIO agent loop and a usable set of real coding tools; the old “no product runtime” status in the plan is historical. This is substantial implementation, not evidence that W02–W14 are accepted. This lane ran no builds, tests, provider requests, or acceptance scenarios. The test files and work records below are inspected historical evidence only.

The native loop in `modules/runtime/src/main/scala/raider/runtime/loop/AgentLoop.scala` dispatches normalized model requests, only executes complete tool calls, sends tool results back by ID, bounds attempts, and validates final text. `modules/cli/src/main/scala/raider/cli/run/HeadlessRunner.scala` wires `raider run --agent coder` to the configured backend, workspace-rooted tool registry, and shared admission; `modules/cli/src/main/scala/raider/cli/chat/ChatLoop.scala` provides a separate interactive chat/task surface using the same AgentLoop. `modules/tools/src/main/scala/raider/tools/CodingToolset.scala` wires real `fs_read`, `fs_search`, `proc_run`, `fs_edit`, `fs_patch`, and `fs_tree` tools. Workspace containment, output bounds, argv execution, and hash preconditions are implemented in these tool classes. These are actual paths, not just planned APIs.

The runtime has meaningful job ownership, cancellation, scopes, admission, and accounting: `JobManager` owns job fibers and idempotent await; `RaiderScope` tracks children/finalizers and reports uncertain cleanup; `Admission` and `BudgetLedger` serialize admission and maintain exact local money reservations/settlement. Model-callable delegation is wired into the headless coder path. Chat persists messages and turn metadata, compacts long histories, and supports reopen. The compositional DSL has a common `Program`/`Task` interpreter and typed `andThen`, `all`, and bounded `batch` composition. These implementations make the project materially beyond a prototype, while the gaps below prevent broad readiness claims.

## Prioritized findings and acceptance gaps

1. **High — delegated live child calls are sent with a scripted model name.** `DelegationToolset.delegateInvoke` constructs each child loop with `s"scripted:${args.agent}"` (`modules/runtime/src/main/scala/raider/runtime/delegate/DelegationToolset.scala:181-189`). `AgentLoop` uses its `model` field as `ModelRequest(model, ...)` (`modules/runtime/src/main/scala/raider/runtime/loop/AgentLoop.scala:511`); the production headless parent instead receives `args.model` (`modules/cli/src/main/scala/raider/cli/run/HeadlessRunner.scala:719-733`). The local OpenAI-compatible test stand explicitly recognizes `scripted:` as the child route (`modules/cli/src/test/scala/raider/cli/run/CoderDelegationRunSpec.scala:68-101`), so that test proves scripted delegation/export, not that live delegated children use the configured model. Thread a valid, explicitly selected child model/profile through the wiring and add a provider stand assertion for the child request model before treating W09 as live-capable.

2. **High — the coding-agent tool surface does not expose all W03 operations.** The registered tool list is six tools (`CodingToolset.scala:59-63`); `fs_patch` accepts one path and calls the single-file `PatchTool.apply` (`CodingToolset.scala:141-152`), which applies hunks to an existing file and writes it back (`PatchTool.scala:30-52`). `PatchTool` separately implements multi-file `applyAll`, including create/delete sections (`modules/tools/src/main/scala/raider/tools/files/edit/PatchTool.scala:160-194`), but the coding registry does not expose it. No structured delete tool is registered. `proc_run` can invoke arbitrary workspace commands, but that does not supply W03's explicit filesystem-tool deletion contract. Therefore multi-file patch/delete acceptance remains unestablished through the agent tool API. Expose and contract-test the needed operations with explicit partial-failure semantics.

3. **High — explicit token/time limits are not aggregated across the native coder runtime.** This is not a product-wide absence: portable launch intersects declared `tokens`/`deadlineMs`, wraps the shared backend in `TokenBudgetBackend`, and enforces the outer deadline (`modules/cli/src/main/scala/raider/cli/portable/PortableLaunchPolicy.scala:29-36,75-90`; `PortableRun.scala:515-520,548-590`). The portable token wrapper accumulates observed wire usage and refuses subsequent dispatch after the ceiling (`TokenBudgetBackend.scala:32-61`); inspected tests cover the envelope/policy and real-process deadline scenarios (`TokenBudgetBackendSpec`, `PortableLaunchPolicySpec`, `PortableParitySpec`). Headless bundle runs also have `--deadline` (`modules/cli/src/main/scala/raider/cli/run/HeadlessRunner.scala:778-799`), but the CLI explicitly restricts that flag to bundle runs (`modules/cli/src/main/scala/raider/cli/run/CliArgs.scala:330-334`). By contrast, the headless `--agent coder` path sets only concurrency/attempt limits (`HeadlessRunner.scala:676-678`), uses `Unknown` cost estimates (`HeadlessRunner.scala:729-736`), and has no shared token or elapsed-time ceiling in `BudgetLimits` (`modules/runtime/src/main/scala/raider/runtime/budget/BudgetLedger.scala:36-44`). W14 therefore remains open for aggregate native agent/coder roots and children, not for portable launch or bundle deadline support. Add root-level aggregation/enforcement for that path and keep unknown cost honestly unpriced.

4. **Medium — W07 context and W08 session acceptance are partial.** The coder prompt tells the model to read files and describes the tools (`modules/cli/src/main/scala/raider/cli/CoderPrompts.scala:11-36`), but the inspected headless coder wiring supplies that static prompt and workspace tools, with no project-instruction/profile precedence or provenance-aware context assembly visible in that path (`HeadlessRunner.scala:680-747`). Chat persistence stores messages and turn/check metadata (`modules/cli/src/main/scala/raider/cli/chat/Session.scala`); it is not a serialized resumable runtime job journal, and arbitrary active work/child handles are not restored by this session store. W07 provenance/context tests and W08 multi-turn goal/tool-ID, journal/archive/reopen, bounded non-replaying recovery acceptance remain necessary.

5. **Medium — DSL and SDK surfaces exist in slices, not as the complete target.** `Program`/`Task` and `all`/`batch` are implemented, and compile positive/negative fixtures exist. `ReplSession` exposes run/ask/start and a real compiler implementation exists in the REPL modules. However, runtime scopes/delegation and REPL facade operations are not interchangeable evidence that all W11 golden scenarios (typed codecs/checks, scope/fork/join semantics, steering/cancellation) compile and run in the real installed loop. Plugin support is more than a descriptor/hook stub: `PluginLoader.load` loads a plugin entry and manifest-declared `raider.core.Tool` implementations through `ServiceLoader` and validates declared/provided tool parity (`modules/core/src/main/scala/raider/core/plugin/loader/PluginLoader.scala:167-233,308-344`); `PluginCli` manages the installed artifact catalog, and lifecycle hook discovery/dispatch exists. The limitation is narrower: the inspected headless coder assembly wires `CodingToolset` plus delegation tools, not the installed plugin tool registry (`HeadlessRunner.scala:687-718`); profile capabilities are preflight metadata, not executable profiles in this loader slice. Thus W13's example of connecting and executing a custom tool plus agent profile through the public SPI is not established by the available loader/tool SPI alone. `SdlcStages` validates descriptions and composes supplied handlers in one Program (`modules/core/src/main/scala/raider/core/sdlc/SdlcStages.scala:184-230`); it is not evidence of automatic commit/PR/merge under the separate SDLC contract.
