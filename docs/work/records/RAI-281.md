## Limitations / blockers

- Malformed-changelog rejection is proven on temp fixtures and the gate's embedded self-test (which also proves the repository file is lint-clean), not by mutating the real `CHANGELOG.md` — its content is owned by release cards (RAI-279 fold) and the card forbids changing it. In production the gate lints the repository file; a malformed tree fails the docs battery with the typed diagnostics shown.
- The first full-lane run failed `compile-fixtures` (exit 21, missing vendored toolchain jar). Root cause: lane worktrees do not inherit the untracked `artifacts/tools/m2` store, and `bootstrap.sh m2 --source` provisions only the 31 pinned consumer-closure artifacts, while `scala-library-3.9.0` belongs to the pinned REPL-toolchain jar set. Remediated per the runbook (copy the whole store; byte-identical jar verified). A missing tool was treated as not-a-pass and the battery rerun to green. Suggested follow-up for the runbook owner: state that fresh worktrees should copy `artifacts/tools/m2` wholesale (or run `bootstrap.sh all`) before JVM-dependent batteries — `m2 --source` alone is insufficient for `compile-fixtures`.
- Old manifests claiming the `docs` profile fail completeness if re-verified against the new policy (docs battery grew). This is expected growth, disclosed in the module docstring and `docs/quality-gates.md` §1a; lane evidence is not transferred — final acceptance re-checks the integrated candidate.
- Gate-policy class: integration (merge to the mainline) is gated on independent review plus owner ratification per the RAI-275 precedent; this lane does not merge, push, or flip board/card status (coordinator-owned).
- The registry `path_profiles` alternation is order-sensitive by design of the classifier (`^CHANGELOG.md` added to the existing docs alternation; `scripts/**`-style precedence conflicts do not arise for the changelog path).
