# RAI-144: work record — multi-job lineage export: delegate children join one events stream with provenance

Status: implemented on the lane branch, acceptance green, independent review
pending. Date: 2026-10-13. Lane: `lane/rai-144`, worktree `wt/rai-144`.
Baseline: `068f4a3` (current main HEAD at lane start, clean status verified).

## Resulting behavior

Delegate CHILD jobs now join the RUN's single `events.jsonl` with the ADR-032
correlation fields, so the versioned reducer
(`LineageReducer.reduceWire`) builds ONE provenance tree with real
parent-child edges. No edges are invented: the application-owned index
pattern is not an edge source, and a job whose stream never carries the
`Delegated` introduction is never joined.

- **New component `MultiJobExport`** (`raider.cli.run`): the join.
  - *Lossless capture.* The exporter's `capture` listener is composed BEFORE
    `StatusLedger.onTransition` in the JobManager's single `onTransition`
    hook. The hook fires after the committed Queued→Running transition but
    BEFORE the job fiber is forked, so the per-job hub subscription is
    registered before the job can publish anything (complete from per-job
    seq 1). The capture consumer is forked with `.interruptible` (mandatory:
    a bare `forkDaemon` inside the registration's `uninterruptibleMask`
    gives a non-interruptible start and `close` could never settle it —
    found by fixture, this card).
  - *Connection.* A captured job becomes a CHILD SEGMENT when its own stream
    carries `Delegated(childId, agent)` (the `DelegationEvents` convention:
    the fork record is published under the CHILD's id). The exporter assigns
    the invocation-level join key `invocationId` (`inv-<n>`, in join order),
    creates the child's NATIVE per-job artifacts
    (`<workDir>/jobs/<childJobId>/events.jsonl` — the verbatim hub stream of
    that job, frozen v1 lines, readable by the frozen `LineageEventReader`),
    and joins the segment into the run stream as `schemaVersion: 2`
    envelopes with `invocationId` set (`LineagePayload.Frozen` copies).
  - *Canonical fork record.* The joined stream represents the introduction
    ONCE, in the PARENT's stream — a frozen v1 `Delegated(childJobId,
    agent)` envelope with the fork's real timestamp. The child's own copy of
    the fork record stays in the child's NATIVE segment file only (a second
    introduction would be `ReduceError.DuplicateDelegation`). This is the
    parent control edge ADR-032 §1 requires.
  - *Provenance.* When the CAMPAIGN job's Terminal is exported and ≥1
    segment was joined, exactly ONE `run_provenance` record (v2, campaign
    job id, `parentRunId` absent — root run, never guessed) is appended
    immediately before the Terminal, carrying `{kind: "work_dir"}` and
    `{kind: "events"}` pointers to every child segment's native artifacts,
    in invocation order. Pointers resolve to real files (fixture-checked).
  - *Honesty rules.* A fork observed after the campaign Terminal was
    exported connects as a NATIVE-ONLY segment (files complete, nothing
    joins — a post-terminal introduction would be an invented edge or
    `ReduceError.AfterTerminal`). A detached child (no Terminal) exports a
    segment without Terminal → strict reduction refuses typed
    (`MissingTerminal`) → the runner falls back to
    `reducePartialWire` (LIN5-03). A child failure exports its
    `Terminal(Failed)` with correlation and a `Delegation` node in the tree.
  - *Watermark honesty.* `campaignWritten` counts CAMPAIGN hub envelopes
    only; the settled-run wait compares it against the campaign job's hub
    `lastSeq` (the sink's raw line count is inflated by child lines and
    would satisfy before the campaign's own tail landed — found by fixture).
    `drain(budgetMs)` is a bounded best-effort wait until every connected
    segment reached its Terminal (a settled child's tail must land before
    the reduction; a detached child just lets the budget expire).
- **Interleave policy (pinned, also in `MultiJobExport` scaladoc).** Parent
  and child envelopes interleave by EMISSION time at one serialized sink:
  every line is appended under a single export lock — the same semaphore
  that updates the in-memory fold buffer — so the file order and the
  reduction input are always the same sequence, and within a job appends
  follow strict per-job seq order. The exported stream's per-job `seq` is
  the EXPORT-CANONICAL sequence: dense `1,2,3,…` per job in file order. For
  a run without delegation the file order equals the hub's per-job seq
  order, so the export is byte-identical to the pre-existing v1 layout (no
  silent artifact-layout change). The reducer's canonical order IS the file
  order (a pure fold); replay is byte-deterministic (re-reading the file
  re-yields the same fold and the same `GraphHash`), and the hash is
  additionally invariant under the cross-job interleave itself: node ids
  are `<job>:n<seq>`, every edge is within-job or via the parent's
  Delegation node, and the canonical form sorts node lines by `(seq, id)`.
  A torn FINAL line is the honest truncated tail (`LineageWireReader`),
  reduced under LIN5-03 partial semantics.
- **Defense-in-depth (RAI-143 review note, cheap hardening).**
  `ReduceError.InvocationIdOnV1(job, seq)`: the versioned entries
  (`reduceWire`/`reducePartialWire`) refuse a `schemaVersion: 1` envelope
  carrying `invocationId` — the same rule the reader enforces on file
  input — because RAI-144 constructs envelopes directly in code, bypassing
  the reader. Fold validation order updated (version → invocationId-on-v1 →
  unknown parent → missing correlation → seq → after-terminal → payload
  pairing); scaladoc pinned.
- **Runner integration (`HeadlessRunner`).** The run's events sink opens
  before the job layer; the exporter is built over it; the manager listener
  composes capture+ledger. The parent collector routes every campaign
  envelope through `exportParent`; the settled wait is
  `drain() *> awaitCaughtUp(campaignWritten) *> collector.interrupt`; the
  reduction goes through `reduceWire`, falling back to `reducePartialWire`
  ONLY on `MissingTerminal`, reported as the honest summary line
  `- lineage: partial graph <hash>, N node(s) (incomplete campaign;
  checkpoint: events.jsonl)`. Delegation-free runs keep the exact
  pre-existing lines (byte-identical events.jsonl, unchanged summary).
- **`RunLineageArtifacts`.** Takes the exported versioned stream + the
  provenance record; emits lineage-data schemaVersion 2 (top-level
  `provenance`) exactly when the record is present, byte-identical v1
  otherwise. The wave-1 writer convention is kept: delegation nodes carry
  no `dataRef`, so they get no data entry — run-written
  `delegationData.invocationId` entries would need a dataRef convention of
  their own (RAI-146 territory).
- **`EventsJsonlWriter.appendLineage`**: the same locked whole-line
  write+flush discipline for `LineageEnvelope` lines (a v1 envelope encodes
  byte-identically to `append`).

Scope note: the card was assessed for a .a/.b split before coding and kept
whole — the export machinery and its acceptance fixtures share one core
(the join), and the defense-in-depth piece rides the same reducer file, so
no half is independently acceptable. Stated here per the card's split
clause; no child cards were created.

## Limitations / blockers

- The headless CLI product path does not yet WIRE delegation tools into the
  coder agent (which agents a headless run may spawn is an unfixed policy
  surface — `CliArgs`/agent-registry scope, outside this card's allowed
  paths). The export path is fully wired in the runner and exercised
  end-to-end by the scripted fixture; a future wiring card flips it on for
  real headless runs with zero exporter changes.
- The partial summary line (`lineage: partial graph …`) is rendered by
  `HeadlessRunner.writeArtifacts` but not asserted by an automated
  HeadlessRunner-level fixture (reaching it requires a delegation run
  through the product entry — see the previous point); the strict→partial
  fallback logic itself is fixture-covered (MJE-03b/03c).
- Child diagnostics dropped INSIDE the hub never consume a seq (per-job
  export seqs stay dense), but children get no per-child drop marker
  (`DiagnosticsCoalesced` is run-global at the root, per ADR-024 §2.3
  semantics) — documented exporter limitation.
- `raider replay` (LIN-10 chain, `raider.cli.lineage` — out of allowed
  paths) still reads events.jsonl with the frozen v1 reader; a multi-job
  (mixed v1/v2) export replayed through it is refused typed
  (`SchemaVersionUnsupported`), which is correct per the frozen pin but
  means unified-graph replay belongs to RAI-145/146.
- `run_provenance` is written only when ≥1 segment was joined; the record
  is the ADR-032 cross-run provenance payload repurposed for same-run
  segment pointers exactly as ADR-032 §6 assigns to RAI-144.
- Evidence binds to the manifests' per-file source snapshot (mode
  `git-status`, run IDs `20261013-125931-83714-0001` and
  `20261013-130349-84505-0001`); this record is operational text written
  after the gate runs.
