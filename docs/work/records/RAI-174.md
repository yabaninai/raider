# RAI-174: work record

Status: partial. Date: 2026-10-18. Baseline commit/source: `2de26ed0267eb33986bbfbb44ad65891e63647b6`; worktree `wt/rai-174`, branch `lane/rai-174`.

## Resulting behavior

Added a schemaVersion-2 SDLC record carrier for one existing artifact path:
`check-result`, `review-verdict`, `candidate-identity`, and `integration-result`
are represented as a closed discriminator plus record ID and the core-owned
typed JSON object. The shared projection can be added to a run.json document;
empty evidence returns the original run bytes unchanged. The existing
EventsJsonlWriter now appends versioned evidence to the same JSONL file. The
decoder rejects unsupported versions, unknown discriminators, and unknown
record-envelope fields; run-level additive keys are tolerated. Mixed event
decoding preserves v1 lines verbatim and preserves stream ordering.

## Limitations / blockers

- RAI-164 implementation/types are not present on this baseline, and
  `docs/work/records/RAI-164.md` is absent. ADR-034 §5 explicitly calls its
  evidence field lists conceptual, not frozen. Therefore this lane references
  the core-owned typed payload contract without fabricating field definitions.
  The `data` payload shape is presently only constrained to a JSON object in
  this lane's schema. Exact per-record validation and domain-type integration
  remain blocked on RAI-164's frozen schemas.
- Current HeadlessRunner calls the new run projection seam with its empty
  default; RAI-164 must pass actual evidence records from its SDLC stage
  execution. EventsJsonlWriter can already append the records through the same
  events.jsonl writer.
- Protected golden files were not modified. Independent review and integrated
  candidate gates remain pending.
