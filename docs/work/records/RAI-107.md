## Resulting behavior

Plan mode по ADR-028 — bounded execution-режим AgentLoop, runtime-слой,
дефолт off:

- `AgentLoop.planMode: Option[PlanMode] = None` — None = поведение до
  RAI-107 байт-в-байт; `runPlan` без binding — typed refusal (`RA-INP`)
  ДО любого spend. `maxRepairAttempts < 0` — `RA-CFG`.
- PLAN-01 (read-only enforcement): plan-фаза рекламирует модели только
  strict `RecoveryClass.ReadOnly`-подмножество реестра (`PlanMode.of`);
  вызов Mutating/Idempotent поверх — typed policy-denial `RA-TOOLDENY`
  (structured tool message `tool_denied`, `ToolCallRefused` trace,
  `ToolFinished(Failed("refused: plan phase allows read-only tools only"))`,
  ToolStarted не эмитится) — loop жив; ReadOnly реально исполняются.
  Обычный `runText` на plan-enabled loop сохраняет полный реестр.
- PLAN-02 (план-артефакт): финальный ответ обязан парситься в
  `PlanProposal` (non-empty title, 1..64 непустых steps, trim-нормализация);
  malformed → structured `plan_rejected` (`RA-PLAN-REJECTED`) + bounded
  repair (`maxRepairAttempts`, каждый attempt — отдельный billable модельный
  вызов; исчерпание = typed `PlanPhaseError.PlanRejected`, артефакт НЕ
  пишется); валидный план персистится атомарно (tmp+`ATOMIC_MOVE`) в
  `plan-<root>.json` рядом с артефактами рана (PlanStore; no-fsync honesty
  как JobJournal); human-readable строки — только через Diagnostics.
- PLAN-03 (approval-переход): `PlanSession` (композиция над существующим
  JobManager, НЕ вторая state machine) — без `approve` execution не
  стартует; `approve` создаёт РОВНО ОДНУ execution-джобу (обычный `runText`
  с полным реестром, план — leading context message, тот же root = общий
  root-бюджет); второй approve → typed `AlreadyApproved`; `cancelPlan` —
  штатный interrupt-путь (bounded cleanup, §7.4/7.5: permit без утечек,
  Uncertain-charge сохранён), cancel ≠ approval (typed `Cancelled`),
  повторный план из `Cancelled` возможен (новая джоба, без resurrection).
- Lineage: plan-джоба и execution-джоба — раздельные JobManager-записи
  (лейблы `plan`/`plan-exec`).

UI/approval-канал (`:plan`, TUI-экран плана) — вне среза по ADR-028 §3
(отдельные wiring-карточки); enforcement — runtime-механика.
