## Resulting behavior

Plan mode under ADR-028 is a bounded AgentLoop execution mode, runtime layer,
off by default:

- `AgentLoop.planMode: Option[PlanMode] = None` — None = behavior before
  RAI-107, byte-for-byte; `runPlan` without binding is a typed refusal (`RA-INP`)
  BEFORE any spend. `maxRepairAttempts < 0` is `RA-CFG`.
- PLAN-01 (read-only enforcement): the plan phase advertises only the strict
  `RecoveryClass.ReadOnly` subset of the registry to the model (`PlanMode.of`);
  a Mutating/Idempotent call is a typed policy denial `RA-TOOLDENY` (structured
  tool message `tool_denied`, `ToolCallRefused` trace,
  `ToolFinished(Failed("refused: plan phase allows read-only tools only"))`,
  no `ToolStarted` emitted) — the loop remains alive; ReadOnly tools actually
  execute. Ordinary `runText` on a plan-enabled loop retains the full registry.
- PLAN-02 (plan artifact): the final response must parse as `PlanProposal`
  (non-empty title, 1..64 non-empty steps, trim normalization); malformed input
  → structured `plan_rejected` (`RA-PLAN-REJECTED`) + bounded repair
  (`maxRepairAttempts`, each attempt is a separate billable model call); exhaustion
  = typed `PlanPhaseError.PlanRejected`, artifact is NOT written. A valid plan is
  persisted atomically (tmp+`ATOMIC_MOVE`) as `plan-<root>.json` alongside run
  artifacts (PlanStore; honest no-fsync semantics as in JobJournal); human-readable
  lines are emitted only through Diagnostics.
- PLAN-03 (approval transition): `PlanSession` (composition over existing
  JobManager, NOT a second state machine) — execution does not start without
  `approve`; `approve` creates EXACTLY ONE execution job (ordinary `runText`
  with full registry, plan as leading context message, same root = shared root
  budget); second approve → typed `AlreadyApproved`; `cancelPlan` is the standard
  interrupt path (bounded cleanup, §7.4/7.5: no permit leaks, Uncertain-charge
  preserved), cancel ≠ approval (typed `Cancelled`), a new plan after `Cancelled`
  is possible (new job, no resurrection).
- Lineage: plan job and execution job are separate JobManager records
  (labels `plan`/`plan-exec`).

UI/approval channel (`:plan`, TUI plan screen) is outside this slice under
ADR-028 §3 (separate wiring cards); enforcement is runtime behavior.
