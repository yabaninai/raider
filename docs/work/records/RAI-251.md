## Limitations / blockers

1. **Cross-clean-round canonical variance remains (known, out of scope).** `canonical(round X)` = `3e39a362…` ≠ `canonical(round Y)` = `5c71d85d…` across two `make clean` rounds — consistent with RAI-240 Limitation 1 (exactly the 3 `raider/core/ids$package*` forwarder entries permute per clean dotc round). The card's determinism criterion (consecutive runs on a clean tree) holds in both rounds. Eliminating the residual is RAI-252's product-source change.
2. **Exit-code battery ran via direct wrapper invocation.** The plain `make repro-jar` target takes no arguments, so `--from-assembly` fault injection goes through `scripts/repro-jar` directly; the target is a verbatim delegation and make propagates a nonzero recipe exit (no `-` prefix, no `.IGNORE`). The wrapper is byte-unchanged (`cd46602e…`), so the measured contract is the wired contract. The battery logs do not capture the observed `$?` (the exit codes were mapped by source inspection of the byte-unchanged wrapper, which was intentional); practice for future cards: capture battery logs as `<command>; echo exit=$?` so the observed status is part of the log.
3. **Shared binding path.** `make raider-jar` and `make repro-jar` both write `modules/cli/target/scala-3.9.0/raider-cli.jar`; the last run wins. After a `raider-jar` run the path holds a raw jar; `make repro-jar` re-canonicalizes (and keeps the raw copy at `raider-cli-raw.jar`). Documented in `scripts/README.md`.
4. **Concurrency scope unchanged.** Full wrapper builds run sbt: one sbt JVM per worktree; concurrent full builds in one checkout remain unsupported. Concurrent packaging invocations must use separate output directories (per-pid temp + atomic `os.replace` are confined to the output directory) — documented in `scripts/README.md`; not re-measured here (RAI-240 measured the wrapper's concurrency behavior directly, and the wrapper is byte-unchanged).
5. **Fresh-worktree provisioning (gitignored, disclosed):** `artifacts/toolchain` and `artifacts/tools` (m2 closure, 62 jars) copied read-only from the root checkout (RAI-240 Limitation-7 precedent); no root-checkout mutation.
6. **Zinc poison (RAI-241) did not occur** this session; both cold compiles (det R1, raider-jar baseline) compiled clean. The heal recipe (`sbt --batch raiderCore/clean` + recompile) was not needed.
7.
