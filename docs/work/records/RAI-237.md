## Resulting behavior

`contracts/acceptance/cross-ecosystem/scenarios/lib.sh` (cross-ecosystem scenario shared helpers) closes the three RAI-229 review LOW findings as one bundle. No scenario/expected/gate-policy/driver file changed; the honest rc contract (malformed-only registrations exit 1) is preserved.

1. **TOCTOU lstart pinning.** `start_stand` captures the process start time (`ps -p "$pid" -o lstart=`) at spawn and writes the pidfile as `<pid>|<lstart>` (legacy bare-`<pid>` pidfiles still parse, as unpinned registrations — command guard only, disclosed below). `stop_one_stand` now applies two identity guards before SIGTERM — command must match `*Stand*` (RAI-229) and current lstart must equal the pinned one (RAI-237) — and re-verifies liveness AND the pinned lstart immediately before SIGKILL (the TERM wait is a wide TOCTOU window; verify before EACH signal). An lstart mismatch is an honest refusal: `ERROR ... refusing to signal a recycled pid`, rc=1, pidfile retained, nothing signalled.
2. **Wiped-`$OUT` stop honesty.** `stop_stands` treats a missing/unreadable `$OUT` as a diagnosed condition, not an empty registry: `WARN: stop_stands: $OUT '...' is missing or unreadable (already wiped?) ...` plus rc=1. In-memory registrations are still processed, so a wiped registry cannot silently mask live stands.
3. **Stale-pidfile pre-wipe sweep.** New `sweep_stale_stands` runs when lib.sh is sourced (unless `XE_NO_SOURCE_SWEEP=1`, drill-only opt-out), i.e. BEFORE a driver wipes `$OUT` (`run-all.sh` sources lib.sh at line 17 and does `rm -rf "$OUT"/*` at line 20; `run-budget.sh` never wipes `$OUT`). A prior crashed run's stands are stopped by pidfile evidence (bounded TERM→KILL, same guards) instead of leaking. Per entry: exited → pidfile removed (converged); live registered Stand → stopped, pidfile removed; recycled/foreign/malformed → diagnosed, pidfile removed, NEVER signalled; survived SIGKILL → pidfile RETAINED, sweep rc=1 (actionable evidence). The sweep is best-effort: a failure is loud (WARN with rc) but never blocks a fresh run.

## Limitations / blockers

- **Concurrent-stop overlap is bounded, not excluded by a lock.** Two simultaneous `stop_stands` on the same registration can each pass the pinned-identity guards and send SIGTERM to the SAME registered pid while it is still alive (F5 observed count=1; worst case 2). No signalling of a foreign pid is possible (command + lstart guards run immediately before every signal), no unbounded escalation was observed, and pidfile removal converges. Adding a lockfile would be a behavior/contract change beyond this card's scope; the single-instance-per-checkout rule keeps production overlap to driver-vs-sweep within one checkout.
- **Legacy bare-pid pidfiles are unpinned by design** (backward compatibility): only the command guard applies. `red-first-base-v2.log` sha256 `ad003fee0c4008344c35b6b418cbbc6241c92600200ebc66e90587f0283e03d8` honestly shows the red harness's bare-pid plant still being signalled on the FIXED lib for this legacy format; all registrations written by `start_stand` since this change carry the pin, and the sweep drains any pre-change leftovers.
- **Residual TOCTOU window:** the microseconds between the pre-signal re-check and `kill` are unguardable in user space; the change narrows the window from the full TERM wait bound (up to 10 s) to that residual sliver, and a mismatch is refused loudly rather than signalled.
- **lstart format is locale-dependent** (`ps -o lstart=`); both reads happen in the same driver environment, so comparisons are internally consistent (commented in lib.sh).
- **First EXECUTE gate attempt (2026-10-29) was terminated** by this session's own 20-minute command timeout during a sibling-lane load burst (`Terminated: 15` in the discarded attempt log); it is not a gate failure and is superseded by the green re-run with a 45-minute ceiling. No thresholds were lowered.
- **Corpus artifacts** (`artifacts/xe-out/`, `artifacts/xe-budget/`) are untracked build outputs regenerated by the recorded runs; the 2026-10-28 15:58 prior-session corpus logs (`corpus-run-all.log`, `corpus-run-budget.log`) also show green content but lacked captured exit codes, which is why both drivers were re-run in this session with captured rcs.
- The card's "adversarial" recycled-pid facet uses a live foreign process whose argv matches `*Stand*` (a real cross-checkout stand shape); planting a genuine second-checkout java Stand was unnecessary because the guards match on `ps command=` output, not process internals.
