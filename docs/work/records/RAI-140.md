# RAI-140: work record — ADR-031 lineage projection runtime contract

Status: done. Date: 2026-10-13. Baseline commit/source: `2510a36` (main HEAD;
lane branch `lane/rai-140`, worktree `wt/rai-140`).

## Resulting behavior

- ADR-031 (`docs/adr/ADR-031-lineage-projection-runtime.md`) is the reviewable
  public contract: four-layer semantics table (rendering | typed dry-run
  description | recorded replay via the existing graph-based `ReplayHarness` |
  live rerun via the existing graph-based `IsolatedRerun`); the generated
  source is NOT a rerun/replay entrypoint and must carry an explicit header
  statement; dry-run execution semantics (`Task.succeed` reports only;
  sequencing = declaration order = graph child order; inputs threaded as
  values; explicit static `nesting`); failure path (recorded-failed node →
  `Task.fail` typed); payloads stay in `lineage-data.json` (dataRef keys
  only).
- Projection runtime implemented in the new subpackage
  `raider.dsl.lineage.proj.runtime` (`LineageStep.scala`): typed step
  constructors `LineageStep.model/tool/delegation/phase(id, ..., dataRef,
  inputs, nesting = 0)` and `LineageStep.failed(id, kind, dataRef, inputs,
  nesting, reason)`, plus the `seq` sequencing helper (sequential `Task.flatMap`
  chain) — all returning `Task[Vector[StepReport]]` (uniform pre-order
  fragment shape). Report type `StepReport(id, kind, dataRef, inputs,
  nesting)`; typed failure value `LineageStepFailure(step, reason)` chained as
  the JDK cause of `RaiderError.OutputValidation` (RA-OUT) — the frozen sealed
  core family is used, not extended (core is outside this card's paths). Only
  `Task.succeed`/`Task.fail`/`map`/`flatMap` are used; construction and
  execution dispatch NOTHING (no provider, no tool, no I/O); no shared mutable
  state.
- `NodeView` gains `inputs: Vector[String]` (graph dataflow edges, mirrors the
  frozen wire `DataNode.inputs`), defaulted to `Vector.empty` so every
  existing 5-argument construction site (renderer, `SessionGraphView`, golden
  fixtures) compiles unchanged and LIN2 golden outputs stay byte-identical.
  Population/threading is RAI-141's integration work (per ADR-031 §2.6).
- Renderer untouched (RAI-141 non-goal); no wire changes; no `Task`/`Program`
  API changes (frozen API consumed only); no provider calls; no shared files
  touched.

## Limitations / blockers

- None blocking. Notes: (1) the typed failure reuses
  `RaiderError.OutputValidation` with the typed value as JDK cause — a
  dedicated `RaiderError` family would be a core schema decision (separate
  card + independent review, ADR-031 §2.4); (2) `NodeView.inputs` is not yet
  populated from the graph — `SessionGraphView` (cli) is outside this card's
  allowed paths, population is RAI-141's integration point; (3) executed-
  projection acceptance semantics (rendered+compiled fixture, scripted probe)
  belong to RAI-141/RAI-142 and are intentionally not claimed here; (4) no
  paid calls, no provider/tool stands used anywhere in this lane.
