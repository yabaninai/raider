## Resulting behavior

Local JVM releases (card RAI-279) now stage BOTH distributions atomically:

- The release driver (`scripts/release/LocalReleaseDriver.scala`) requires the RAI-262 REPL distribution built under the release version (`modules/repl/target/raider-repl-dist/raider-repl-<version>/{raider-repl,raider-repl.jar,README.txt,SHA256SUMS,version}` plus `raider-repl-<version>.zip`), verifies no payload bytes contain the release placeholders (`VERSION`, `REPLACE_WITH_RELEASE_SHA256`), and stages all six files via `ReleaseStage.DistributionArtifact` under `repl/raider-repl-<version>/...` and `repl/raider-repl-<version>.zip` alongside the headless package.
- A new `afterStagedArtifacts` materialization hook runs after the release stage has written the staged artifact set, changelog, release.json, and top-level SHA256SUMS into the `.release-*` staging directory and before the atomic move. The hook (1) adds `"distributions": {"headless": "raider-cli.jar", "repl": "repl/raider-repl-<version>", "replArchive": "repl/raider-repl-<version>.zip"}` to the staged release.json (zio-json AST `Json.Obj.add`; manifest schema itself unchanged — a schema change would need a separate card), (2) folds the unreleased `## [<version>] - unreleased` changelog section into the dated `## [<version>] - YYYY-MM-DD` section the stage rendered (moving the dated section directly below the file intro, preserving one blank line as section separator; no-op when nothing was cut), and (3) rewrites the top-level SHA256SUMS so it covers every staged file except itself, in `sha256sum -c` format with forward-slash paths, path-sorted. The nested `repl/.../SHA256SUMS` remains a covered payload file and stays internally consistent because no REPL payload is placeholder-rendered.
- `scripts/release/local-jvm-release.sh`: refuses to start when a stale `.release-*` staging directory exists under `artifacts/release`; after `make raider-jar` it builds the REPL distribution with `sbt --batch "set version := \"$VERSION\"" raiderReplDist` and fails fast if the payload set, archive, or version metadata is missing/mismatched; after the driver run it applies the same changelog fold to the repository `CHANGELOG.md` (POSIX awk; guarded by assertions: exactly one heading for the version, dated section present, unreleased section gone), verifies BOTH manifests (`verify_checksums` on the release root and the nested REPL directory), checks the staged REPL directory/archive/version metadata, and keeps the existing placeholder/URL/smoke checks. The EXIT trap now also removes the fold temp file (a second `trap ... EXIT` would have overwritten the Git-pointer restore trap).
- `scripts/release/verify-local-release.sh`: release.json must now carry the `distributions` object with non-empty `headless`, `repl`, `replArchive` strings, and the top-level SHA256SUMS must cover exactly the set of files in the release (listed-but-missing or present-but-unlisted is exit 21). Only the top-level manifest is exempt from coverage; the nested REPL manifest is itself a covered entry.
- `scripts/release/negative-install-smoke.sh`: derives the expected version from the fixture release.json (charset-validated), refuses legacy fixtures without the REPL distribution, and adds four corruption cases (missing REPL jar, truncated REPL jar, tampered REPL launcher bytes, missing REPL zip) — each must be refused with exit 21 and leave no install staging directory. The two JDK cases exercise the real `packaging/raider` launcher, which exits 21 on missing/old JAVA_HOME before invoking Java, so the harness runs fully without a release build.
- `scripts/release/signal-install-smoke.py`: accepts an optional release directory argument (default `artifacts/release/0.1.1`) and derives the version from its release.json instead of a hardcoded 0.1.1.
- `CHANGELOG.md`: gains the `## [0.2.0] - unreleased (cut pending)` section (5 bullets mirroring the driver release notes verbatim) and drops the duplicated bottom `[0.1.1]` block (dedupe).
- `docs/releases/jvm-distribution.md`: refreshed — release layout/flow now documents both distributions, the `distributions` naming object, the changelog fold, full-manifest coverage, the stale-staging pre-check, and the updated harness commands; removed the stale "CLI does not currently support --help" claim (`raider --help`/`raider help` exit 0 per RAI-261; `run --help` is not a supported form); compatibility note: pre-RAI-279 releases (e.g. 0.1.1) fail the new verify checks by design.
- Driver release notes mirror the unreleased 0.2.0 bullets verbatim, so the dated section rendered by `ReleaseStage.updateChangelog` and the folded repository changelog have identical content.

## Limitations / blockers

- **Scala compile skipped (load gate).** System load was 12-16 (gate threshold 4) throughout the session; `sbt` compile of `LocalReleaseDriver.scala` was not run. The driver was instead verified statically against the actual sources: `ReleaseStage.Request`/`DistributionArtifact`/`AcceptanceEvidence` signatures, `LocalReleaseHandler.apply`, `RaiderTask` alias, `Task` companion, zio-json 0.10.0 AST API (from the sources jar). Residual compile-risk is low but nonzero; the coordinator's release run compiles it for real.
- **Two defects were caught by review/testing and fixed before commit:** (1) the materialization hook was initially placed in the `build` Request slot, which runs BEFORE staging exists and would have failed every release — moved to `afterStagedArtifacts`; (2) `verify-local-release.sh` excluded every `SHA256SUMS` from the coverage set while the driver's manifest includes the nested REPL manifest — fixed to exempt only the top-level manifest, and the test fixture was regenerated to the real driver output shape (the earlier fixture masked the bug by excluding the nested manifest too).
- **`sbt raiderReplDist` version pinning**: the wrapper sets `version := "<release version>"` for that single invocation, so the REPL distribution and its `version` metadata file are built under the release version even if the project version differs.
- **Hook failure behavior**: if the materialization hook fails, the release stage deletes the destination but leaves the `.release-*` staging directory; the wrapper's stale-staging pre-check then refuses the next run until the directory is removed manually after inspection. The repository changelog is not modified in that case (writeAtomic never ran).
- **Old releases**: 0.1.x release directories lack `repl/` and the `distributions` naming; `verify-local-release.sh` and `negative-install-smoke.sh` now refuse them by design (documented compatibility note). Use the pre-RAI-279 harness state or point the signal harness at a new-style release directory.
- The `distributions` release.json key is outside the manifest case class (`Manifest`) by intent: extending the schema requires a separate card per the card's non-goals.
