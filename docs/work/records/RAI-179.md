Status: partial. Date: 2026-10-18. Baseline commit: `0bb6f8958b59104e27a123854a0ed6655194933e`; lane branch: `lane/rai-179`. Prerequisite: merged `lane/rai-165` at `d015a50` into this lane as a local merge commit; no push or merge to main.

## Resulting behavior

Added a typed `CheckpointDispatch` boundary that carries trusted `CandidateIdentity`, checkpoint ID, expiry, request artifact path, optional decision-file path, an owner-provided current-state reader, required capability, and an injectable clock. A first headless evaluation writes the RAI-165 request artifact and returns typed `CheckpointOutcome.NeedsApproval` (exit 25), without retaining a fiber. A new evaluation reads the persisted request and decision files, then calls RAI-165 recheck with current owner state. Missing/malformed artifacts and stale candidate/capability state are typed refusals.

The boundary is not yet wired to either production launcher. Existing HeadlessRunner Agent/Bundle and `raider workflow run` do not expose an SDLC checkpoint in their executable workflow/program contracts, and no trusted production source for current candidate/policy/repository/task/evidence state or owner capability is available at those entry points. Wiring file flags or caller-supplied identity as authority would violate ADR-030. The typed component contract and fixture are useful prerequisites but do not complete RAI-179's required seams or CLI surface.

## Limitations / blockers

The new boundary deliberately does not fabricate these values or treat CLI file contents as authority.

- RAI-169 independent verification remains separate.
