### Mechanism analysis (per flake)

**LIN13-01 / ReplayProductCliSpec — in-child hub relay race.** The replay
drives a REAL child process (`raider.cli.Main replay …`); inside the child,
`ReplayHarness.replay` subscribes a collector fiber to a fresh `EventHub` and
terminates the capture as soon as the Terminal envelope appears in the sink
(`eventuallyTerminal`). Per the hub's own contract (ADR-024 §2.3,
`hub.subscribe` scaladoc), reliable and diagnostics envelopes are relayed by
TWO INDEPENDENT forwarder fibers with UNSPECIFIED relative arrival order. The
fixture's last diagnostics event is seq 13 (`Diagnostics`, diagnostics class),
immediately before the reliable Terminal seq 14: under CPU starvation the
diagnostics-class tail is still in flight when Terminal triggers the sink
read, the sink misses diagnostics seqs, and the reducer refuses the stream
typed — `ReduceError.SeqGap(j_1,k,k+1)` → `Verdict.Failed(Failure.Reduce(…))`
→ exit 20, exactly the retained RAI-146 red signature
(`SeqGap(j_1,13,14)`). Discriminator that pins the mechanism: a hub-level
diagnostics drop consumes NO sequence (the fold/state commit is skipped on a
failed permit acquisition), so a drop can NEVER produce a gap — a gap with
`droppedDiagnostics == 0` is the relay race by construction. Lane probe
evidence (first storm attempt): `dropped=0 envelopes=9
graph=Left(SeqGap(j_1,8,10))` — the five missing seqs (8,9,11,12,13) are
EXACTLY the diagnostics-class tail; every reliable-class event (1,3,6,10,14)
is present.

**SessionRegistrySpec focus invariant — ungated per-tab fold.** `TabView`
renders `status` from the HUB snapshot (authoritative, committed at publish
time) but `lastSeq` from the tab-LOCAL fold, produced by a per-tab consumer
fiber (`hub.subscribe` stream per `create`). The test gates the baseline
capture on tab A's registry-side fold ONLY (`reg.snapshot(a).lastSeq == 1`);
tab B's consumer is ungated, so under load `localBefore` can capture B at
`lastSeq=0` (hub status already `Running`) while B catches up to `lastSeq=1`
before `localAfter` — failing `localBefore == localAfter` with exactly the
retained RAI-146 red signature (`(…,0,Running())` was not equal to
`(…,1,Running())`). Lane probe evidence (first storm attempt): after the
verbatim A-only gate, B's local fold was still at `lastSeq=0`.

**Third consumer of the same product race (found during FLK-03).** The first
full-suite run on the fix tree went red in `ReplayChainE2EPropertySpec`
PROP-01 seed 1: `envelopes=14/13, dropped=0/0`, second replay's comparison
`None` — the same `ReplayHarness.eventuallyTerminal` relay race (the suite's
own scaladoc already records a prior cold-start flake of this family,
mitigated then by `sequential` only). The suite is inside this card's allowed
paths and FLK-03 requires the cli module green in every full run, so it
joined the fix set.

### Fixes (test-only, precedent-shaped)

1. `ReplayProductCliSpec` — bounded FRESH-PROCESS retry on documented
   retryable LOAD signatures only (`runReplayFreshProcess`, 3 attempts total,
   per-attempt 120s bound unchanged): (a) child exit 20 with `SeqGap(` in the
   child's typed stderr; (b) launch/timeout Left (spawn/JIT/scheduler
   starvation). Real verdicts (match, mismatch exit 10, any typed exit-21
   config failure) NEVER retry; the FINAL attempt's result flows into the
   UNCHANGED assertions. Every process-spawning test of the suite (LIN13-01
   match/mismatch, LIN13-02 corrupt/missing/usage, LIN13-03 parallel pair)
   uses the same wrapper.
2. `SessionRegistrySpec` — the focus-invariant baseline capture is now
   quiescence-gated for BOTH tabs (await-condition on logically guaranteed
   progress: hub side already delivered, both consumer fibers are forward
   progress); assertions unchanged; no sleep added.
3. `ReplayChainE2EPropertySpec` — a did-NOT-reduce replay
   (`comparison = None` ⇔ reducer-refused gapped stream) is retried with a
   FRESH harness (fresh hub/forwarder fibers), bounded at 3 attempts
   (`replayDense`); any real verdict, including a genuine mismatch diff,
   never retries; all assertions unchanged.

Both retry helpers log every engaged attempt to the test output
(`[rai-152] …` markers) for honest trails. Post-fix, no retryable signature
was ever observed again (retry paths exercised by review, not by firing —
recorded honestly below).

## Limitations / blockers

- **The product-side race is NOT fixed (out of allowed paths) — follow-up
  card proposed.** Root cause lives in `ReplayHarness.eventuallyTerminal`
  (`modules/cli/src/main/scala/raider/cli/lineage/ReplayHarness.scala`,
  src/main): Terminal-presence termination does not imply diagnostics-class
  quiescence. The typed reproducer exists (probe: `dropped=0` + missing
  diagnostics-class tail; suite reds: `SeqGap(j_1,13,14)` exit 20,
  `envelopes=14/13 dropped=0/0`). A scoped product fix (drain to the hub
  watermark: after Terminal, await sink coverage of
  `1..hub.snapshot(jobId).lastSeq`, then read) would determinize EVERY
  consumer (ReplayCli product behavior under load, not only tests). This
  lane applied the card-prescribed test-side determinism and returns the
  contract-scope request to the coordinator.
- **Retry paths never fired post-fix.** No retryable load signature
  (`SeqGap` exit 20 / launch-timeout / non-reducing replay) was observed in
  any post-fix run (30 targeted + 3 full-suite executions), so the bounded
  retry logic is evidenced by diff review, not by a fired retry. The pre-fix
  reds prove the signatures occur under storm; the helpers are bounded (3
  attempts) and log every engagement.
- **Reproduction statistics honestly recorded.** LIN13-01: probe red in 1 of
  1 probe runs (180 replays) under storm; 12 targeted suite runs green.
  SessionRegistry: probe red in 1 of 1 valid runs (200 rounds); 18 suite
  runs green. The suite-level reds remain the retained RAI-146 manifests
  (cited by the card) plus this lane's full2 red for the prop suite.
- **Tooling failures are not counted as flake reproductions**: 2 ui-probe
  compile errors and 10 first-batch propx10 compile errors (helper error
  channel) exited 1 but were compile failures; logs were discarded/overwritten
  and the affected runs repeated to green/red on valid code.
- **Storm approximation**: 2 churn clones + 10 burners + 4 sibling lanes
  (live sbt, one JVM observed at 99% CPU); 1-min load 20→161 across the
  window, 416 samples retained. Neighboring lane worktrees were not touched;
  churn ran from detached clones of `e8ec85e` outside the repository.
- Evidence directories (`artifacts/rai-152/**`) are outside git; for
  coordinator merge the manifest hashes are in the tables above. The lane
  report applies to the final fingerprints listed at the top; the integrated
