## Resulting behavior

The REPL host now attaches a lineage provider to `:aux`. `RAIDER_LINEAGE_DIR` configures a run directory; a scoped poller reads snapshots exclusively with `raider.cli.lineage.LineageSnapshot.read`, which resolves and validates the `lineage-commit.json` pointer and committed source/data digest pair. The poller publishes an atomic cached UI state, so terminal commands only read an in-memory snapshot. No fixed artifact-file read or direct-path fallback exists. Missing source configuration and invalid/malformed snapshots are distinct typed states. Invalid projections render as `lineage invalid | validity unknown: <bounded one-line detail>`. Typed unavailable states are now renderable by the Lineage tab and show `lineage unavailable | validity unknown: <bounded one-line detail>` instead of the shell's generic unavailable-tab hint.

The real product PTY acceptance drove the live producer through two committed generations, switched between `:aux` and `:tabs`, replaced the pointer with malformed content during the session, observed the typed invalid message, switched back, and created a session tab successfully. A separate product PTY starts with `RAIDER_LINEAGE_DIR` explicitly absent and verifies that `:aux` displays the typed unavailable status (and not the generic hint). The producer and PTYs are cleaned up by their fixtures. No lineage schema or GraphHash changes were made.

## Limitations / blockers

The adapter consumes committed run-directory snapshots via the RAI-173 pointer protocol. It does not subscribe to a REPL job's incremental envelope stream: this REPL host does not currently expose that producer seam. Live behavior is verified through successive real pointer publications. `RAIDER_LINEAGE_DIR` must identify a run directory; when unset, the tab reports the typed unknown-validity status. Gate results and their manifest details are absent from this finalized pre-gate record by design and are to be returned in the completion message.
