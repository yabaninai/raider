## Resulting behavior

The REPL host now attaches a lineage provider to `:aux`. `RAIDER_LINEAGE_DIR` configures a run directory; a scoped poller reads snapshots exclusively with `raider.cli.lineage.LineageSnapshot.read`, which resolves and validates the `lineage-commit.json` pointer and committed source/data digest pair. The poller publishes an atomic cached UI state, so terminal commands only read an in-memory snapshot. No fixed artifact-file read or direct-path fallback exists. Missing source configuration and invalid/malformed snapshots are distinct typed states. Invalid projections render as `lineage invalid | validity unknown: <bounded one-line detail>`; unavailable data is not presented as valid.

The real product PTY acceptance drove the live producer through two committed generations, switched between `:aux` and `:tabs`, replaced the pointer with malformed content during the session, observed the typed invalid message, switched back, and created a session tab successfully. The producer and PTY are cleaned up by the fixture. No lineage schema or GraphHash changes were made.

## Limitations / blockers

The adapter consumes committed run-directory snapshots via the RAI-173 pointer protocol. It does not subscribe to a REPL job's incremental envelope stream: this REPL host does not currently expose that producer seam. Live behavior is verified through successive real pointer publications. `RAIDER_LINEAGE_DIR` must identify a run directory; the default is honestly unavailable. The gate results and their manifest details are absent from this frozen pre-gate record by design and are to be returned in the completion message.
