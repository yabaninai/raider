## Resulting behavior

Portable CLI execution route under ADR-036, opt-in only:

- `raider workflow check --doc <file>` — zero-dispatch document gate. Validates the frozen schema (v1), pinned registry snapshots (checkId + argv SHA-256 against the launcher-pinned trusted registry), declared-safe operations, node/link conformance, uniqueness constraints, and root reachability. Document-level outcomes print closed JSON on stdout (`{"valid":true/false,...}` with machine-readable diagnostics); argv/usage errors print one human-readable line on stderr with exit `RA-CFG` (21). No provider calls, no filesystem effects.
- `raider workflow explain --doc <file>` — zero-dispatch outline: declared limits, structure (nodes/links/reachability), outputs (bindings/verdict), and required trusted references (checks with registry snapshots, safe operations, checkpoints). Same stdout/stderr discipline as `check`.
- `raider workflow run --doc <file>` — full launcher-pinned portable run: lowerer validation, launch-layer limit enforcement (`PortableLaunchPolicy.intersect`: attempts = min(declared, invocation), outer deadline = min(`--deadline-s`, declared `deadlineMs`), tokens/parallelism/children declared-only), per-attempt model token ceiling via `TokenBudgetBackend` (honest in-flight completion past ceiling; next dispatch rejected `RA-PBUDGET` before any wire call), trusted registry fixed to the pinned snapshots, artifacts and SIGTERM handling byte-compatible with the compiled route (`WorkflowRun` discipline), events JSONL with exactly one Terminal event last, `run.json` with doc/input digests, declared and effective limits, and honest task verdicts (`taskVerdict` only when the root output's trusted check passed; otherwise typed `RA-OUT` exit 10).
- `workflow check|explain|run` refuse compiled-route flags (`--classes`, `--source`, `--checkpoint`, `--decision-file`, `--approval-request`) with `RA-CFG`.

Deadline semantics: a declared positive `deadlineMs` now gets launcher teeth — the run stops with `RA-DEADLINE` (24) at the earlier of the invocation `--deadline-s` and the declared deadline (previously the declared deadline was parsed but ignored).

Attempt semantics (verified by the live-provider parity suite): `maxAttempts` bills the root attempt plus each agent model round; a two-round scripted task (tool call + final) requires `attempts >= 3`.
