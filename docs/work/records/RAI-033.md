## Limitations / blockers

1. **Gate registry gap (integration blocker)**: `scripts/quality-policy/registry.json` `path_profiles` has no entries for `^vendor/` and `^THIRD_PARTY_NOTICES.md`, so `make quality-changed QUALITY_EXECUTE=1` hard-refuses on this tree (fail-safe by design; the refusal also fires under explicit `--profiles`). The registry is coordinator-owned gate policy and protected for product implementation cards, so the mapping entries (plus the `quality.py` self-check classify fixtures, which assert unknown-path → `__unmapped__`) require a separate card and independent review. Until then, required-gate evidence for this lane cannot be produced on any tree containing the pinned corpus.
2. **Module not registered in the sbt build**: `static`/`unit`/`contracts` gates (`sbt-compile`, `sbt-test`, `scalafmt-check`) cannot see `modules/compat-opencode` until the coordinator registers it. The in-lane runner provides equivalent compile+test evidence with the same pinned toolchain (dotc 3.9.0, zio-test 2.1.26, zio-json 0.10.0).
3. **`compatibility` profile** named in the card's required-gates line does not exist in the current registry (profiles: ci, contracts, docs, eval, fast, perf, repl, runtime, security, self, static, tools, transport, unit); `security` and `eval` execution is blocked by blocker 1.
4. **Documented simplifications**: a markdown-disabled agent cannot remove registry built-ins (only JSON-config disable does); documents apply sequentially so a later markdown document silently overrides an earlier one; `small_model`/`default_agent` parse only string form (`provider/model[#variant]`).
5. Evidence logs live in gitignored `artifacts/quality/rai-033/` (worktree-local, per the RAI-284 convention); tracked records are the citation basis.
