## Resulting behavior

- `:sessions` is an alias for the frozen tab/session list and `:switch` continues to focus a session through the existing registry. Focus remains UI-only.
- The chat layout footer shows the configured model, an explicit `budget unknown`, and the stream state; existing chunk/ready/cancel feedback remains visible.
- `:tasks`, `:task-up`, and `:task-down` open and navigate a bounded task panel. The panel accepts the existing `PlanTab.Snapshot` through `ChatLayoutSink.updateTasks`; absent plan data is rendered as “No plan tasks available.”
- The current `--chat` entry point does not connect an active ADR-028 `PlanPanel` to `updateTasks`, so populated task proposals are not yet demonstrated in the product shell. The budget display is honestly unknown and is not yet updated from live ADR-024 budget events. These are card acceptance gaps; no claim of full completion is made.
- The coordinator's interpreter-world EventHub and serialized bridge mandate is not implemented in this lane result. The PTY scenarios for populated plan tasks, a real budget transition from the session ledger, and a session-switch regression were not added or run. No synthetic values were introduced.
