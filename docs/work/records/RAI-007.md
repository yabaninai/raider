## Resulting behavior

raider-runtime/jobs: job registry и atomic lifecycle по runtime-contracts §4:
- `JobStatus` — полный набор состояний и легальные рёбра §4 (включая
  WaitingApproval→Cancelling; WaitingApproval→Succeeded/Failed отсутствуют по
  спецификации);
- `JobManager` (STM): start с cancellation-safe регистрацией (uninterruptibleMask;
  ghost-защита onInterrupt в окне fork), единый atomic settle-переход
  (transition + публикация typed результата), отмена побеждает в гонке с финальным
  завершением (waiters получают typed Cancelled, завершение — late observation),
  поздние завершения считаются и не перезаписывают исход, watcher при дефекте
  публикует Failed (никаких висящих waiters), bounded retention (эвикция только
  старых TERMINAL записей, живые job'ы не удаляются), admin view по id + root
  lineage в snapshot, typed `snapshotById` (UnknownJob);
- `JobHandle[A]` реализует core Job[A]; await идемпотентен, много waiter'ов,
  повторный await не повторяет эффект (счётчик runs==1 в тесте).
