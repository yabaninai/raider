## Resulting behavior

Per-tab drafts закреплены на продуктовой поверхности behavioral-спеками.
Механика фичи уже полностью обеспечена принятыми frozen-слоями и потреблена
как есть — продуктовых правок НЕТ. Основание закрытия behavioral-спеками без
продуктового кода — assignment packet coordinator'а (wave 2, 2026-10-12),
не текст карточки: «если механика уже полностью обеспечена frozen-слоем —
карточка закрывается фича-специфичными behavioral-спеками на продуктовом
хосте»; зависимость RAI-102 принята, acceptance-критерии карточки выполнены
(named-тестами P2D-01..03).

- drafts per-tab — `raider.ui.SessionRegistry` (`draftAppend`/`draftGet`/
  `draftClear` на TabId, UI-local, не события; RAI-057);
- ввод не-командной строки → append в draft ФОКУСНОЙ вкладки, focus-навигация
  drafts не трогает — `raider.ui.CommandRouter`/`ShellExecutor` (RAI-061);
- close живой вкладки с draft → диалог hide/cancel
  (`TabShell.Config().closePrompt`), отказ (невалидные ответы → безопасный
  non-destructive default cancel-request) вкладку не удаляет и draft не
  трогает — `raider.ui.ShellExecutor.close` + `CloseChoiceResolver`
  (RAI-061/062);
- продуктовый хост — `raider.repl.TabShellHost` (wiring EventHub +
  SessionRegistry + ShellTerminal.jline + resolver + TabShell.run; RAI-102),
  не изменён.

Новое (только test-scope, два НОВЫХ файла, паттерн RAI-102 PTY-харнесса;
TabShellHostPtyApp/TabShellHostPtySpec не редактировались):

- `raider.repl.TabShellDraftsPtyApp` — тестовый harness: хостит РОВНО
  продуктовый wiring (`TabShellHost.wiring` + `TabShellHost.run`), тестовый
  фидер публикует синтетический runtime-поток (1 JobStatusChanged → Running +
  N Diagnostics) через РЕАЛЬНЫЙ hub (ADR-024, без bypass) на каждый `:new`;
  report-оракул — read model registry (draft байт-в-байт, draftLen,
  status/lastSeq/unread, scrollback counts, feedDone, hubDroppedDiagnostics),
  атомарный tmp+rename. Отличия от RAI-102-харнесса: tunables
  RAI103_PTY_EVENTS / RAI103_PTY_DELAY_MS (плотность шторма P2D-03), plus
  `stty -echo` на PTY slave (kernel line-discipline echo в cooked-окнах
  между строками подмешивал набранные байты в конец рендерящегося bar-row в
  ЗАХВАТЕ драйвера — артефакт захвата, не свойство продукта; JLine сам рисует
  ввод в raw-режиме, все ассерты — по printAbove-строкам и report-оракулу).
- `raider.repl.TabShellDraftsPtySpec` — Scala PTY-драйвер (new file, паттерн
  TabShellHostPtySpec: `/usr/bin/script -q /dev/null` → openpty+setsid+dup2,
  master релеится pipes, capability-запросы JLine отвечаются, ANSI-чистка,
  evidence persists даже при фейле) + 3 fixtures.

## Limitations / blockers

- Тот же класс транскрипт-ограничений, что принят в RAI-062/102: атомарность
  строки оценивается по финальному cleaned-транскрипту; re-ask счётчик
  close-диалога — нижняя границей (≥2/≥3), т.к. фоновые bar-рендеры
  перерисовывают строку диалога (printAbove-строки — точно считаемы, они и
  ассертятся). Ctrl+C/resize вне scope P2D (покрыто RAI-062 PTY-02).
- `stty -echo` — test-scope решение в НОВОМ harness-файле: отключает kernel
  echo артефакты захвата; продуктовый код не менялся. Если reviewer сочтёт
  нужным видеть kernel echo в транскрипте — tunable, но тогда bad==0 требует
  переосмысления (артефакт захвата не отделим от tear по транскрипту).
- Первый sbt-прогон в worktree упал на протухшем Zinc-инкременте
  (pre-existing target/ в worktree при создании): лечится `sbt clean`;
  исходники baseline корректны (после clean полная компиляция зелёная,
  включая интеграцию с frozen UI). Воспроизводимость для других lanes:
  чистить target при первом странном member-resolution фейле.
- artifacts/tools/m2 скопирован из root (untracked, §1a) — требование
  compile-fixtures; в git не попадает.
- docs/lineage.md §9.2 («продуктовая поверхность не подключена» для
  drafts) обновляется координатором вне allowed paths lane — на merge.
- Подключение TabShellHost в пользовательский вход Main.ttyLoop / chat —
  вне этой карточки (как и в RAI-102; smoke CLI-цепочка не задета).
