# RAI-189: work record

Status: review-ready (independent review pending). Date: 2026-10-24. Lane baseline: `bcd1b58`; coordinator mandate merge: `e4d7a44`.

## Resulting behavior

The typed approval API and guarded-tool wrapper now live in `modules/runtime/src/main/scala/raider/runtime/tools/approval/ToolApproval.scala`, adjacent to runtime tool-dispatch policy. Both `raider-repl` (`FacadeOps` + `ChatLayoutSink`) and `raider-cli` (`ChatLoop`) consume the shared runtime API without a module cycle. `ToolApproval.guard` wraps only tools stamped `RecoveryClass.Mutating`; explicit `Approve` invokes the original tool, while explicit `Deny` and a missing hook fail closed with `RaiderError.ToolDenied` (`RA-TOOLDENY`). The CLI asks for a typed `yes` response at each mutating invocation; every other response or input failure denies. Read-only and idempotent tools are not prompted. The launcher registry is not expanded.

Tool cards remain bounded and render through the existing renderer bridge. The approval wait uses the shell's existing JLine input/read loop and render writer.
