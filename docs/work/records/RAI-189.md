# RAI-189: work record

Status: partial. Date: 2026-10-23. Baseline commit: `de242a2` (`lane/rai-189`); the worktree was clean before implementation.

## Resulting behavior

The ordinary REPL facade now wraps each tool stamped `RecoveryClass.Mutating` at the `AgentLoop.runText` construction point. The typed `ToolApprovalHook` receives the invocation name, frozen recovery class, arguments, and a per-request token. An explicit `Approve` invokes the original tool; `Deny` and an absent hook fail closed with `RaiderError.ToolDenied` (`RA-TOOLDENY`). Read-only and idempotent tools are not prompted. In chat mode the existing `ChatLayoutSink` waits for the shell input loop to submit the exact displayed token using `:approve <token>` or `:deny <token>`; duplicate/stale tokens do not settle a request. The launcher's frozen registry is not expanded.

Tool cards remain bounded and render through the existing renderer bridge. The approval wait uses the shell's existing JLine input/read loop and render writer.
