# RAI-115: SDK Embedding Boundary Audit

Date: 2026-10-12. Baseline: 3a60f93a2197a0097e4a9f326260dd9fd7844578. Worktree: lane/rai-115-sdk-audit; the source tree was clean. This is a read-only source audit and design exploration. No API, runtime tests, or real provider calls were performed.

## Conclusion

A minimal SDK can be assembled on top of the current core/runtime/dsl/providers while retaining a single runtime. The main gap is the absence of a host-facing launcher/resource factory that connects a typed Program to the backend, jobs, scopes, admission, budget, and tools, establishes a root, and manages resources in the ZIO lifecycle. Typed composition exists; convenient launching is currently tied to the REPL, while the CLI serves a separate process-oriented path.

Recommendation for a separate ADR: an explicit ZIO-native managed runtime capability over the current AgentLoop/JobManager/Admission/BudgetLedger. The host creates and closes it in its scope; the SDK does not introduce a second loop/scheduler. Task with environment Any can be retained in the first additive slice, with dependencies passed explicitly. ZLayer.scoped can be considered as an adapter, but the API shape remains an ADR decision.

Confirmed positioning: the primary differentiator is the most convenient Scala DSL for AI-native SDLC. The first path is a Scala 3 workflow through a local generic runner; the CI system has not yet been selected, and GitHub Actions is not the first target. The target project is the neighboring TokenRouter/Yabanin: work on its code belongs only in separate companion cards; this Raider card does not change or investigate the sibling repo. The desired cycle includes PR, automatic commit/merge, version/changelog/tag, and build artifacts, but excludes deploy. The release tag is created locally: pushing a tag is excluded because it triggers GHCR publish and staging deploy in the target system. The forge/remote adapter has not yet been selected. Human gates are configured in the Scala workflow. Host embedding is additional SDK proof. The Raider wave continues; the project is OSS. An experimental preview before M4 is acceptable with migration for breaking changes; the TASTy limitation must be stated honestly. Durable resume is not required: after interruption, the result is uncertain and rerun is explicit. Extended trace privacy is deferred; the preview is intended for trusted local data.

## Lifecycle invariants and options

Official ZIO documentation describes Scope as the basis for resource management, and ZIO.acquireRelease/ZIO.scoped/ZLayer.scoped as ways to bind release to the lifecycle ([Scope](https://zio.dev/reference/resource/scope/), [ZLayer](https://zio.dev/reference/contextual/zlayer/)). This supports a ZIO-native lifecycle, but does not prescribe the shape of the Raider API.

- One execution instance: root, validated limits, admission+ledger, frozen tool/config snapshot, and an explicit owner. Shutdown reports incomplete/uncertain cleanup; upstream cancellation acknowledgement is not promised.
- maxLLM=1: parent join does not hold a model permit; verify this on the public host path.
- Cost claims: trace UsageObserved → loop outcome → withSlot settlement → UsageReport again. The current code's successful AgentLoop path records zero; unknown price must remain unknown/unpriced, not become zero. A hard cap depends on the reservation estimate and pricing policy, not only on the ledger.
- Two host instances isolate jobs, roots, queue, budget, and tools; closing one does not affect the other.
- Construction performs no network call/dispatch.
- Task[Any,...] does not accept host services through R. Options are explicit dependency capture when creating Program or changing the contract environment type. The minimal option with explicit dependencies is recommended first; generic effects need separate justification.
- ZIO Scope ownership differs from the current JobManager daemon ownership; the ADR must define acquisition, close grace, and report.

Four boundaries are being considered for the ADR:

1. **Recommended managed runtime capability:** effectful construction from explicit backend/config/tools/policy/limits; the host scope controls closing; the capability launches Programs and jobs. Reuses one runtime graph. Risk: coordinating manager-owned daemon fibers and the cleanup report.
2. **ZLayer-first:** natural in a ZIO app graph; may be a thin adapter. Risk: mandating a layer API and complicating multiple isolated instances.
3. **Low-level AgentLoop/Admission/JobManager:** available and adds few abstractions, but the consumer wires internals and lifecycle manually. Not sufficient as the only SDK.
4. **REPL/CLI reuse:** not a primary API because of Runtime.default/global registries or process-specific schemas/coding defaults.

The ADR chooses the package/artifact boundary; Program vs Agent/Workflow entry; backend injection vs direct provider factories; generic ToolRegistry vs optional coding tools; scope/close/uncertainty behavior; root/instance isolation; Task environment policy; Scala/ZIO/JDK compatibility; credentials; bundle admission boundary; API compatibility/deprecation. No signature is accepted by this audit.
