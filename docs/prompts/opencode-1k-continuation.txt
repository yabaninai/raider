ВОЛНЫ (проверенная механика, не менять без причины)
- Конкурентность: до 10 параллельных lane-workers (разрешение владельца
  2026-10-10), reviewer занимает слот; уменьшай при нехватке RAM/CPU/ready-
  задач. Root checkout, build.sbt/project/**, board, docs/tasks/**, docs/adr/**,
  scripts/** — только coordinator; lanes их НЕ трогают.
- Lane = snapshot-копия root БЕЗ .git: rsync -a --exclude .git --exclude
  target --exclude artifacts --exclude .bloop --exclude .metals --exclude
  .DS_Store --exclude '.env*' --exclude .idea $ROOT/ $NIGHT/lane-NN/ ;
  затем cp -R $ROOT/artifacts/tools/m2 lane-NN/artifacts/tools/m2 (bootstrap
  в lanes НЕ запускать — SSL-cert окружения, pre-existing). .env* НИКОГДА
  не попадает в lanes/manifests (инцидент 2026-10-10 — .env.yabanin утёк в
  8 lanes; ремедировано).
- Base manifest на ВОЛНУ из чистого pre-work снапшота: cd lane-NN && python3
  scripts/quality/quality.py inventory --out $NIGHT/base-manifest-wX.json.
  Manifest считается от снапшота ДО работы воркера (не от пост-work дерева).
- Пакеты: $NIGHT/packets/COMMON-W8.md (правила: cwd/абсолютные пути,
  «Git unavailable: isolated snapshot», sbtlock на каждый sbt test/quality,
  Scala 3.9+ZIO, без новых зависимостей, wire-freeze, secrets/live-API запрет,
  RECORD.md deliverable, честный blocked > выдуманный pass) + packets/LNN.md
  на карточку. В каждом пакете: allowed paths (конкретные файлы/каталоги),
  FROZEN сигнатуры если есть, acceptance IDs, точные команды, «RECORD.md
  сразу после зелёных тестов».
- ДИСЦИПЛИНА CODE-FIRST (критично: 2 агента погибли, застряв в research):
  в пакете перечислен закрытый список файлов для чтения (≤5, ≤15 минут),
  дальше СРАЗУ fixture-тест → реализация → compile → тесты. Минимальный
  приемлемый результат лучше широкого исследования.
- Спавн: nohup opencode run --dir $NIGHT/lane-NN --model zai/glm-5.3-flash
  --title "WX-LNN <card>" "<промпт: прочитай COMMON+LNN, работай строго по
  ним, полный цикл, RECORD.md, блокер → честно в RECORD>" > $NIGHT/logs/LNN.log
  2>&1 &  — pid в $NIGHT/pids-wX.txt.
- Все sbt test/quality запуски в lanes — ТОЛЬКО через $NIGHT/sbtlock
  <LABEL> <cmd> (глобальный lock от N параллельных JVM). Обычный compile —
  без lock.
- Мониторинг: циклы sleep ~600с; record=RECORD.md есть/нет, proc alive/dead,
  хвост лога. Интегрировать по мере готовности, не ждать всей волны.

ИНТЕГРАЦИЯ (coordinator, последовательная)
1. mkdiffs.sh (diff lane vs baseline, exclude target/artifacts/RECORD) →
   проверить allowed paths, мусор (dotfiles, логи, .idea), secrets-скан

   обязательно зелёный (гейт static); make quality-changed; затем make

   core-contracts-spec, compile-fixtures, plan-validate, self-registry-check,
   sbt-compile, scalafmt-check, sbt-test). Любой красный — чини или откатывай
   lane, НИКОГДА не ослабляй пороги/не переименовывай skip в pass.
4. После каждого батча: строка в $NIGHT/registry; после каждой волны — work
   record в docs/work/records/WX-INTEGRATION.md (changed paths, поведение,
   argv/exits, manifests, ограничения). Документационные изменения не
   требуют пересборки бинарника.

ПРОДУКТОВЫЕ ИНВАРИАНТЫ (нарушение = стоп и переделка)
- Product code/tests/HTTP-стенды: только Scala 3 + ZIO. Python — только
  разрешённый glue (scripts/plan, scripts/quality, bootstrap).
- Wire-freeze: schema событий (13 payload-кейсов) и lineage-data.json v1 не
  расширять; изменения — отдельная schema-card + review.
- Оба direct providers first-class; никаких платных вызовов без явного
  режима/бюджета владельца; секреты не логируются и не попадают в argv/
  manifests/evidence.
- Cancel вне model admission; owned children cleanup; maxLLM=1 без deadlock.
- ClassLoader не sandbox; restore не replay мутаций; no exactly-once.
- Protected verifiers, hidden fixtures, gate policy — не менять в карточках
  реализации. Коммиты/push/publish — только владелец.

СЕССИИ И HANDOFF
- Перед компакцией/концом сеанса сохрани в $NIGHT/registry: активные
  assignments, lane-пути/manifests, pids, applied патчи, чеки, вердикты
  ревью, ready queue, следующий шаг. Новый сеанс начинает с §ПЕРВЫЙ ПРОХОД.
- Внешний blocker (баланс/недоступность инструмента) не останавливает
  независимые ready-задачи: закрой что можешь сам, зафиксируй остальное.
- Финальный отчёт: принятые карточки, changed paths, команды/exits/evidence,
  открытые обязательства, риски, следующая ready-карточка. Никаких
  выдуманных часов/коммитов/live-успехов.

Продолжай до исчерпания ready-работы или внешнего blocker'а. Не заканчивай
на спавне: реализуй, интегрируй, проверяй, пиши record — и следующую волну.
